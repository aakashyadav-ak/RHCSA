1. What is a Process?

A program is a file sitting on disk (like /usr/bin/ls). A process is that program running in memory. One program can have many processes: open 3 terminals and you have 3 bash processes.

IDMeaningExample
PIDProcess ID, a unique number1234
PPIDParent PID: the process that started me1000
UIDThe user it runs as. Decides which files it can touch (Chapter 11)john

Three kinds of process

👤 User process
Started by a person: ls, vim, Firefox. Has a terminal.
🛎️ Daemon process
A background service: sshd, httpd, crond. No terminal, so TTY shows ?. Names often end in d.
🧠 Kernel process
Run by the kernel itself. Shown in [square brackets] like [kthreadd]. You cannot and should not kill them.

Parent and child: the family tree

Every process is created by another process, so they form a tree. The root is PID 1 = systemd. (The old init program was discontinued. systemd replaced it, and it starts and manages everything.)

systemd (1)
 ├─ sshd (850)
 │   └─ sshd (3001)
 │       └─ bash (3010)        <- your shell
 │           ├─ sleep (3050)   <- child of bash
 │           └─ ps (3060)
 └─ crond (870)
$ pstree -p | head -5
systemd(1)─┬─sshd(850)───sshd(3001)───sshd(3009)───bash(3010)───pstree(3070)
           ├─crond(870)
$ echo $$ $PPID       # my shell's PID and its parent's PID
3010 3009

Life cycle of a process

fork
parent makes a copy of itself = child
→
exec
child loads a new program (e.g. ls)
→
run
parent waits (sleeps)
→
exit
child ends and frees memory
→
reap
parent collects the result, PID is removed
🧟 Zombie: the child has finished, but the parent has not collected its result yet. It uses no CPU or memory, only a PID slot. You cannot kill a zombie, because it is already dead. Fix it by killing or restarting the parent.
👶 Orphan: the parent died first. systemd adopts the child and cleans it up properly.
Built-in commands like cd and jobs run inside the shell (no new process). External commands like ls and ps become a new child process.

2. Process States

Every process is in one state. See it in the STAT column of ps or the S column of top.

RRunning
on the CPU, or waiting in line to run
SSleeping
waiting for input, timer or event. Most processes are here
DDeep sleep
waiting for disk or network. Cannot be interrupted
TStopped
paused with Ctrl+Z or SIGSTOP
ZZombie
finished, waiting for parent
XDead
fully gone. Never seen in tools

I = idle kernel thread. K = killable deep sleep. A CPU core runs one process at a time, but many can show R because they are queued.

New process
→
R running
⇄
S sleeping
…
T stopped
→
Z zombie
→
X gone

Extra letters after the state in ps

LetterMeaningLetterMeaning
ssession leader (a login shell)<high priority
+in the foregroundNlow priority
lmulti-threadedLpages locked in memory

Ss = sleeping session leader (your shell). R+ = running in foreground (the ps command itself).

3. Listing Processes: ps

ps is a photo (snapshot) of the processes at that moment. top is a live video.

CommandMeaning
psOnly your processes on this terminal
ps auxa = all users, u = user format (CPU, memory), x = also processes without a terminal (daemons)
ps -efAll processes, with PPID (UNIX style)
ps laxLong format with PPID, priority and nice. Faster
ps -ef --forestTree view
ps -u johnOne user's processes
ps aux (no dash) is not the same as ps -aux. Write it without the dash.
$ ps aux
USER   PID %CPU %MEM    VSZ   RSS TTY   STAT START  TIME COMMAND
root     1  0.0  0.1 169836 12456 ?     Ss   10:00  0:02 /usr/lib/systemd/systemd
root     2  0.0  0.0      0     0 ?     S    10:00  0:00 [kthreadd]
john  3010  0.0  0.1 227916  5100 pts/0 Ss   10:05  0:00 -bash
john  3060  0.0  0.0 228364  3800 pts/0 R+   10:09  0:00 ps aux
ColumnMeaning
TTYTerminal. ? = none (daemon or kernel). pts/0 = SSH or terminal window
VSZ / VIRTAll memory the process could use (virtual)
RSS / RESReal RAM it is using now
[name]Brackets mean a kernel process

Find things quickly

ps aux | grep sshd                      # find a process (also shows the grep line)
pgrep -l sshd                           # cleaner: PID and name
ps -eo pid,ppid,stat,%cpu,%mem,cmd --sort=-%cpu | head -5   # top CPU users
ps -eo pid,stat,cmd | awk '$2 ~ /^Z/'   # list zombies
$ pgrep -l sshd
850 sshd
3001 sshd

4. Real-time Monitoring: top

top refreshes every 3 seconds. Press q to quit. Here is how to read it:

top - 10:30:00 up 5 days,  2:30,  2 users,  load average: 0.15, 0.10, 0.05  # 1, 5, 15 min
Tasks: 150 total,   1 running, 149 sleeping,   0 stopped,   0 zombie        # process states
%Cpu(s):  2.0 us,  1.0 sy,  0.0 ni, 96.5 id,  0.5 wa,  0.0 hi,  0.0 si     # CPU use
MiB Mem :   7976.5 total,  2345.6 free,  3456.7 used,  2174.2 buff/cache
MiB Swap:   2048.0 total,  2048.0 free,     0.0 used.  4123.4 avail Mem

  PID USER   PR  NI    VIRT    RES    SHR S  %CPU  %MEM    TIME+ COMMAND
 1234 john   20   0  123456  56789  12345 S   5.0   0.7  1:23.45 firefox
PartMeaning
us / syCPU used by user programs / by the kernel
idIdle. High is good (CPU has free time)
waWaiting for disk or network. High means an I/O problem
stTime stolen by the host in a virtual machine
avail MemThe memory number to watch. The free number is misleading because Linux uses spare RAM as cache
NI / PRNice value / priority (section 5)
SState letter (section 2)
%CPUCan go above 100% on multi-core (400% max on 4 cores)

Keys inside top

KeyWhat it does
1Show each CPU separately (press again to join). Same as the "Ctrl+1" in your notes: just press 1
Shift+P / Shift+MSort by CPU / by memory

top -u john             # only john's processes
top -d 5                # refresh every 5 seconds
top -b -n 1 | head -15  # one snapshot, good for scripts

📍 Where to Add What

You do not edit a file by hand. Press f and Shift+P to set what you want, then press Shift+W. This creates /home/you/.config/procps/toprc, which top reads every time it starts.

Load average: how busy is the server?

Load average is the number of processes that are running (R) or waiting for disk/network (D). It shows three numbers: the average of the last 1, 5 and 15 minutes.

$ uptime
 15:29:03 up 14 min,  2 users,  load average: 2.92, 4.48, 5.20
$ lscpu | grep '^CPU(s)'      # how many logical CPUs?
CPU(s):                          4
$ nproc
4

Load only means something per CPU. Divide each number by the CPU count. Try it:

Load:   CPUs:
Per CPU below 1
Healthy. Little or no waiting.
About 1
CPUs fully used.
Above 1
Overloaded. Processes are queueing and the server slows down.
Trend: 1-min < 5-min < 15-min means the load is falling (recovering). 1-min > 5-min > 15-min means it is rising (getting worse). High load but low CPU use? Look at the disk or network (wa in top, vmstat 1 5).

htop and free

free -h                 # memory in human sizes. Check the "available" column
sudo dnf install epel-release htop   # htop is not in the default RHEL repos; on RHEL enable EPEL first
htop                    # colours, mouse support, F9 to kill, F6 to sort

🏢 Scenario: "the server is slow"

$ uptime
 11:02:10 up 20 days,  load average: 8.10, 6.50, 3.20     # 4 CPUs, load is rising and above 1 per CPU
$ top                          # press Shift+P: sort by CPU
  PID USER   %CPU COMMAND
 7712 app    380.0 java                     # one process is eating 4 cores
$ ps -o pid,ppid,user,etime,cmd -p 7712     # who owns it, how long has it run?
$ kill 7712                                 # polite stop first (see section 7)

5. Priority: nice and renice

When many processes want the CPU, the nice value decides who goes first. Think: a "nice" process lets others go before it.

-20-100 (default)+10+19
highest priority (least nice)lowest priority (very nice)
One correction to your notes: the nice range is -20 to +19, nothing lower. The "-99 to -1" numbers you may see are the PR column in top, used by real-time processes that the kernel controls. You cannot set them with nice. For normal processes, PR = 20 + NI.
WhoWhat they can do
Regular userOnly on their own processes, and only increase the value (0 to +19). Cannot lower it again.
rootAny value from -20 to +19, on any process.
nice -n 10 ./backup.sh        # start with low priority
renice -n 5 -p 4023           # change a running process (by PID)
sudo renice -n -5 -p 4023     # raise priority: root only
$ ps -o pid,ni,cmd -p 4023
  PID  NI CMD
 4023   5 ./backup.sh

📍 Where to Add What

GoalFileLine
Nightly backup at low prioritycrontab -e (opens your cron file)0 2 * * * nice -n 15 tar -czf /backup/data.tar.gz /data
Every process of user student starts with nice 10Create /etc/security/limits.d/90-nice.conf (as root)student - priority 10
The limits line takes effect at the next login of that user.

6. Jobs: Foreground and Background

A job is a command started from your terminal. Every job is a process, but not every process is a job (daemons are not jobs, and fg/bg cannot touch them). Jobs are numbered by the shell (%1), processes by the system (PID).

🖥️ Foreground
sleep 300
Takes over the terminal. You wait. Only one per terminal.
🌙 Background
sleep 200 &
Terminal is free. You can run many.
$ sleep 200 &
[1] 4410                 # job number 1, PID 4410
$ sleep 300
^Z                       # Ctrl+Z pauses it
[2]+  Stopped                 sleep 300
$ jobs
[1]-  Running                 sleep 200 &
[2]+  Stopped                 sleep 300
$ bg %2                  # let job 2 continue in the background
[2]+ sleep 300 &
$ fg %1                  # bring job 1 to the front
sleep 200
^C                       # Ctrl+C ends it
Key / commandEffect
cmd &Start in background
Ctrl+ZPause (SIGTSTP)
Ctrl+CTerminate (SIGINT)
bg %n / fg %nResume in background / bring to front
jobsList jobs. + = default job, - = next default

🏢 Scenario: edit a file, then jump back to the shell

$ vim abc          # Ctrl+Z to pause vim
[1]+  Stopped                 vim abc
$ ls ; cat /etc/hostname      # do other work
$ fg %1            # back to vim exactly where you left it
(vim abc & in the background will be stopped at once, because vim needs the keyboard.)

What happens when the terminal closes?

Normal jobs get a hangup signal and die. To keep a long task alive after logout:

nohup ./long_task.sh &         # output goes to nohup.out
./long_task.sh & disown        # remove from the job list
tmux                           # reconnect to it later (best for long work)

7. Signals: Controlling and Killing Processes

A signal is a message you send to a process. kill -l lists all signals. Use the name instead of the number when you can.

No.NameMeaningCan it be ignored?
1SIGHUPHangup. Daemons also use it as "reload config"Yes
2SIGINTInterrupt, same as Ctrl+CYes
15SIGTERMPolite stop, lets the program clean up. DefaultYes
9SIGKILLForce kill, no clean upNo
19SIGSTOPPauseNo
18SIGCONTContinue a paused processNo
20SIGTSTPCtrl+Z pauseYes
Right order: SIGTERM first, SIGINT next, SIGKILL only as the last choice. SIGKILL gives the program no chance to save data or delete temp files.

kill: by PID or job number

kill 4410                  # SIGTERM (default)
kill -9 4410               # SIGKILL. Note the dash: "kill 9 %1" is wrong
kill -9 %1                 # job number 1
kill -SIGSTOP %2           # pause job 2
kill -SIGCONT %2           # resume job 2
kill -HUP 850              # ask sshd to reload its config

killall vs pkill vs pgrep

CommandPicks processes byExample
killPID or job numberkill 4410
killallExact namekillall sleep
pkillName pattern, user, terminal, parentpkill -u john · pkill -t pts/1 · pkill -P 8391
pgrepSame as pkill but only lists, never killspgrep -l -u john
Habit: run pgrep -l first. If the list looks right, replace it with pkill. Careful: pkill -u yourself kills your own shell and ends your session.
$ pgrep -l -u john
6964 bash
6998 sleep
6999 sleep
$ pstree -p john          # who is the parent?
bash(6964)─┬─sleep(6998)
           └─sleep(6999)
$ pstree -p 6964          # tree of one process id
$ sudo pkill -SIGKILL -u john      # log john out completely
🧟 Zombie?
ps -eo stat,pid,ppid,cmd | awk '$1~/^Z/'
kill 2210     # kill the PARENT (PPID)
🧊 Stuck in D state?
kill -9 will not work until the disk or network I/O finishes. Check the storage or NFS mount instead.

🏢 Scenario: log out a user who is abusing the server

$ w                         # who is logged in, from where
USER  TTY    FROM          LOGIN@  IDLE  WHAT
bob   pts/1  10.0.0.15     12:28   14:42 -bash
$ sudo pkill -t pts/1               # everything on that terminal except his shell
$ sudo pkill -SIGKILL -t pts/1      # including the shell: he is out
$ sudo loginctl terminate-user bob  # modern one-line way
His login shell ignores SIGTERM on purpose, so only SIGKILL removes it.

🏢 Scenario: pause a heavy report, then resume

$ pgrep -l report        # 5120 report.sh
$ kill -SIGSTOP 5120     # state becomes T, CPU is free for the business
$ kill -SIGCONT 5120     # continues from the same spot

📍 Where to Add What

No file is edited for signals. For a daemon like sshd, prefer sudo systemctl reload sshd and systemctl stop over kill, so systemd stays in sync.

8. Extra Things You Must Know

/proc folder
Every process has /proc/PID/ with its status, command and open files. Try cat /proc/$$/status | head.
Limit runaway users
Add john hard nproc 200 to /etc/security/limits.d/90-limits.conf so one user cannot start unlimited processes.
watch
watch -n 2 uptime repeats a command every 2 seconds.
Other tools
vmstat 1 5, iostat, sar, pidstat (package sysstat) show if the problem is CPU, memory or disk.
Common mistakes: using kill -9 first · trying to kill a zombie · pkill name without checking pgrep -l · reading load average without dividing by CPU count · judging the load right after a change (it is a moving average) · closing a terminal that holds important jobs · trusting free instead of avail Mem · killing a daemon with kill instead of systemctl.

Cheat sheet
