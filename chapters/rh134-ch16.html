Installing Red Hat Enterprise Linux

Install RHEL with the Anaconda installer, and automate it for many servers with a Kickstart file. This is mostly theory plus one file to read and validate.

1Installation: the big picture

Why? A company may build 50 servers. Doing every install by hand is slow and each server comes out a little different. The installer can follow a saved answer file, so all servers are identical.

2Installer steps (what you choose)

Why? Know the choices, because in an interview or at work you must explain each one.
  1. Boot from the ISO or USB and choose Install Red Hat Enterprise Linux.
  2. Language and keyboard.
  3. Installation Destination: pick the disk. Choose automatic or custom partitioning (/boot, /, swap, LVM).
  4. Software Selection: for example *Server* or *Minimal Install*.
  5. Network and Host Name: IP (DHCP or static) and the hostname.
  6. Time and Date: time zone, and NTP.
  7. Root password and user: create an admin user with sudo rights, lock root over SSH.
  8. Connect to Red Hat (subscription) if needed. Click Begin Installation, then reboot.
Typical layoutWhy
/boot 1 GiB (xfs)kernel and GRUB files
/boot/efi 600 MiBneeded on UEFI systems
/ (root) on LVMsystem, grows with LVM
swapmemory overflow
/home, /var separate (optional)stop logs or users filling the whole disk
Minimal installFor servers pick Minimal Install. Fewer packages = fewer updates and a smaller attack surface.

3Kickstart file basics

Why? Kickstart answers every installer question in advance. The same file builds the same server again and again, even without anyone sitting at the screen.

After every manual install RHEL saves your choices in /root/anaconda-ks.cfg. Copy it and edit it. That is the easiest way to start.

/root/anaconda-ks.cfg (shortened)
text
lang en_US.UTF-8
keyboard us
timezone Asia/Kolkata --utc
network --bootproto=dhcp --hostname=server1.example.com
rootpw --lock
user --name=student --groups=wheel --plaintext --password=redhat
zerombr
clearpart --all --initlabel
autopart --type=lvm
reboot

%packages
@^minimal-environment
vim-enhanced
%end

Check the syntax before using it

$ sudo dnf install -y pykickstart
$ ksvalidator /root/anaconda-ks.cfg
$ echo $?
0
$ ksvalidator bad.cfg
The following problem occurred on line 7 of the kickstart file:
Unknown command: autopar
  • No output and exit code 0 = the file is valid.
  • ksverdiff compares the syntax of two RHEL versions.

4Use the Kickstart file: inst.ks=

Why? The installer must know where the file is. You tell it with a boot option.
  1. Put the file on a web server, FTP, NFS or USB.
  2. Boot the installer. At the GRUB menu press Tab (BIOS) or e (UEFI).
  3. Add the inst.ks= option at the end of the boot line.
  4. Press Ctrl+X (UEFI) or Enter (BIOS) to start.
OptionWhere the file is
inst.ks=http://server/ks.cfgweb server
inst.ks=ftp://server/ks.cfgFTP
inst.ks=nfs:server:/dir/ks.cfgNFS
inst.ks=hd:sdb1:/ks.cfga local disk or USB
inst.ks=cdrom:/ks.cfgCD or DVD
Boot line (end)
vmlinuz initrd=initrd.img inst.stage2=hd:LABEL=RHEL-10-0-BaseOS-x86_64 quiet inst.ks=http://192.168.1.10/ks.cfg
Serve the file with a quick web servercd /var/www/html && cp ~/ks.cfg . on a server with Apache, or python3 -m http.server 8080 for a test.
