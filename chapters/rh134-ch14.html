Managing Network Security

Control which network traffic may reach your server with firewalld, and which ports a service may use with SELinux. Both must allow, or the connection fails.

1Two gates: firewall and SELinux port label

Why? A new web server on port 8080 can be reached only if two things allow it: the firewall must open the port, and SELinux must allow the service to use that port.
ToolFull formControls
firewalldfirewall daemonwhich incoming traffic is allowed (services, ports, sources)
firewall-cmdfirewall commandthe command that talks to firewalld
semanage portSELinux managewhich ports a service type may bind to
Start the servicesudo systemctl enable --now firewalld. Check: firewall-cmd --state prints running.

2firewalld zones

Why? A zone is a set of rules for a level of trust. Home network = trusted, public Wi-Fi = strict. Each network interface or source IP belongs to one zone.
ZoneDefault behaviour
dropall incoming dropped silently
blockincoming rejected with a message
publicdefault. Only selected services (ssh, cockpit, dhcpv6-client)
internal / home / workmore trusted
trustedeverything allowed
dmzlimited access from outside
$ sudo firewall-cmd --get-default-zone
public
$ sudo firewall-cmd --get-active-zones
public
  interfaces: ens160
$ sudo firewall-cmd --get-zones
block dmz drop external home internal nm-shared public trusted work
$ sudo firewall-cmd --set-default-zone=internal
$ sudo firewall-cmd --permanent --zone=internal --add-source=192.168.1.0/24
Which zone wins?1) a rule matching the source IP 2) the zone of the interface 3) the default zone.

4Open a service or port: --permanent and --reload

Why? Two kinds of rules: runtime (active now, lost at reboot) and permanent (saved, active after reload). Forgetting this is the number one firewall mistake.
WayCommandResult
Runtime onlyfirewall-cmd --add-service=httpworks now, gone after reboot or reload
Permanent onlyfirewall-cmd --permanent --add-service=httpsaved, not active until --reload
Both (best)add with --permanent, then --reloadsaved and active

Standard way: 3 commands

$ sudo firewall-cmd --permanent --add-service=http
success
$ sudo firewall-cmd --permanent --add-port=8080/tcp
success
$ sudo firewall-cmd --reload
success
$ sudo firewall-cmd --list-all | grep -E "services|ports"
  services: cockpit dhcpv6-client http ssh
  ports: 8080/tcp
  • --add-service=NAME opens the ports of a known service (http = 80). Names are in /usr/lib/firewalld/services/.
  • --add-port=8080/tcp opens a port number and protocol (tcp or udp). A range: 5000-5100/tcp.
  • --remove-service and --remove-port close them.
  • --zone=ZONE chooses a zone. No option = default zone.

Other way: test first, then save

$ sudo firewall-cmd --add-service=https
success
# test it works, then save the running rules to permanent:
$ sudo firewall-cmd --runtime-to-permanent
success
Where are permanent rules stored?In /etc/firewalld/zones/public.xml. You can read it but do not edit by hand. Use the command.
Do not close SSH by mistakeOn a remote server never remove ssh. You will lock yourself out. Use a safety at job (chapter 3) when testing risky changes.

5Rich rules

Why? When normal rules are not enough, for example "allow SSH only from one IP", you write a rich rule.
$ sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.1.50" service name="ssh" accept'
success
$ sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="10.0.0.0/8" port port="8080" protocol="tcp" reject'
success
$ sudo firewall-cmd --reload
$ sudo firewall-cmd --list-rich-rules
rule family="ipv4" source address="192.168.1.50" service name="ssh" accept
$ sudo firewall-cmd --permanent --remove-rich-rule='rule family="ipv4" source address="192.168.1.50" service name="ssh" accept'
PartMeaning
rule family="ipv4"IPv4 (or ipv6)
source address="IP"who the rule is for
service name or port port=.. protocol=..what traffic
accept / reject / dropaction. reject sends a reply, drop is silent
log prefix="SSH "optional: write matches to the log
Remove: use the exact same textTo remove a rich rule, copy the whole line used to add it and use --remove-rich-rule.

6SELinux ports: semanage port -a

Why? SELinux allows httpd only on ports labelled http_port_t (80, 443, 8008, 8009, 8443, 9000...). If you move Apache to port 82, SELinux blocks it, even if the firewall is open.
$ sudo semanage port -l | grep http_port_t
http_port_t                    tcp      80, 81, 443, 488, 8008, 8009, 8443, 9000
$ sudo sed -i 's/^Listen 80/Listen 82/' /etc/httpd/conf/httpd.conf
$ sudo systemctl restart httpd
Job for httpd.service failed because the control process exited with error code.
$ sudo journalctl -u httpd | tail -2
(13)Permission denied: AH00072: make_sock: could not bind to address [::]:82
  1. Add the port label: semanage port -a -t http_port_t -p tcp 82
  2. Check: semanage port -l | grep http_port_t
  3. Restart the service: systemctl restart httpd
  4. Open the firewall: firewall-cmd --permanent --add-port=82/tcp then --reload
$ sudo semanage port -a -t http_port_t -p tcp 82
$ sudo semanage port -l | grep http_port_t
http_port_t                    tcp      82, 80, 81, 443, 488, 8008, 8009, 8443, 9000
$ sudo systemctl restart httpd
$ sudo firewall-cmd --permanent --add-port=82/tcp && sudo firewall-cmd --reload
$ ss -tulpn | grep :82
tcp   LISTEN 0   511   *:82   *:*   users:(("httpd",pid=3720,fd=4))
OptionMeaning
-aadd
-t TYPEport type, e.g. http_port_t, ssh_port_t
-p tcpprotocol
-mmodify an existing port
-ddelete
ss -tulpnss = socket statistics. Options: tcp, udp, listening, process, numeric. It proves that the service listens on the port.
Find the type namesudo semanage port -l | grep -i ssh shows the type for a service. If a port is already assigned to another type use -m instead of -a.
