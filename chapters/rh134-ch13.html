Recovering Superuser Access

Forgot the root password? You can reset it from the GRUB menu using rd.break. This chapter shows the exact keys, commands and the SELinux relabel step that people forget.

1When and why this works

Why? If you have console access to the machine, you can stop the boot early (before the real system is ready) and become root without a password. That is why servers need physical and console security.
Full formsrd.break = ramdisk break (stop in the initial RAM disk). /sysroot = where the real root file system is mounted during early boot. chroot = change root (make /sysroot look like /).
Only with console accessThis does not work over SSH. You need the VM console or the physical screen.

2Reset the root password: step by step

Why? Each command has a reason. If you skip one, the new password does not work or you cannot log in at all.
  1. Reboot the machine. At the GRUB menu press any key, highlight the first kernel and press e.
  2. Find the line that starts with linux. Press End and add rd.break at the end of that line.
  3. Press Ctrl+X to boot.
  4. Wait for the prompt switch_root:/#.
  5. Remount the real root as writable: mount -o remount,rw /sysroot
  6. Enter it: chroot /sysroot
  7. Set the password: passwd root
  8. Ask SELinux to fix labels at next boot: touch /.autorelabel
  9. Leave: type exit, then exit again. The system continues to boot (relabel can take a while).

CommandWhy it is needed
mount -o remount,rw /sysrootthe real root is mounted read-only at this point, so you cannot write the new password
chroot /sysrootmakes the real system your /, so passwd edits the real /etc/shadow
passwd rootsets the new root password
touch /.autorelabelthis shell has no SELinux labels, so the edited /etc/shadow gets a wrong label. This file tells the system to relabel everything at boot
Do not skip /.autorelabelWithout it, SELinux blocks the login with the new password (it looks like "Login incorrect"). With it, the next boot relabels all files and may take several minutes.
Check after logingetenforce should say Enforcing and ls /.autorelabel should be gone, because it is deleted after the relabel.

4Other cases and good practice

If the file system is damaged

Use rescue.target or emergency.target (chapter 12). They ask for the root password, so they do not help when it is forgotten. For a forgotten password use rd.break.

Alternative: init=/bin/bash

Some admins add init=/bin/bash instead of rd.break. It starts a bash shell as root with / read-only. You must then mount -o remount,rw /, run passwd root, touch /.autorelabel, and reboot with exec /usr/lib/systemd/systemd. rd.break is the standard method for the exam.

Protect the server

  • Set a GRUB password so nobody can edit boot options.
  • Lock the BIOS/UEFI, physical room, and the VM console.
  • Use encrypted disks (LUKS), because root access in this way cannot read encrypted data without the key.
  • Prefer sudo and SSH keys for admins, with a locked-down root login.
