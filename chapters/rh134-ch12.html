Controlling and Troubleshooting the Boot Process

What happens from power button to login prompt, how to change the target (text or graphical), and how to use rescue mode, edit GRUB and fix a broken fstab.

1Boot process in 6 steps

Why? If a server does not start, you must know which step failed. Each step has its own fix.
StepFull formWhat happens
UEFI / BIOSUnified Extensible Firmware Interface / Basic Input Output Systemhardware test (POST), finds the boot disk
GRUB2GRand Unified Bootloader 2shows the menu, loads kernel and initramfs
Kernelstarts, mounts a temporary root from the initramfs
initramfsinitial RAM file systemsmall image with drivers needed to find the real root disk
systemdfirst process (PID 1), starts services
Targeta group of services = the final state (login prompt or desktop)
Where are the files?/boot/vmlinuz-* kernel, /boot/initramfs-*.img, /boot/grub2/grub.cfg menu (do not edit by hand), /etc/default/grub settings you edit.

2Targets: get-default, set-default, isolate

Why? A target is a goal state. Servers usually boot to text mode (no desktop) to save resources. You choose which one.
TargetMeaning
graphical.targetmulti-user + desktop (GUI)
multi-user.targetfull text mode, network, all services
rescue.targetsingle-user, basic system, root password, file systems mounted
emergency.targetsmallest shell, root file system read-only only
reboot.target / poweroff.targetrestart / shut down
$ systemctl get-default
graphical.target
$ sudo systemctl set-default multi-user.target
Removed '/etc/systemd/system/default.target'.
Created symlink '/etc/systemd/system/default.target' -> '/usr/lib/systemd/system/multi-user.target'.
$ sudo systemctl isolate rescue.target
$ systemctl list-units --type=target
  • get-default shows the target used at next boot.
  • set-default changes the next boot (permanent). Nothing changes now.
  • isolate switches right now, stopping what that target does not need. Your SSH session may drop!
Careful with isolate on a remote serversystemctl isolate emergency.target kills the network and your SSH login. Use it on a console only.

3Rescue and emergency mode at boot

Why? When the system fails to boot, rescue or emergency mode gives you a root shell so you can repair it.
rescue.targetemergency.target
Root file systemmounted read-writemounted read-only
Other file systems (fstab)mountednot mounted
Servicesfew basic onesnone
Use whenforgotten fstab problem, service breaks bootfstab is broken or rescue also fails

Enter rescue mode from the GRUB menu

  1. Reboot. At the GRUB menu press any key to stop the timer.
  2. Highlight the kernel line and press e (edit).
  3. Go to the line that starts with linux and press End.
  4. Add a space and systemd.unit=rescue.target (or systemd.unit=emergency.target).
  5. Press Ctrl+X to boot with this change (only once, not saved).
  6. Enter the root password when asked.
GRUB edit screen (the linux line)
linux ($root)/vmlinuz-6.12.0-55.el10.x86_64 root=/dev/mapper/rhel-root ro crashkernel=auto rd.lvm.lv=rhel/root rd.lvm.lv=rhel/swap rhgb quiet systemd.unit=rescue.target
Give root password for maintenance
(or press Control-D to continue):
[root@server ~]# systemctl default      # leave rescue mode, boot normally
[root@server ~]# mount -o remount,rw /  # in emergency mode only
TemporaryChanges made with e in GRUB are used for this boot only.

4GRUB settings: grubby and /etc/default/grub

Why? To add a kernel option permanently, for example to print boot messages, you must change the saved settings, not only the one-time edit.

grubby: easy way, changes every kernel entry

$ sudo grubby --default-kernel
/boot/vmlinuz-6.12.0-55.el10.x86_64
$ sudo grubby --info=ALL | grep args
args="ro crashkernel=auto rd.lvm.lv=rhel/root rhgb quiet"
$ sudo grubby --update-kernel=ALL --remove-args="rhgb quiet"
$ sudo grubby --update-kernel=ALL --args="console=ttyS0"
  • --update-kernel=ALL = every installed kernel.
  • --args="..." adds, --remove-args="..." removes.
  • Removing rhgb quiet shows boot messages instead of the graphic splash.

/etc/default/grub: classic way

/etc/default/grub
GRUB_TIMEOUT=5
GRUB_DEFAULT=saved
GRUB_CMDLINE_LINUX="crashkernel=auto rd.lvm.lv=rhel/root rd.lvm.lv=rhel/swap"

Change a value (for example GRUB_TIMEOUT=10 for a longer menu time) and then rebuild the menu file:

$ sudo grub2-mkconfig -o /boot/grub2/grub.cfg
Generating grub configuration file ...
Adding boot menu entry for UEFI Firmware Settings ...
done
Never edit /boot/grub2/grub.cfg directlyIt is generated. Your hand edits are lost at the next kernel update.

5Fix a bad fstab at boot

Why? A wrong line in /etc/fstab (wrong UUID, wrong disk) makes systemd wait 90 seconds and then drop to emergency mode. This is a very common interview scenario.
[  OK  ] Reached target Local File Systems (Pre).
[DEPEND] Dependency failed for /data.
[DEPEND] Dependency failed for Local File Systems.
You are in emergency mode. After logging in, type "journalctl -xb" to view
system logs, "systemctl reboot" to reboot, "systemctl default" or "exit"
to boot into default mode.
Give root password for maintenance
(or press Control-D to continue):
  1. Enter the root password.
  2. Make the root file system writable: mount -o remount,rw /
  3. Open the file: vim /etc/fstab
  4. Comment the bad line with # (or fix the UUID, check with blkid).
  5. Test: mount -a (no message = OK).
  6. systemctl daemon-reload then systemctl reboot.
/etc/fstab (before and after)
UUID=aaaa-1111  /data  xfs  defaults  0 0
#UUID=aaaa-1111  /data  xfs  defaults  0 0
Prevent boot hangs for optional disksAdd nofail in the options: UUID=... /data xfs defaults,nofail 0 0. The system boots even if this disk is missing.

6Boot messages: dmesg and journalctl -b

Why? After the system is up, read what happened during boot to find errors.
$ sudo dmesg | head -3
[    0.000000] Linux version 6.12.0-55.el10.x86_64 ...
$ sudo dmesg --level=err,warn
$ journalctl -b -p err
Nov 20 08:01:10 server systemd[1]: Failed to mount /data.
$ journalctl --list-boots
-1 8a1b... Thu 2026-11-19 09:02:11 IST—Thu 2026-11-19 23:50:01 IST
 0 c7d2... Fri 2026-11-20 08:01:05 IST—Fri 2026-11-20 11:20:44 IST
$ journalctl -b -1 -p err      # previous boot
CommandMeaning
dmesgkernel ring buffer (hardware and driver messages)
journalctl -ball messages of this boot
journalctl -b -1previous boot (needs a persistent journal)
journalctl -b -p erronly errors of this boot
systemd-analyze blamewhich service took longest to start
