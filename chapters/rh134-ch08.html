Transferring Files

Copy files between two Linux servers with scp, sftp and rsync (all over SSH), and download from the web with wget and curl.

Why and which toolscpsftprsyncwget and curlSSH keysCommands listQuiz

1Why transfer tools? Which one to use

Why? Servers are remote. You must move backups, configs and logs between machines safely. All three main tools use SSH, so the data is encrypted on the way.
ToolFull formBest for
scpSecure CP (copy)quick copy of a file or folder
sftpSSH File Transfer Protocolbrowse remote files, many small tasks
rsyncRemote SYNChronizationbackup, mirror, resume, only send changes
wgetWeb GETdownload a file from a URL
curlClient URLtest URLs and APIs, also download
Before you startYou need SSH access to the other server (port 22) and a user name. Key-based login (ssh-keygen, ssh-copy-id) saves typing the password every time.

2scp: secure copy

Why? scp works like cp, but one side can be a remote server. Pattern: scp SOURCE DESTINATION, where the remote side is written user@host:path.
$ scp /home/student/report.txt student@192.168.1.20:/tmp/
student@192.168.1.20's password:
report.txt                         100%   12KB   4.1MB/s   00:00
$ scp student@192.168.1.20:/etc/hostname /tmp/hostname-server2
$ scp -r /home/student/project student@192.168.1.20:/home/student/
$ scp -P 2222 file.txt student@server2:/tmp/
OptionMeaning
-rrecursive, needed for folders
-P PORTcapital P = SSH port (small -p keeps timestamps)
-ppreserve times and modes
-i keyuse a specific private key
-Ccompress while sending
Colon is the secretserver2:/tmp/ = remote path. Without the colon, scp file server2 just makes a LOCAL copy named server2. A very common mistake.
scp overwrites without askingIf the destination file exists, scp replaces it silently. For safe repeated copies use rsync.

3sftp: interactive transfer

Why? When you do not remember the exact file name, sftp lets you look around on the remote server, then download or upload.
$ sftp student@192.168.1.20
student@192.168.1.20's password:
Connected to 192.168.1.20.
sftp> pwd
Remote working directory: /home/student
sftp> ls
Documents  report.txt
sftp> get report.txt
Fetching /home/student/report.txt to report.txt
sftp> lpwd
Local working directory: /home/student
sftp> put backup.tar.gz /tmp
Uploading backup.tar.gz to /tmp/backup.tar.gz
sftp> bye
CommandMeaning
ls, cd, pwdwork on the remote side
lls, lcd, lpwdlocal side (letter l in front)
get FILEdownload
put FILEupload
get -r DIR, put -r DIRfolder
mkdir, rmremote folder / delete
bye or exitquit

4rsync: -avz and --delete

Why? rsync compares both sides and sends only what changed. A 10 GB backup that changed 50 MB sends 50 MB. It can also resume a broken copy.
$ rsync -avz /home/student/project/ student@192.168.1.20:/backup/project/
sending incremental file list
./
notes.txt
src/main.py

sent 4,215 bytes  received 62 bytes  8,554.00 bytes/sec
total size is 11,901  speedup is 2.78
OptionMeaning
-aarchive: recursive + keeps permissions, owner, times, links
-vverbose
-zcompress during transfer
-nno action: dry run (test first!)
-Pprogress + keep partial file (resume)
--deletedelete files on the destination that no longer exist in the source
-e "ssh -p 2222"set the SSH command or port
--exclude=PATTERNskip files
Trailing slash matters!rsync -a /src/ /dest/ copies the content of src into dest. rsync -a /src /dest/ creates /dest/src/. Always check with -n first.

Safe mirror: dry run, then real run

$ rsync -avzn --delete /data/ student@server2:/backup/data/
deleting old-report.txt
./
new-file.txt
$ rsync -avz --delete /data/ student@server2:/backup/data/

rsync over ssh with a different port

$ rsync -avz -e "ssh -p 2222" /data/ student@server2:/backup/data/
Local to local also worksrsync -av /etc/ /backup/etc/ is a good local backup too. SSH is only used when a host: is present.

Real scenario: nightly backup with cron

crontab -e
30 1 * * * rsync -az /var/www/ student@backup01:/backup/www/ >> /var/log/rsync-www.log 2>&1

5Downloads: wget and curl

Why? Sometimes you need a file from a web or FTP URL: an ISO, a script, a repo file. wget and curl do it from the terminal.
$ wget https://example.com/files/app.tar.gz
--2026-11-20 10:40:11--  https://example.com/files/app.tar.gz
Saving to: 'app.tar.gz'
app.tar.gz          100%[=====================>]   2.1M  3.0MB/s    in 0.7s
$ wget -O /tmp/new.tar.gz https://example.com/files/app.tar.gz
$ wget -c https://example.com/big.iso      # -c continue a broken download
$ curl -O https://example.com/files/app.tar.gz
$ curl -o /tmp/new.tar.gz https://example.com/files/app.tar.gz
$ curl -I https://example.com               # only the headers
wgetcurl
Save with remote namedefault-O (capital)
Save with own name-O name-o name
Resume-c-C -
Show headers only--spider-I
Best atplain downloadstesting URLs, APIs, headers
curl prints to the screen by defaultcurl URL shows the page on screen. Use -O or -o to save it.

6Make transfers easier: SSH keys

Why? Typing the password for every scp is slow and cannot be used in cron. A key pair fixes both.
$ ssh-keygen -t ed25519
Generating public/private ed25519 key pair.
Enter file in which to save the key (/home/student/.ssh/id_ed25519):
$ ssh-copy-id student@192.168.1.20
Number of key(s) added: 1
$ scp report.txt student@192.168.1.20:/tmp/
report.txt                         100%   12KB   4.1MB/s   00:00
