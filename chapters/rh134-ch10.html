Managing Basic Storage

Add a disk, cut it into partitions, put a file system on it, mount it forever, and create swap space. Every step comes in the exact order you type it.

1Why storage steps? The 4 steps

Why? A new disk is empty and Linux cannot use it. These 4 steps make it ready to store files.
  • Partition: one disk is split into parts, so data stays separate (backup, logs, swap).
  • File system: a raw partition is just empty space. The file system adds files and folders on it.
  • Mount: Linux has no drive letters like C:. A file system is reached only through a folder.
  • /etc/fstab: a normal mount is forgotten after reboot. fstab makes it permanent.
RememberA partition with no file system cannot store files. A file system that is not mounted cannot be reached. Skip one step and it fails.

4MBR vs GPT

Why? A disk needs a label (a partition map) before you can make partitions. MBR and GPT are the two kinds of label.

Question: max size of one partition in GPT?A GPT partition can be as large as the disk itself, so the limit is the GPT disk limit of about 8 ZiB. In MBR one partition cannot go above 2 TB.
ExamIn the exam you will mostly use GPT. In fdisk, press g first.

5fdisk: create a partition

Why fdisk? fdisk (fixed disk) is the standard tool to make the label and the partitions. It is the main tool we use. Changes are saved only when you press w, so it is safe to practice: q quits without saving.

What each question means

Using MBR instead

On a blank disk fdisk already starts with MBR, so skip g (or press o for a fresh MBR label). The n command then asks one extra question:

Select (default p): p
Partition number (1-4, default 1): 1

p = primary, e = extended.

CarefulThe command is fdisk /dev/sdb (the whole disk), not fdisk /dev/sdb1 (a partition).

Next: run udevadm settle (section 6), then format and mount (section 7).

6udevadm settle: what and why

Why? After you press w in fdisk, Linux needs a moment to create the device file /dev/sdb1. udevadm settle makes you wait until that work is finished.
  • udev is the part of Linux that creates and removes device files in /dev (like /dev/sdb1) when hardware or partitions change.
  • It works in the background, so it can be a little late.
  • udevadm settle waits until udev has finished all its pending work, then returns. It prints nothing when it is done.

When to use

Right after you save a partition change (w in fdisk), before mkfs.xfs or mkswap.

[root@server ~]# udevadm settle
[root@server ~]# mkfs.xfs /dev/sdb1
What if you skip it?Most of the time nothing goes wrong. But sometimes the next command is too fast and fails like this. Run udevadm settle and try again: 
[root@server ~]# mkfs.xfs /dev/sdb1
mkfs.xfs: cannot open /dev/sdb1: No such file or directory

7File system and temporary mount

Why? The partition is only empty space. mkfs.xfs (make file system) writes the XFS structure on it so files and folders can be stored. mount then attaches it to a folder so you can reach it.
  1. udevadm settle
    Wait until /dev/sdb1 exists.
  2. mkfs.xfs /dev/sdb1
    Format the partition with XFS.
  3. mkdir /disksdb1
    Make the mount point, an empty folder.
  4. mount /dev/sdb1 /disksdb1
    Attach the partition to that folder.
  5. df -hT
    Check size, type and mount point.
[root@server ~]# mkfs.xfs /dev/sdb1
meta-data=/dev/sdb1         isize=512    agcount=4, agsize=65536 blks
         =                  sectsz=512   attr=2, projid32bit=1
data     =                  bsize=4096   blocks=262144, imaxpct=25
naming   =version 2         bsize=4096   ascii-ci=0, ftype=1
log      =internal log      bsize=4096   blocks=16384, version=2
realtime =none              extsz=4096   blocks=0, rtextents=0
Discarding blocks...Done.

[root@server ~]# mkdir /disksdb1
[root@server ~]# mount /dev/sdb1 /disksdb1
[root@server ~]# df -hT /disksdb1
Filesystem     Type  Size  Used Avail Use% Mounted on
/dev/sdb1      xfs   960M   39M  922M   5% /disksdb1
[root@server ~]# mount | grep /disksdb1
/dev/sdb1 on /disksdb1 type xfs (rw,relatime,seclabel,attr2,inode64,logbufs=8,logbsize=32k,noquota)
Not permanent!A mount done with the mount command is lost after reboot. For a permanent mount, add the partition to /etc/fstab (next section).

8Permanent mount with /etc/fstab

Why? /etc/fstab (file systems table) is the list Linux reads at boot to know what to mount. Without a line here, your mount disappears after reboot.

Step 1: get the UUID

Use blkid (or lsblk --fs) and copy the UUID.

[root@server ~]# blkid /dev/sdb1
/dev/sdb1: UUID="d85f5387-9791-400a-9a74-f637e7ee68aa" TYPE="xfs" PARTUUID="7c1e0f1b-..."

[root@server ~]# lsblk --fs /dev/sdb1
NAME FSTYPE FSVER LABEL UUID
sdb1 xfs                d85f5387-9791-400a-9a74-f637e7ee68aa

Step 2: edit the file

[root@server ~]# vim /etc/fstab

Go to the last line and add one new line:

/etc/fstab
...output omitted...
UUID=d85f5387-9791-400a-9a74-f637e7ee68aa   /disksdb1   xfs   defaults   0 0

You can also write /dev/sdb1 in place of the UUID, but UUID is better. Disk names like sdb can change if disks are added or removed. The UUID never changes.

The 6 fields of a fstab line

defaults is the default option set. It means: rw (read and write), suid, dev, exec, auto (mount at boot), nouser (only root can mount), async. The last two fields are normally 0 0.

Step 3: make it live and test

[root@server ~]# systemctl daemon-reload      # systemd reads the new fstab
[root@server ~]# mount -a                      # mount everything in fstab. No message = good
[root@server ~]# mount | grep /disksdb1
/dev/sdb1 on /disksdb1 type xfs (rw,relatime,seclabel,attr2,inode64,logbufs=8,logbsize=32k,noquota)
[root@server ~]# df -hT
Always run mount -a before rebootIf the fstab line has a mistake, the server can fail to boot and go to emergency mode. mount -a shows the error now, while you can still fix it.
Best testUnmount first with umount /disksdb1, then run mount -a. If /disksdb1 comes back, your fstab line works. A final reboot and mount | grep /disksdb1 proves it.

9Removing a partition

Why this order? If you delete the partition but leave its fstab line, the next boot tries to mount something that no longer exists.
  1. Unmount it
    umount /disksdb1
  2. Remove its line from /etc/fstab
    Open vim /etc/fstab and delete the line that has the UUID. Then run systemctl daemon-reload.
  3. Delete the partition
    fdisk /dev/sdb, press d, then w.
  4. Reboot if the old partition still shows in lsblk

10Swap space

Why swap? When RAM is full, Linux moves old, unused data to the disk. This keeps the system running instead of crashing.
  • Swap is slower than RAM. It is a safety net, not a replacement.
  • Low RAM and no swap: the system becomes unstable, and programs (such as a normal user login) can fail to start.
  • Swap can be a partition (this chapter). The partition type must be Linux swap.

The 5 swap steps

  1. Create a partition with fdisk and set its type to Linux swap
  2. udevadm settle
  3. mkswap formats it as swap (instead of mkfs.xfs)
  4. swapon turns it on now
  5. /etc/fstab line for permanent use, then reboot to check
fdisk labelType code for Linux swap
MBR (dos)82
GPT19 (or the alias swap)

The Swap line in free -h now shows 2.0Gi. Before swapon it showed 0B.

Make it permanent

Open vim /etc/fstab and add one line at the end:

/etc/fstab
...output omitted...
UUID=54a08491-2722-4145-911c-317c6919e53d   swap   swap   defaults   0 0

(/dev/sdc1 swap swap defaults 0 0 also works, but UUID is safer.)

[root@server ~]# systemctl daemon-reload
[root@server ~]# swapon -a                     # turn on everything marked swap in fstab
[root@server ~]# reboot                        # or: init 6
[root@server ~]# free -h                       # Swap line must still show 2.0Gi

11Two swaps and priority

Why priority? With more than one swap, you decide which one Linux fills first. Example: put the faster disk first.

The swap with the higher pri number is used first. If you set nothing, the first swap gets -2, the next one -3, and so on.

Step 1: create the second swap (512 MB) in fdisk

[root@server ~]# fdisk /dev/sdc
Command (m for help): n
Partition number (2-128, default 2): 2
First sector (4196352-10485726, default 4196352): [Enter]
Last sector, +/-sectors or +/-size{K,M,G,T,P}: +512M
Created a new partition 2 of type 'Linux filesystem' and of size 512 MiB.

Command (m for help): t
Partition number (1,2, default 2): 2
Partition type or alias (type L to list all): 19
Changed type of partition 'Linux filesystem' to 'Linux swap'.

Command (m for help): w
[root@server ~]# udevadm settle
[root@server ~]# mkswap /dev/sdc2
Setting up swapspace version 1, size = 512 MiB (536866816 bytes)
no label, UUID=353fe8ca-1276-4443-935e-e1ae87039aef
[root@server ~]# blkid /dev/sdc1 /dev/sdc2        # copy both UUIDs

Step 2: edit fstab and add pri

Change the old sdc1 line (add ,pri=20) and add one new line for sdc2:

/etc/fstab
...output omitted...
UUID=54a08491-2722-4145-911c-317c6919e53d   swap   swap   defaults,pri=20   0 0
UUID=353fe8ca-1276-4443-935e-e1ae87039aef   swap   swap   defaults,pri=30   0 0

Use your own UUIDs from blkid. The first line must belong to /dev/sdc1, the second to /dev/sdc2.

Step 3: apply and check

[root@server ~]# systemctl daemon-reload
[root@server ~]# swapoff -a          # sdc1 is already on with the old priority, so switch all off first
[root@server ~]# swapon -a
[root@server ~]# swapon --show
NAME      TYPE      SIZE USED PRIO
/dev/sdc1 partition   2G   0B   20
/dev/sdc2 partition 512M   0B   30

[root@server ~]# init 6
# after reboot
[root@server ~]# swapon -s
[root@server ~]# lsblk

If both swaps and their PRIO values are the same after the reboot, the permanent setup is correct.

Turn a swap offswapoff /dev/sdc1 turns it off now. Also delete its line from /etc/fstab so it does not come back at boot.

12Extra: partedextra, fdisk is enough

Why parted? parted (partition editor) does the same job as fdisk. You can do all the work with fdisk, so read this only if you want one more tool. The big difference: parted saves every change immediately, there is no w key and no undo.

Partition with one-line commands (on /dev/sdd)

[root@server ~]# parted /dev/sdd print
Error: /dev/sdd: unrecognised disk label
Partition Table: unknown

[root@server ~]# parted /dev/sdd mklabel gpt          # or: mklabel msdos for MBR
[root@server ~]# parted /dev/sdd mkpart backup xfs 2048s 2GB
Information: You may need to update /etc/fstab.

[root@server ~]# parted /dev/sdd print
Model: QEMU QEMU HARDDISK (scsi)
Disk /dev/sdd: 5369MB
Partition Table: gpt

Number  Start   End     Size    File system  Name    Flags
 1      1049kB  2000MB  1999MB               backup
Part of the commandMeaning
mklabel gptsets the label (like g in fdisk). On a disk with data it wipes the old table.
backupname of the partition (GPT). On MBR this place takes primary or extended
xfsfile-system type label only. It does not format the partition
2048sstart at sector 2048 (s = sectors)
2GBend position (not the size)

Menu mode

[root@server ~]# parted /dev/sdd
(parted) mklabel gpt
(parted) mkpart
Partition name?  []? backup
File system type?  [ext2]? xfs
Start? 2048s
End? 2GB
(parted) print
(parted) quit

Type ? or help inside parted for help. help mkpart shows help for one command.

Swap with parted

Write linux-swap in mkpart. The second swap starts where the first one ended.

[root@server ~]# parted /dev/sdd
(parted) mkpart swap1 linux-swap 2001MB 3001MB
(parted) mkpart swap2 linux-swap 3001MB 3257MB
(parted) print
(parted) quit
[root@server ~]# udevadm settle
[root@server ~]# mkswap /dev/sdd2
[root@server ~]# mkswap /dev/sdd3

After that the steps are the same as before: swapon, blkid, the two /etc/fstab lines with pri=, systemctl daemon-reload, swapon -a, swapon --show.
