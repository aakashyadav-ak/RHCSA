CHAPTER 10

🔐 Controlling Access to Files

Many people share one Linux server. Permissions decide who may read, change or run each file and folder. Without them, any user could delete the system files or read your passwords.

Five kinds of permission in this chapter
1. General
chmod on one file
2. Recursive
chmod -R on a folder tree
3. Default
umask for new files
4. Special
SUID, SGID, sticky
5. ACL
per-user extra rules

1. The 10 Characters of ls -l

Run ls -l. Every line starts with 10 characters. They are the whole permission story of that file.

Full line: -rw-r-----. 1 john developers 1024 Jan 15 myfile.txt

Character 1: file type

-dlbcps
Normal fileDirectory (folder)Link (shortcut)Block device (disk, /dev/sda)Character device (keyboard, terminal)PipeSocket

Characters 2 to 10: three groups of three

👤 Owner (u)
One user, usually who created the file.
👥 Group (g)
All members of the file's group (like the "developers" team).
🌍 Others (o)
Everyone else: normal users who are neither the owner nor in the group. root is not limited by these rules.
Linux stops at the first match:
Are you the owner?
Use owner bits
→
No. In the group?
Use group bits
→
No.
Use others bits
An owner with --- is blocked, even if the group has rwx.

The dot . and the plus + after the permissions

SymbolMeaning
.The file has an SELinux security label. Normal on RHEL. Show it with ls -Z.
+The file has an ACL. That plus sign is the "logo" of an ACL. See section 7.

Now look at the line from your notes:

drwx------. 15 ak ak 4096 Oct 26 15:28 .

d = directory, rwx------ = only owner ak has access, . after the permissions = SELinux label, 15 = links, ak ak = owner and group, 4096 = size. The last . is the name: it means "this current folder" (shown with ls -la). .. is the parent folder.

2. Read, Write, Execute

On a FILEOn a DIRECTORY
r readOpen and see the content (cat)See the names inside (ls)
w writeEdit the contentCreate, delete and rename files inside (needs x too)
x executeRun it as a program or scriptEnter it with cd and reach files inside

Why a file opens with r but a folder does not

📄 A file is a book. If you may read it, you open it and read it. Done.
🚪 A directory is a room with a notice board outside.
r = you may read the notice board (list of names).
x = you hold the key to open the door and go in.
With r only, you see the names but cannot enter.
Directory modeWhat you can do
r-xList and enter. A normal read-only folder.
r--See names only. cd fails.
--xCannot list, but can enter if you know the exact name.
rwxFull control.
rw-Useless: without x you cannot reach anything.
"Everyone can enter /, but only permitted users can change it": the root directory / is rwxr-xr-x. Others have r-x (enter and list) but no w, so only root can create or delete there. To open /a/b/file you need x on /, a and b (check with namei -l /a/b/file).
Deleting a file is decided by the folder's w, not the file's own permission.

🧪 Try it: lock a folder

# as root
mkdir /test ; echo hello > /test/text.txt
chmod o-r /test/text.txt ; ls -l /test/text.txt
-rw-r-----. 1 root root 6 Oct 31 10:00 /test/text.txt   # others lost read
chmod o-x /test/
su - student
cd /test/
-bash: cd: /test/: Permission denied                     # no x on the folder

📍 Where to Add What

No file is edited here. Permissions are stored on the file itself.

3. Changing Permissions: chmod

chmod (change mode) changes permissions of a file or folder. Two styles:

Style 1: Symbolic (letters)

Who
u owner · g group · o others · a all three
Operator
+ add · - remove · = set exactly (wipes the old ones)
chmod u+x script.sh          # owner may run it
chmod o-r /test/text.txt     # others lose read
chmod g=rw file.txt          # group becomes exactly rw-
chmod a+r file.txt           # everybody can read
chmod u=rwx,g=rx,o= file.txt # set all three at once

Style 2: Numeric (numbers)

4read
2write
1execute
rwx4+2+1 = 7
rw-4+2 = 6
r-x4+1 = 5
r--4
---0

640 means 6 = owner (rw-), 4 = group (r--), 0 = others (---). Practise here:

 

type a number

NumberSymbolTypical use
600rw-------Private file, SSH key
644rw-r--r--Normal file
640rw-r-----Group reads, others nothing
700rwx------Private folder
755rwxr-xr-xPrograms, public folders
770rwxrwx---Team folder
777rwxrwxrwx⚠️ Everyone can do everything. Avoid.

Recursive: the folder and everything inside

mkdir -p /test/dir1               # -p creates parent folders too
touch /test/dir1/file.txt
chgrp -R developers /test/        # -R = recursive (note: chgrp, not chrgp)
ls -lR /test/
/test/:
drwxr-xr-x. 2 root developers 22 Oct 31 10:10 dir1
/test/dir1:
-rw-r--r--. 1 root developers 0 Oct 31 10:10 file.txt
chmod -R g+rwX /test/             # capital X: x only on folders, not on normal files

🏢 Scenario: developers cannot upload to the website

$ ls -ld /var/www/html/uploads
drwxr-xr-x. 2 root root 4096 Oct 31 10:00 /var/www/html/uploads
$ sudo chown :developers /var/www/html/uploads
$ sudo chmod 775 /var/www/html/uploads
drwxrwxr-x. 2 root developers 4096 Oct 31 10:05 /var/www/html/uploads

📍 Where to Add What

No file is edited. Type the command in the terminal (use sudo for files you do not own).

4. Changing Owner and Group

CommandChanges
chown amit fileOwner only
chown :devteam fileGroup only
chown amit:devteam fileOwner and group
chgrp devteam fileGroup only
chown -R amit:devteam /dataWhole folder tree
Only root can change an owner. A normal owner may change the group, but only to a group they belong to. Use a colon user:group, not a dot.
$ ls -l report.txt
-rw-r--r--. 1 amit amit 0 Oct 31 10:00 report.txt
$ sudo chown ravi:devteam report.txt
-rw-r--r--. 1 ravi devteam 0 Oct 31 10:01 report.txt

📍 Where to Add What

No file is edited. Users and groups live in /etc/passwd and /etc/group. Use useradd, groupadd and usermod -aG instead of editing them by hand.

5. Default Permissions: umask

When you create a file or folder, Linux starts from a maximum and umask takes some permissions away. Check it with umask. The usual answer is 0022.

New file: max 666
Files never get x automatically. A new file can never run by accident (safety). That is why 666 and not 777.
New folder: max 777
A folder needs x so people can enter it.

How to subtract (digit by digit)

umask 022:   file 666-022 = 644 (rw-r--r--)    folder 777-022 = 755 (rwxr-xr-x)
Rule: subtract each digit and never go below 0. Question: umask is 027, what does a new file get?
OwnerGroupOthers
umask 027027
File: start 6666−0 = 66−2 = 46−7 → 0
File resultrw-r-----
Folder: start 7777−0 = 77−2 = 57−7 = 0
Folder resultrwxr-x---

Answer: file = 640, folder = 750. Visual for the group digit (mask 2 removes write):

rw- start 6 (rw-)−w mask 2r-- = 4 (r--)
$ umask 027 ; touch report.txt ; mkdir reports ; ls -ld report.txt reports
-rw-r-----. 1 ak ak 0 Oct 31 10:00 report.txt
drwxr-x---. 2 ak ak 6 Oct 31 10:00 reports
Strictly, umask switches bits off. With a file and umask 033, the answer is 644 (not 633), because files never had x. Simple subtraction is fine for 022, 002, 027, 077.
Try: umask → file , folder

Making umask permanent

umask 077 typed in a terminal lasts only for that terminal. Put it in a startup file:

📍 Where to Add What

WhoFileLine to add (at the very bottom)
Only you~/.bash_profile (or ~/.bashrc)umask 027
All users (global, in /etc)Create /etc/profile.d/local-umask.sh as rootumask 027
$ echo "umask 027" >> ~/.bash_profile    # >> appends. A single > erases the file!
$ tail -n 1 ~/.bash_profile
umask 027
$ exit        # log in again
$ umask
0027

🏢 Scenario: audit says "other users can read finance reports"

New files are 644, so others can read them. Set umask 027 in /etc/profile.d/local-umask.sh. New files become 640. Old files do not change, so also run chmod -R o-rwx /data/finance.

6. Special Permissions (the 4th permission)

NameSetNumOn a fileOn a folder
SUIDu+s4Runs as the ownerNo effect
SGIDg+s2Runs as the groupNew files get the folder's group
Stickyo+t1No effectOnly the owner can delete their files
SpecialSeen inWith xWithout xExample
SUIDownersS-rwsr-xr-x
SGIDgroupsSdrwxrwsr-x
StickyotherstTdrwxrwxrwt

Capital S or T = special bit is set but x is missing, so it does nothing. Usually a mistake.

🔑 SUID: passwd
-rwsr-xr-x root
You run it, but it runs as root so it can write the password file. You get only that one task, not root power.
📁 SGID: team folder
Every new file gets the folder's group, so the team can all edit it.
📌 Sticky: /tmp
drwxrwxrwt
Anyone can create files, but only the owner can delete their own.
chmod u+s /usr/sbin/fdisk   # practice only. Undo it: chmod u-s /usr/sbin/fdisk
chmod g+s /srv/project      # or numeric: chmod 2770 /srv/project
chmod o+t /srv/public       # or numeric: chmod 1777 /srv/public
chmod 4755 file             # 4 = SUID, 2 = SGID, 1 = sticky, as the first digit
$ ls -l /usr/sbin/fdisk
-rwsr-xr-x. 1 root root 123456 Oct 31 10:00 /usr/sbin/fdisk
SUID on programs like fdisk lets any user run them as root. That is a big security hole. Find all SUID files with find / -xdev -perm -4000 -type f. SUID on scripts is ignored.

🏢 Scenario: three developers share /srv/project

$ sudo groupadd devteam ; sudo usermod -aG devteam amit   # repeat for ravi, sita
$ sudo mkdir /srv/project ; sudo chown :devteam /srv/project
$ sudo chmod 2770 /srv/project
drwxrws---. 2 root devteam 6 Oct 31 10:00 /srv/project
$ touch /srv/project/plan.txt                              # as amit
-rw-rw-r--. 1 amit devteam 0 Oct 31 10:02 plan.txt
The group is devteam, not "amit". SGID only affects new files; fix old ones with chgrp -R devteam /srv/project.

📍 Where to Add What

No file is edited. Use chmod in the terminal. Group membership is saved in /etc/group by usermod -aG. The user must log out and in again.

7. ACL – Access Control List

Normal permissions give only one owner, one group and others. An ACL gives different permissions to different users on the same file. If a file has an ACL, ls -l shows a +.

📄 File
owner root, group root
+
ACL list
student rw-
user1 ---
grp rw-
=
Shows + in ls -l
CommandUse
getfaclShow ACL of a file or folder
setfacl -m u:name:permModify: give a user permissions
setfacl -m g:name:permGive a group permissions
setfacl -m d:u:name:perm dirDefault ACL: new files inside copy it
setfacl -x g:grp fileRemove one entry
setfacl -b fileRemove all ACL entries
$ mkdir /all-in-one ; vim /all-in-one/information
$ ls -l /all-in-one/information
-rw-r--r--. 1 root root 12 Oct 31 10:00 /all-in-one/information
$ getfacl /all-in-one/information
# file: all-in-one/information     # file name
# owner: root                      # owner
# group: root                      # group
user::rw-                          # owner permission
group::r--                         # group permission
other::r--                         # others permission

$ setfacl -m u:student:rw /all-in-one/information
$ setfacl -m u:user1:--- /all-in-one/information
$ setfacl -m g:grp:rw /all-in-one/information
$ ls -ld /all-in-one/information
-rw-rw-r--+ 1 root root 12 Oct 31 10:00 /all-in-one/information   # + appeared
$ getfacl /all-in-one/information
user::rw-
user:student:rw-       # named user student
user:user1:---         # user1 blocked
group::r--
group:grp:rw-          # named group grp
mask::rw-              # upper limit for all named entries
other::r--
$ setfacl -x g:grp /all-in-one/information     # remove grp entry
$ setfacl -b /all-in-one/information           # remove everything, + disappears

Default ACL on a folder

$ mkdir /kk
$ setfacl -m d:u:student:rw /kk/     # d: = default for future files
$ touch /kk/hh
$ getfacl /kk/hh
user:student:rw-                     # inherited automatically
$ setfacl -m o::--- /kk              # o:: means others, no name needed. Others get ---

🏢 Scenario: auditor needs read-only access

/data/reports is 770 root:finance. Auditor meena must only read. Adding her to finance would give write access, so use an ACL:
$ sudo setfacl -R -m u:meena:rX /data/reports
$ sudo setfacl -d -m u:meena:rX /data/reports

📍 Where to Add What

No file is edited. ACLs are stored in the file system (XFS supports them). Run setfacl in the terminal.

8. Extra Things You Must Know

root ignores permissions
root can read or change anything, except when SELinux or chattr +i stops it.
Group changes need a new login
After usermod -aG devteam amit, amit must log out and in, or run newgrp devteam.
Moving vs copying
A copy becomes a new file owned by you, using your umask. A move keeps owner and permissions.
Immutable file
chattr +i file stops even root from changing or deleting it. Check with lsattr, remove with chattr -i.
SELinux
Permissions can be fine and access still denied. See ls -Z. Never fix this with 777.
Create with a mode
mkdir -m 750 /data/team
find /home -perm -o+w -type f          # files others can write: a security risk
find / -nouser -o -nogroup 2>/dev/null # files with a deleted owner
stat -c '%a %U:%G %n' report.txt       # prints: 640 amit:devteam report.txt
namei -l /srv/project/plan.txt         # shows permissions of every folder in the path
Common mistakes: chmod -R 777 to "fix" things · folder with r but no x · expecting SGID to change old files · umask typed in terminal but not saved · testing group access without logging in again · using > instead of >> on startup files.

Cheat sheet (f = a file name, d = a directory name)
