1. TCP/IP Model and OSI Model

These are maps that show how data travels. OSI has 7 layers (theory). TCP/IP has 4 layers (real world, used by RHEL).

4. Application — SSH, HTTPS, DNS, SMTP
3. Transport — TCP, UDP + ports
2. Internet — IP address, routers, ICMP (ping)
1. Link — Ethernet, Wi-Fi, MAC address
OSI 7, 6, 5 — Application, Presentation, Session
OSI 4 — Transport
OSI 3 — Network
OSI 2, 1 — Data Link, Physical
WordSimple meaning
TCPReliable. Checks that data arrived. Used by SSH, web, email
UDPFast, no checking. Used by DNS, video, syslog
PortA door number on a server. SSH = 22, HTTP = 80, HTTPS = 443, DNS = 53
SocketIP address + port, like 192.168.1.100:22
MAC addressHardware ID of a network card, like 52:54:00:00:fa:0a. Works only on the local network

2. Network Interface Names

Old Linux used eth0, eth1. The order could change after a reboot. New RHEL gives fixed names based on the hardware.

enEthernet (cable)
wlWLAN (Wi-Fi)
wwWWAN (mobile data)
NameHow to read it

ens160en + PCI slot 160 (common in VMware)
enp0s3en + PCI bus p0 + slot s3 (common in VirtualBox)

On your VMware VM the name is likely ens160. In the book labs it is eth0 or enX. Always check your own name with ip link and use it in commands.

4. IPv6 (Short Version)


IPv6 has 128 bits, written in hex with colons: 2001:db8:0:10::1. RHEL runs IPv4 and IPv6 together (dual-stack).


✂️ How to shorten
Full: 2001:0db8:0000:0010:0000:0000:0000:0001
1. Drop leading zeros: 2001:db8:0:10:0:0:0:1
2. Replace one run of zeros with :: → 2001:db8:0:10::1
:: only ONCE per address


📋 Special addresses
::1 loopback (like 127.0.0.1)
fe80::/10 link-local (every interface has one)
2000::/3 global (Internet)
fd00::/8 private (unique local)
ff02::1 all nodes on the link


  • Standard subnet is /64: 64 bits network + 64 bits interface ID.
  • IPv6 has no broadcast. It uses multicast.
  • With a port, use brackets: [2001:db8::1]:80.
  • Link-local ping needs the interface: ping -6 fe80::1%ens160. Without %ens160 you get Invalid argument.

5.2 Routing table


$ ip route
default via 192.168.1.1 dev ens160 proto static metric 100
192.168.1.0/24 dev ens160 proto kernel scope link src 192.168.1.100 metric 100
$ ip -6 route                  # IPv6 table
$ ip route get 8.8.8.8         # which way will this destination go?


default via 192.168.1.1 = the gateway. Everything not on your own network goes there. No default line = no Internet.

Correction to your notes: nmap -p- IP scans a host from outside (all 65535 ports). It is not the normal way to see your own open ports. Use ss -tulpn on the server. Use nmap only when you have permission to scan, and install it first (dnf install nmap).



6. NetworkManager and nmcli


NetworkManager is the service that manages the network on RHEL. You control it with:


⌨️ nmcli
Command line. Best for scripts and exams.
🖥️ nmtui
Menu screen in the terminal. Easy for beginners. Can set IP, activate connection and hostname.
📝 Edit file
Edit .nmconnection by hand, then reload.


Two words you must know


Device
The network card
ens160
⇄
Connection
A saved set of settings (profile)
System ens160


A device can have many saved connections, but only one is active at a time. The connection name is often different from the device name.


6.1 View information


$ nmcli device status
DEVICE  TYPE      STATE      CONNECTION
ens160  ethernet  connected  ens160
lo      loopback  unmanaged  --
$ nmcli connection show               # all saved connections
$ nmcli connection show --active      # only active ones
$ nmcli connection show "ens160"      # all settings (quote names with spaces)
$ nmcli device show ens160            # live info: IP, gateway, DNS


In nmcli con show NAME: lowercase keys (ipv4.method) are the saved settings you can change. UPPERCASE keys (IP4.ADDRESS) are the live values right now. You can shorten words: nmcli con mod, nmcli dev stat.


6.2 Add a new connection


# DHCP (automatic)
$ sudo nmcli connection add con-name testing type ethernet ifname ens160
# Static IP
$ sudo nmcli connection add con-name static-ens160 type ethernet ifname ens160 \
    ipv4.method manual ipv4.addresses 192.168.1.100/24 \
    ipv4.gateway 192.168.1.1 ipv4.dns 8.8.8.8
$ sudo nmcli connection up static-ens160      # turn it on


PartMeaning
con-nameName of the profile (you choose)
type ethernetKind of connection
ifnameThe device it belongs to
ipv4.method manualUse the static values (not DHCP)


Backslash rule: in the multi-line command, \ must be the very last character on the line. A space after it breaks the command. In your pasted notes some lines have spaces after \. Remove them.


6.3 Change an existing connection (DHCP to static)


$ nmcli con show                                       # find the exact name, e.g. "System eth0"
$ sudo nmcli con mod "System eth0" ipv4.method manual \
    ipv4.addresses 192.168.1.100/24 ipv4.gateway 192.168.1.1
$ sudo nmcli con mod "System eth0" ipv4.dns "8.8.8.8"        # replaces the DNS list
$ sudo nmcli con mod "System eth0" +ipv4.dns 1.1.1.1         # + adds one more
$ sudo nmcli con mod "System eth0" -ipv4.dns 1.1.1.1         # - removes one
$ sudo nmcli con mod "System eth0" +ipv4.addresses 10.0.1.1/24   # second IP
$ sudo nmcli con up "System eth0"                      # REQUIRED to apply


Important: nmcli con mod saves to the file at once, but the running network does not change until you run nmcli con up NAME. Always set ipv4.method manual when going static. If you forget, it may hang or still take a DHCP address.


6.4 Manage connections


CommandUse

Over SSH use sudo for changes. You can lose your own connection if you set a wrong IP on the interface you are logged in through. In a VM, keep the console open.

7. Edit the Connection File by Hand


📍 Where are the files?
Folder: /etc/NetworkManager/system-connections/ (note the s: system-connections, not system-connection). One file per connection: NAME.nmconnection.
$ sudo ls /etc/NetworkManager/system-connections/
ens160.nmconnection  static-ens160.nmconnection


📍 What to edit: add a second IP address
Open the file: sudo vim "/etc/NetworkManager/system-connections/static-ens160.nmconnection". In the [ipv4] section, add the address2 line under address1:
[connection]
id=static-ens160
type=ethernet
autoconnect=true
interface-name=ens160

[ipv4]
method=manual
address1=192.168.1.100/24,192.168.1.1        # IP/prefix,gateway
address2=10.0.1.1/24                           # <-- NEW LINE
dns=8.8.8.8;                                 # lists end with ;

[ipv6]
method=auto
Then run:
$ sudo chown root:root /etc/NetworkManager/system-connections/static-ens160.nmconnection
$ sudo chmod 600 /etc/NetworkManager/system-connections/static-ens160.nmconnection
$ sudo nmcli con reload
$ sudo nmcli con up static-ens160
$ ip -br addr show ens160
ens160  UP  192.168.1.100/24 10.0.1.1/24 fe80::.../64


Permission rule: NetworkManager ignores a key file that is not owned by root or can be read by others. Always chown root:root and chmod 600.


nmcli settingFile line

ipv4.addresses IP/24address1=IP/24,GATEWAY


ipv4.dns 8.8.8.8dns=8.8.8.8;

Old ifcfg-* files in /etc/sysconfig/network-scripts/ are legacy. They still work on RHEL 9 but are removed in RHEL 10. Use only .nmconnection files.



8. Hostname and Name Resolution


8.1 Hostname


The hostname is the name of the server. Use a full name (FQDN) like server1.lab.example.com.


$ hostname                                    # show current name
$ sudo hostnamectl set-hostname server1.lab.example.com    # PERMANENT
$ hostnamectl
 Static hostname: server1.lab.example.com
Operating System: Red Hat Enterprise Linux 10
$ cat /etc/hostname
server1.lab.example.com
$ sudo hostname testname                      # TEMPORARY, lost after reboot


TypeMeaning
StaticSaved in /etc/hostname. Survives reboot
TransientGiven by DHCP or kernel while running

8.2 How a name becomes an IP


You type
ping web1
→
1. /etc/hosts
local list
→
2. DNS server
from /etc/resolv.conf
→
IP found
192.168.1.10


The order comes from /etc/nsswitch.conf: hosts: files dns (files first, then DNS).


📍 /etc/hosts: local names (no DNS needed)
Edit as root: sudo vim /etc/hosts. Add a new line at the bottom. Format: IP  full-name  nickname
127.0.0.1   localhost localhost.localdomain
::1         localhost localhost.localdomain
192.168.1.10   web1.lab.example.com   web1      # <-- NEW LINE
Or add a line fast (use >>, one > would erase the file!):
$ echo "192.168.1.10 web1.lab.example.com web1" | sudo tee -a /etc/hosts
$ getent hosts web1
192.168.1.10    web1.lab.example.com web1


📍 /etc/resolv.conf: which DNS server to ask
$ cat /etc/resolv.conf
# Generated by NetworkManager
search lab.example.com
nameserver 192.168.1.1
nameserver 8.8.8.8
Correction: the line is nameserver 8.8.8.8 (a space, not =). Up to 3 nameservers; they are tried in order. search adds a domain to short names (ssh web1 tries web1.lab.example.com).
Do not edit this file by hand. NetworkManager overwrites it. Set DNS in the connection:
$ sudo nmcli con mod "System eth0" ipv4.dns "192.168.1.1 8.8.8.8"
$ sudo nmcli con mod "System eth0" ipv4.dns-search lab.example.com
$ sudo nmcli con up "System eth0"
$ cat /etc/resolv.conf

Real-World Scenarios


🏢 "I can ping 8.8.8.8 but google.com fails"
Meaning: network and routing are fine. DNS is broken.
$ cat /etc/resolv.conf                                  # is there a nameserver line?
$ nmcli -f ipv4.dns con show "System eth0"              # is DNS set in the connection?
$ dig @8.8.8.8 google.com                               # does another DNS answer?
$ sudo nmcli con mod "System eth0" ipv4.dns 8.8.8.8 && sudo nmcli con up "System eth0"


🏢 "Users cannot reach the web app on port 8080"
$ ss -tulpn | grep 8080
tcp LISTEN 0 128 127.0.0.1:8080 ...   # only on localhost! Must listen on 0.0.0.0
$ sudo firewall-cmd --list-all         # is port 8080/tcp allowed? (next chapters)
Not listening = start the service. Listening on 127.0.0.1 only = change the app config. Listening but still blocked = check the firewall and SELinux.


🏢 "Server has no IP after reboot"
$ nmcli device status          # STATE disconnected?
$ nmcli con show               # is there a profile for the device?
$ nmcli con show "NAME" | grep autoconnect    # autoconnect: yes ?
$ sudo nmcli con mod "NAME" connection.autoconnect yes
$ sudo nmcli con up "NAME"

Common Mistakes


Forgetting ipv4.method manual · changing settings but not running nmcli con up · using the device name where the connection name is needed · missing quotes around names with spaces · space after \ · wrong chmod (must be 600) on the key file · editing /etc/resolv.conf by hand · using > instead of >> on /etc/hosts · testing /etc/hosts with dig or host · expecting hostname NAME to survive a reboot · saying a /24 has 256 usable hosts (it is 254) · using :: twice in IPv6 · pinging link-local IPv6 without %interface · typos: system-connection, namserver, nmcli con dwon.
