CHAPTER 14

📜 Analyzing and Storing Logs

A log is the diary of a server. It records who logged in, what started or stopped, and every error. When something breaks, the log tells you what, when and why. Reading logs is the number one skill of a support or monitoring engineer.

1. How Logging Works

RHEL has two logging systems working together.

📝 rsyslog
The traditional one. Writes plain text files in /var/log. Read with less, tail, grep. Survives reboot.
📦 systemd-journald
The modern one. Stores logs in a binary journal with extra details. Read with journalctl. By default it is lost at reboot.
Kernel, boot, services, apps
→
systemd-journald
collects everything
(journal in RAM)
→
rsyslog
sorts by facility + priority
→
Text files in /var/log
or sent to another server
"Are all logs stored in text files?" No. rsyslog logs are text. The journal is binary, so cat shows garbage. Use journalctl. Some apps (Apache) write their own files in /var/log/httpd/.
WhereWhat is insideLasts after reboot?
/var/log/messagesGeneral system messages (not login, mail or cron)Yes
/var/log/secureLogin and security: ssh, sudo, su, failed passwordsYes
/var/log/cronScheduled job runsYes
/var/log/maillogMail serverYes
/var/log/boot.logMessages shown while bootingYes
/var/log/audit/audit.logAudit and SELinux denialsYes
/var/log/dnf.logPackage installsYes
/run/log/journal/Journal in RAM (temporary)No
/var/log/journal/Journal on disk (permanent), only if enabledYes

🏢 "Where do I look?"

Someone cannot log in → /var/log/secure. A service crashed → journalctl -u name. Cron job did not run → /var/log/cron. Problem before the last reboot → journalctl -b -1. Server clock looks wrong → timedatectl.
$ systemctl status rsyslog | grep Active
     Active: active (running) since Sun 2026-11-01 09:10:11 IST; 2h ago
$ ls /var/log | head
audit  boot.log  cron  dnf.log  messages  secure  maillog

2. Syslog Files and rsyslog

Reading one log line

Nov  1 11:12:48 server1 sshd[1433]: Failed password for student from 192.168.1.50 port 59344 ssh2
└─ time ─────┘ └host──┘ └program[PID]┘ └──────────────── message ─────────────────────────┘

Oldest line is at the top, newest at the bottom. The time is the server's local time, so a wrong clock means confusing logs (section 6).

Facility and priority: two labels on every message

Facility = who sent it (kern, mail, auth, authpriv, cron, daemon, user, local0 to local7). Priority = how serious:

0 emerg
1 alert
2 crit
3 err
4 warning
5 notice
6 info
7 debug

◀ most serious   ·   least serious ▶   (memory trick: Every Admin Can Eventually Write Nice Instructions Daily)

*.info means info AND everything more serious (notice, warning, err, crit, alert, emerg). A lower number is more serious.

rsyslog rules

Config file: /etc/rsyslog.conf. Your own rules go in /etc/rsyslog.d/*.conf. A rule has two parts:

facility.priority       destination
authpriv.*              /var/log/secure          # all auth messages go to secure
*.info;mail.none;authpriv.none;cron.none   /var/log/messages   # everything info+, EXCEPT mail, auth, cron
mail.*                  -/var/log/maillog        # the dash = faster buffered writes
*.emerg                 :omusrmsg:*              # emergencies shown on every logged-in terminal
local7.*                /var/log/boot.log
SymbolMeaning
*Any facility or any priority
;Separates several selectors
noneExclude that facility
,List facilities: uucp,news.crit

🎮 Try it: where does my message go?

Facility Priority

📍 Where to Add What: your own rule

Create the file /etc/rsyslog.d/custom.conf (as root) with this line: 
local5.*     /var/log/myapp.log
$ sudo systemctl restart rsyslog               # REQUIRED to load new rules
$ sudo rsyslogd -N1                            # optional: checks the config for typos
$ logger -p local5.info "myapp started"        # send a test message
$ tail -1 /var/log/myapp.log
Nov  1 11:20:05 server1 student[3320]: myapp started
An app writes to local0 to local7 when it has no official facility. Pick one and give it its own file like this.

Test and watch logs

$ logger "hello world"                         # default: user.notice, lands in /var/log/messages
$ sudo tail -1 /var/log/messages
Nov  1 11:22:01 server1 student[3401]: hello world
$ logger -p authpriv.notice "hey guys"         # auth message
$ sudo tail -1 /var/log/secure
Nov  1 11:22:30 server1 student[3410]: hey guys
$ sudo tail -f /var/log/secure                 # live view. Ctrl+C to stop. Try a login in another terminal
$ sudo grep -c "Failed password" /var/log/secure   # how many failed logins?
$ sudo less /var/log/messages                  # G = end, /text = search, q = quit

Log rotation: logs cannot grow forever

logrotate runs daily. It renames the old log (messages-20261101), creates a new empty one, and deletes the oldest after about 4 weeks (default weekly + rotate 4).

$ ls /var/log/messages*
/var/log/messages  /var/log/messages-20261025  /var/log/messages-20261018
$ cat /etc/logrotate.conf | grep -E 'weekly|rotate|create|compress'
$ sudo logrotate -d /etc/logrotate.conf        # -d = dry run, changes nothing

📍 Where to Add What: rotate your own log

Create /etc/logrotate.d/myapp:
/var/log/myapp.log {
    weekly
    rotate 4
    compress
    missingok
}

3. Central Log Server (send logs to another machine)

With many servers, you collect all logs on one machine. The standard rsyslog port is 514. @@ = TCP (reliable), @ = UDP (faster, can lose messages).

Client 1
*.* @@192.168.2.200:514
→
Log server 192.168.2.200
listens on TCP 514
←
Client 2
*.* @@192.168.2.200:514
Your notes mention port 515. Use the same port number on both sides. The standard is 514. If you pick another, you must open it in the firewall and allow it in SELinux.

📍 Step 1: On the LOG SERVER (192.168.2.200)

Edit /etc/rsyslog.conf. Find these two lines, and remove the # in front: 
module(load="imtcp")
input(type="imtcp" port="514")
$ sudo firewall-cmd --permanent --add-port=514/tcp ; sudo firewall-cmd --reload
$ sudo systemctl restart rsyslog
$ sudo ss -tlnp | grep 514
LISTEN 0 25 0.0.0.0:514 0.0.0.0:* users:(("rsyslogd",pid=912,fd=7))   # it is listening

📍 Step 2: On each CLIENT

Create /etc/rsyslog.d/remote.conf with one line: 
*.*   @@192.168.2.200:514
$ sudo systemctl restart rsyslog
$ logger "hello central server"

📍 Step 3: Check on the SERVER

$ sudo grep "hello central" /var/log/messages
Nov  1 11:30:14 client1 student[2211]: hello central server        # host name shows the client

4. The Journal: journalctl

The journal is binary, indexed and rich in details. Root sees everything. A normal user sees only some entries (add them to the systemd-journal group or use sudo). The skill is limiting the output. Colours: red = error or worse, bold = notice/warning.

CommandShows
journalctlEverything, oldest first (q quits)
journalctl -n 10Last 10 entries
journalctl -fFollow live (like tail -f)
journalctl -rNewest first
journalctl -p errPriority err and worse (also warning, crit or numbers 0 to 7)
journalctl -u sshd.serviceOne service
journalctl -kKernel messages only
journalctl --since "-1 hour"Last hour
journalctl -bThis boot only
journalctl -o verbose -n 1All fields of an entry
$ sudo journalctl -u sshd.service -n 3
Nov 01 09:10:11 server1 sshd[850]: Server listening on 0.0.0.0 port 22.
Nov 01 10:58:02 server1 sshd[1796]: Accepted publickey for student from 192.168.1.20 port 43876 ssh2
Nov 01 10:58:02 server1 sshd[1796]: pam_unix(sshd:session): session opened for user student(uid=1000)
$ sudo journalctl -p warning -n 2 --no-pager
$ sudo journalctl -u sshd -p err --since today     # options combine

Filter by time

$ sudo journalctl --since today
$ sudo journalctl --since yesterday --until today
$ sudo journalctl --since "2026-11-01 09:00:00" --until "2026-11-01 10:00:00"   # quotes needed (there is a space)
$ sudo journalctl --since 9:00:00                  # today at 9:00
$ sudo journalctl --since "-10min"                 # last 10 minutes
Times use the server's time zone. A server in UTC and you in India (UTC+5:30): adjust, or show UTC with --utc.

Filter by field

$ sudo journalctl -o verbose -n 1                  # find field names
    PRIORITY=6
    _UID=0
    _PID=1
    _COMM=systemd
    _SYSTEMD_UNIT=init.scope
    MESSAGE=Removed slice User Slice of UID 1000.
$ sudo journalctl _PID=1                           # everything systemd itself logged
$ sudo journalctl _UID=81                          # entries from user ID 81 (dbus)
$ sudo journalctl _SYSTEMD_UNIT=sshd.service _PID=1796    # different fields = AND
FieldMeaning
_PIDProcess ID
_UIDUser ID that ran the process
_COMMCommand name
_EXEPath of the program
_SYSTEMD_UNITService (unit) that started it

🏢 Scenario: users say "SSH was failing at 10 AM"

$ sudo journalctl -u sshd --since "10:00" --until "10:30" -p warning
$ sudo grep "Failed password" /var/log/secure | tail -3
Nov  1 10:12:03 server1 sshd[2210]: Failed password for invalid user admin from 203.0.113.9 port 51022 ssh2
A stranger is guessing the username "admin". Next step: block that IP and harden SSH (Chapter 19).

5. Keep the Journal After Reboot

By default the journal lives in RAM (/run/log/journal) and disappears at reboot, so you cannot read why the server crashed. Fix it by making it persistent (/var/log/journal).

Storage=Meaning
persistentAlways on disk. Creates /var/log/journal if missing
volatileRAM only. Lost at reboot
auto (default)On disk only if /var/log/journal already exists
noneStore nothing

📍 Method A: edit the config file

Edit /etc/systemd/journald.conf (as root). Find #Storage=auto, remove the # and change it: 
[Journal]
Storage=persistent
$ sudo systemctl restart systemd-journald
$ ls /var/log/journal
4ec03abd2f7b40118b1b357f479b3112                 # folder named with the machine ID
$ ls /var/log/journal/4ec03abd2f7b40118b1b357f479b3112
system.journal  user-1000.journal

📍 Method B (your notes): keep auto and create the folder

With Storage=auto, just creating the folder is enough: 
$ sudo mkdir /var/log/journal
$ sudo chgrp systemd-journal /var/log/journal
$ sudo chmod 2755 /var/log/journal           # 2 = setgid: new files get the systemd-journal group
$ sudo systemctl restart systemd-journald    # NOT rsyslog. No reboot or daemon-reload needed
$ ls /var/log/journal
Correct file name: /etc/systemd/journald.conf (not /usr/lib/...).

Read older boots

$ journalctl --list-boots
-2 27de... Fri 2026-10-30 09:02:11 IST—Fri 2026-10-30 21:44:52 IST
-1 e754... Sat 2026-10-31 09:15:08 IST—Sat 2026-10-31 22:10:03 IST
 0 ee2c... Sun 2026-11-01 09:10:01 IST—Sun 2026-11-01 11:40:20 IST      # current boot
$ sudo journalctl -b -1 -p err        # errors from the PREVIOUS boot: great after a crash
Negative numbers count back from now (-1 = previous boot). Positive numbers count from the oldest boot.
$ journalctl --disk-usage
Archived and active journals take up 112.0M in the file system.
$ sudo journalctl --vacuum-size=500M      # shrink to 500 MB
$ sudo journalctl --vacuum-time=2weeks    # delete older than 2 weeks

6. Accurate Time: NTP and chrony

Why: log lines carry a time. If servers have different times, you cannot match events. Certificates, Kerberos and cron also break when the clock is wrong.

🌐 NTP
Network Time Protocol. A way for a computer to ask another computer for the exact time.
🖥️ NTP server
A machine that gives out accurate time. Examples: pool.ntp.org on the Internet, or 192.168.1.200 inside your company.
⏱️ chronyd
The RHEL service that talks to NTP servers and keeps your clock correct. Client tool: chronyc.

Stratum: how close to the real clock

Stratum 0
atomic or GPS clock
→
Stratum 1
server attached to it
→
Stratum 2
syncs from stratum 1
→
Stratum 3 …
your server

Lower stratum = closer to the real clock = better.

timedatectl: view and change

$ timedatectl
               Local time: Sun 2026-11-01 11:45:05 IST
           Universal time: Sun 2026-11-01 06:15:05 UTC
                 RTC time: Sun 2026-11-01 06:15:05
                Time zone: Asia/Kolkata (IST, +0530)
System clock synchronized: yes          # synced with NTP
              NTP service: active       # chronyd is on
          RTC in local TZ: no           # hardware clock kept in UTC (correct for Linux)
$ timedatectl list-timezones | grep -i kolkata
Asia/Kolkata
$ sudo timedatectl set-timezone America/New_York       # format: Continent/City
$ tzselect                                            # interactive helper. It only PRINTS a name, it changes nothing

Set the time by hand (3 steps)

$ sudo timedatectl set-ntp false          # 1. switch off automatic sync, otherwise you get an error
$ sudo timedatectl set-time "2026-11-01 12:00:00"   # 2. set it (time only also works: 12:00:00)
$ sudo timedatectl set-ntp true           # 3. switch auto sync back on
On a real server do not set time by hand. Fix the NTP source instead. Wrong clocks break logs, certificates and cron.

📍 Where to Add What: use your own NTP server

Edit /etc/chrony.conf (as root). Comment out the default pool line and add yours: 
#pool 2.rhel.pool.ntp.org iburst
server 192.168.1.200 iburst
$ sudo systemctl restart chronyd
$ chronyc sources -v
MS Name/IP address         Stratum Poll Reach LastRx Last sample
===============================================================================
^* 192.168.1.200                3    6   377    14   +2957ns[+2244ns] +/- 25ms
$ chronyc tracking | head -3
Reference ID    : C0A801C8 (192.168.1.200)
Stratum         : 4

poolA name that resolves to many servers

Common Mistakes

Forgetting to restart rsyslog after a rule change · editing a commented line and not removing the # · restarting rsyslog when you meant systemd-journald · reading old logs from a volatile journal after a reboot · no quotes around --since "2026-11-01 09:00" · different ports on client and server · comparing logs from servers with unsynced clocks · thinking tzselect sets the zone · setting time by hand while NTP is on · using cat on a .journal file · typos like /var/log/message, persistant, timedate.
tail -f /var/log/secure | logger -p local5.info "x" | journalctl -u NAME -p err --since today | journalctl -b -1
sudo timedatectl set-timezone Asia/Kolkata | chronyc sources -v | sudo systemctl restart rsyslog
