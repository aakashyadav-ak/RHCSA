Working with Image-based Red Hat Enterprise Linux

In image mode, the whole operating system is built like a container image with a Containerfile and updated with bootc. This is new in RHEL 10, so this chapter is concepts and a few commands.

Package vs image modeContainerfileDisk imagesbootcCommands listQuiz

1Package mode vs image mode

Why? Normal RHEL (package mode) is changed server by server with dnf. After years every server is a little different. In image mode the OS is one image. You rebuild the image and every server gets exactly the same system.
Package mode (classic)Image mode
Update withdnf updatebootc upgrade (new image)
Change the OS byinstalling packages on each serverediting the Containerfile and rebuilding
/usrwritableread-only
Rollbackdifficultbootc rollback, one command
Servers stay identicalno, they driftyes
Full formsbootc = bootable container. A bootc image is a container image that also holds a kernel, so it can start a real machine. OCI = Open Container Initiative (the image standard).

2Build an OS image with a Containerfile

Why? The Containerfile is now the blueprint of the whole operating system.
Containerfile
FROM registry.redhat.io/rhel10/rhel-bootc:10.0
RUN dnf install -y httpd && dnf clean all
RUN systemctl enable httpd
COPY motd /etc/motd
RUN useradd -m -G wheel admin1
$ podman login registry.redhat.io
$ podman build -t quay.io/student/my-rhel:1.0 -f Containerfile .
$ podman push quay.io/student/my-rhel:1.0
  • FROM ...rhel-bootc = the base OS image from Red Hat.
  • RUN dnf install runs at build time. You do not run dnf on the live server.
  • systemctl enable httpd makes the service start at boot.
  • podman push uploads the image so servers can pull it.
RuleAnything the server needs (packages, users, services, config files) goes into the Containerfile, and then you rebuild.

4bootc basics on a running server

Why? bootc is the one command to see, update and roll back the OS on the server.
$ sudo bootc status
● Booted image: quay.io/student/my-rhel:1.0
        Digest: sha256:4b2a...
       Version: 10.0 (2026-11-18)
  Rollback image: quay.io/student/my-rhel:0.9
$ sudo bootc upgrade
Fetching layers...
Queued for next boot: quay.io/student/my-rhel:1.1
$ sudo systemctl reboot
$ sudo bootc rollback
Next boot: rollback deployment
$ sudo bootc switch quay.io/student/other-image:2.0
CommandMeaning
bootc statusbooted image, staged image, rollback image
bootc upgradedownload the newer image of the same tag. Used after reboot
bootc switch IMAGEchange to a different image
bootc rollbackgo back to the previous OS on next boot
bootc upgrade --checkonly check for an update
Reboot activates itThe new image is staged in the background. You keep working, and the change is applied at the next reboot. If it fails, roll back.
Do not install packages on the server/usr is read-only. A change made by hand is not part of the image. Change the Containerfile instead.

What stays writable?

  • /etc and /var are writable. Config changes are kept across upgrades (merged with the new image).
  • /home and /root hold user data.
  • /usr is read-only.
