SELinux

SELinux is a second lock on every file, process and port. This chapter covers modes, contexts, booleans, and how to read a denial and fix it.

1What SELinux is and why we need it

Why? Normal permissions (rwx) only check the user. If a web server is hacked, it runs as apache and can read anything apache may read. SELinux (Security-Enhanced Linux) adds rules for what each program may touch, so a hacked service stays locked in its own box.
DAC (normal permissions)MAC (SELinux)
Full formDiscretionary Access ControlMandatory Access Control
Checksuser, group, rwxlabels (contexts) and policy
Can the owner change it?yesno, only the admin policy
Orderchecked firstchecked after DAC; both must allow
RememberIf rwx says yes but SELinux says no, the access is denied. The error looks like a normal "Permission denied", which confuses beginners.

2Modes and status: getenforce, setenforce, sestatus

Why? You must know if SELinux is blocking, only warning, or off. Permissive mode is the safe way to test.
ModeBehaviour
Enforcingrules are applied, violations are blocked and logged
Permissivenothing is blocked, violations are only logged (for testing)
DisabledSELinux is off (needs reboot to change, avoid it)
$ getenforce
Enforcing
$ sudo setenforce 0
$ getenforce
Permissive
$ sudo setenforce 1
$ sestatus
SELinux status:                 enabled
SELinuxfs mount:                /sys/fs/selinux
Loaded policy name:             targeted
Current mode:                   enforcing
Mode from config file:          enforcing
Policy MLS status:              enabled
Policy deny_unknown status:     allowed
  • getenforce = get enforcing mode (one word answer).
  • setenforce 0|1 changes the mode now, lost after reboot. 0 = Permissive, 1 = Enforcing.
  • sestatus = status, shows current mode and the mode in the config file.

Make it permanent: /etc/selinux/config

/etc/selinux/config
SELINUX=enforcing
SELINUXTYPE=targeted

Change the word after SELINUX= to enforcing, permissive or disabled, then reboot. The targeted policy protects network services and is the default.

Do not disable SELinuxInterviewers ask: "A service fails, what do you do?" The wrong answer is "turn SELinux off". Use permissive to test, then fix the context or boolean.

3Contexts: ls -Z and ps -Z

Why? SELinux decides using a label (context) on every file, process and port. To fix a denial you must read the labels first.
$ ls -Z /var/www/html/index.html
unconfined_u:object_r:httpd_sys_content_t:s0 /var/www/html/index.html
$ ps -Z -C httpd
LABEL                             PID TTY          TIME CMD
system_u:system_r:httpd_t:s0     1450 ?        00:00:00 httpd
$ id -Z
unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023
PartMeaning
user (_u)SELinux user
role (_r)role
type (_t)the important part. Rules say "type httpd_t may read type httpd_sys_content_t"
levelMLS/MCS security level, ignore at this stage

Common types

TypeUsed for
httpd_sys_content_tweb server files in /var/www/html
user_home_tfiles in /home
tmp_tfiles in /tmp
ssh_port_tSSH port 22
New files inherit the label of the folder they are created inCopying a file creates a new file, so it takes the target folder label. Moving (mv) keeps the old label. This is the #1 cause of "my website gives 403 after mv".

4Fix a wrong context: semanage fcontext and restorecon

Why? The label is wrong, so SELinux blocks the service. Two steps: save the correct rule (semanage fcontext), then apply it (restorecon). Without the first step the fix is lost on a full relabel.

Scenario: you made a web folder /web instead of /var/www/html. Apache gets 403 Forbidden.

$ sudo mkdir /web
$ echo "Hello" | sudo tee /web/index.html
$ ls -Zd /web /web/index.html
unconfined_u:object_r:default_t:s0 /web
unconfined_u:object_r:default_t:s0 /web/index.html
  1. Add the rule: semanage fcontext -a -t httpd_sys_content_t "/web(/.*)?"
  2. Apply it: restorecon -Rv /web
  3. Check: ls -Z /web
$ sudo semanage fcontext -a -t httpd_sys_content_t "/web(/.*)?"
$ sudo restorecon -Rv /web
Relabeled /web from unconfined_u:object_r:default_t:s0 to unconfined_u:object_r:httpd_sys_content_t:s0
Relabeled /web/index.html from unconfined_u:object_r:default_t:s0 to unconfined_u:object_r:httpd_sys_content_t:s0
$ ls -Z /web
unconfined_u:object_r:httpd_sys_content_t:s0 index.html
OptionMeaning
semanage fcontext -a -t TYPE "PATH(/.*)?"-a add rule, -t type. The pattern means the folder and everything inside
semanage fcontext -l | grep weblist saved rules
semanage fcontext -d "PATH(/.*)?"delete a rule
restorecon -Rv PATH-R recursive, -v show changes
touch /.autorelabel and rebootrelabel the whole system
Shortcut: copy the label of a good folderchcon -R -t httpd_sys_content_t /web changes the label now but it is temporary and is lost on a relabel. Use semanage fcontext + restorecon for a permanent fix.
If semanage is missingInstall the tools: sudo dnf install -y policycoreutils-python-utils.

5Booleans: getsebool and setsebool -P

Why? A boolean is an on/off switch for one allowed behaviour (for example "may httpd connect to the network?"). It is safer than writing new rules.
$ getsebool -a | grep httpd_can
httpd_can_check_spam --> off
httpd_can_network_connect --> off
httpd_can_sendmail --> off
$ sudo setsebool httpd_can_network_connect on
$ sudo setsebool -P httpd_can_network_connect on
$ getsebool httpd_can_network_connect
httpd_can_network_connect --> on
  • getsebool -a lists all booleans. Filter with grep.
  • setsebool NAME on is temporary (lost at reboot).
  • setsebool -P NAME on -P = Permanent (saved in the policy). Takes a few seconds.
  • semanage boolean -l shows each boolean with a description.
$ sudo semanage boolean -l | grep httpd_enable_homedirs
httpd_enable_homedirs   (off  ,  off)  Allow httpd to enable homedirs

6Reading denials: ausearch and sealert

Why? When SELinux blocks something it writes the reason in the audit log. Reading it tells you whether the fix is a label, a boolean or a port.
$ sudo ausearch -m AVC -ts recent
type=AVC msg=audit(1763634010.120:412): avc:  denied  { read } for  pid=1450 comm="httpd" name="index.html" dev="vda1" ino=1048700 scontext=system_u:system_r:httpd_t:s0 tcontext=unconfined_u:object_r:default_t:s0 tclass=file permissive=0
Word in logMeaning
denied { read }the blocked action
comm="httpd"the program
scontextsource (process) context: httpd_t
tcontexttarget (file) context: default_t. Wrong type here = the cause
tclass=fileobject kind (file, dir, tcp_socket)
AVCAccess Vector Cache = the denial message

sealert gives the fix in plain English

$ sudo dnf install -y setroubleshoot-server
$ sudo sealert -a /var/log/audit/audit.log
SELinux is preventing /usr/sbin/httpd from read access on the file index.html.
*****  Plugin catchall_labels (83.8 confidence) suggests  *****
If you want to allow httpd to have read access on the index.html file
Then you need to change the label on index.html
Do
# semanage fcontext -a -t FILE_TYPE '/web/index.html'
# restorecon -v '/web/index.html'
$ sudo journalctl -t setroubleshoot --since today

The fix workflow

  1. Service fails but rwx looks fine? Suspect SELinux. getenforce.
  2. Read the denial: ausearch -m AVC -ts recent or sealert.
  3. Wrong file label? semanage fcontext + restorecon.
  4. Missing permission? setsebool -P.
  5. Wrong port? semanage port (chapter 14).
  6. Test again. Do not leave SELinux in permissive.
