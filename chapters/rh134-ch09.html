Tuning System Performance

A server is slow? tuned applies a ready-made performance profile in one command, and nice / renice decide which process gets the CPU first.

Why tuningtuned-admnice and reniceScenarioCommands listQuiz

1Why tuning?

Why? A database server needs different settings than a laptop. Tuning adjusts kernel and disk settings for the job. Doing it by hand is hard, so Red Hat gives ready profiles through the tuned service.
Full formtuned = tuning daemon. nice is just a name: a "nice" process is kind to others, so it gets less CPU. renice = change the nice value of a running process.

2tuned and tuned-adm

Why? tuned-adm (tuned administration) is the one command you use to see, choose and check profiles.
$ sudo dnf install -y tuned
$ sudo systemctl enable --now tuned
$ tuned-adm active
Current active profile: virtual-guest
$ tuned-adm list

Where is the profile saved?The active profile name is stored in /etc/tuned/active_profile. Profile files are in /usr/lib/tuned/profiles/ and your own in /etc/tuned/profiles/.
tuned must be runningIf tuned-adm says it cannot talk to the daemon, run systemctl enable --now tuned.

3Process priority: nice and renice

Why? When many programs want the CPU, a heavy backup can slow your web server. Priority tells the scheduler who goes first.
$ ps -o pid,ni,comm -C sleep
    PID  NI COMMAND
   5120   0 sleep
$ nice -n 10 tar -czf /tmp/big.tar.gz /var &
[1] 5301
$ ps -o pid,ni,comm -p 5301
    PID  NI COMMAND
   5301  10 tar
  • nice -n VALUE command starts a new process with that nice value.
  • A normal user can only raise the number (lower priority).
  • Only root can use negative values (higher priority).

renice: change a running process

$ renice -n 15 -p 5301
5301 (process ID) old priority 10, new priority 15
$ sudo renice -n -5 -p 1450
1450 (process ID) old priority 0, new priority -5
$ renice -n 5 -u student
OptionMeaning
-p PIDa process id
-u USERall processes of a user
-g GIDa process group

See it in top

$ top
  PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM
 5301 student   30  10  210236   3568   3144 R  45.0   0.1 tar

The NI column is the nice value. PR is the kernel priority (PR = 20 + NI for normal processes).

Nice does not limit CPUIt only matters when the CPU is busy. On an idle server a nice 19 process still uses 100% CPU.

4Real scenario: nightly backup slows the web server

  1. Notice the slowness: top shows tar using high CPU.
  2. Find the PID: pgrep tar.
  3. Lower its priority: sudo renice -n 15 -p PID.
  4. Make the cron job nice from now: put nice -n 15 in the crontab line.
  5. If the whole server is for throughput, set tuned-adm profile throughput-performance.
crontab -e
0 2 * * * nice -n 15 /usr/bin/tar -czf /backup/www.tar.gz /var/www >> /var/log/backup.log 2>&1
