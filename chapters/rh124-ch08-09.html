Editing Text Files and Redirecting Shell Input and Output

Save command output into files, connect commands together, edit files in the terminal, and make the shell work the way you like. Simple words, pictures, and outputs explained line by line.

🧭 Before you start
• Linux keeps almost all settings in plain text files. So this chapter is about writing those files (redirection), changing them (editors), and setting up your shell (variables and aliases).
• Practise in your home folder on a practice VM. Example user: john.
• Lines starting with $ are commands you type (do not type the $). Lines without it are the output.
• Dates and numbers in outputs are examples. Yours will be different.

9.1 Redirecting Output to Files and Programs

File descriptors: the three channels of every command

When you run a command, the result normally appears on your screen. That is output. But Linux has not one, but three channels for every running program. Each channel has a number, called a file descriptor (FD).

Input comes in on channel 0. Results leave on channel 1. Errors leave on channel 2.
FDNameMeaningDefault
0stdin (standard input)Data going into a commandKeyboard
1stdout (standard output)Normal resultsTerminal screen
2stderr (standard error)Error messagesTerminal screen
3 and upother filesFiles the program opens itselfnone
💡 Why two output channels?
Results and errors are kept apart on purpose. You can save the results to a file and still see the errors on screen (or the other way round). On screen they look the same, but they are different channels.
$ ls /etc/hostname /fake/folder ls: cannot access '/fake/folder': No such file or directory # this line is stderr (channel 2) /etc/hostname # this line is stdout (channel 1) $ ls -l /proc/$$/fd # $$ = the ID of your current shell lrwx------. 1 john john 64 Oct 26 10:00 0 -> /dev/pts/0 lrwx------. 1 john john 64 Oct 26 10:00 1 -> /dev/pts/0 lrwx------. 1 john john 64 Oct 26 10:00 2 -> /dev/pts/0

Reading the second command: channels 0, 1 and 2 of your shell all point (->) to /dev/pts/0, which is your terminal window. That is why input, results and errors all use the same screen by default.

Output redirection: save results into a file

🚰 Water pipe analogy
Normally the results "flow" to the screen. With redirection you move the end of the pipe: the same water now flows into a bucket (a file).
OperatorWhat it doesKeyword
> fileSend stdout to a file. Replaces the old content. Creates the file if missingoverwrite
>> fileSend stdout to a file and add to the endappend
2> fileSend only errors to a file (overwrite)errors
2>> fileSend only errors to a file (append)errors, append
2> /dev/nullThrow away the errorsdiscard
> /dev/nullThrow away the normal outputdiscard
> file 2>&1Results and errors into the same file (overwrite)both
&> fileSame as above (shorter, Bash only)both
>> file 2>&1Results and errors into the same file (append)both, append
&>> fileSame as above (shorter, Bash only)both, append
&> /dev/nullThrow away everythingsilence

/dev/null is a special "black hole" file. Anything sent there disappears.

Overwrite (>) versus append (>>)

$ echo "Hello" > file.txt # file.txt is created and contains: Hello $ echo "World" >> file.txt # World is ADDED below Hello $ cat file.txt Hello World $ echo "Only me" > file.txt # > wipes the old content first! $ cat file.txt Only me
⚠️ One arrow deletes, two arrows add
A single > destroys what was in the file, without asking. Be extra careful when the file is important (for example ~/.bashrc). When in doubt, use >>.

More everyday examples

$ date > /tmp/saved-timestamp # save the date and time $ tail -n 100 /var/log/dmesg > /tmp/last-100 # save the last 100 lines of a file $ cat step1.sh step2.log > /tmp/all-in-one # join several files into one $ ls -a > my-file-names # save the list of files (hidden too) $ echo "new line of information" >> /tmp/many-lines

Create files without an editor

$ > empty.txt # an empty file (careful: empties an existing one!) $ echo "Hello World" > myfile.txt # a one-line file $ cat > notes.txt # type lines, finish with Ctrl+D $ cat > conf.txt << EOF # "here-document": type many lines, end with the word EOF > line 1 > line 2 > EOF $ cat conf.txt line 1 line 2

With << EOF the shell keeps reading your typing until you write a line that contains only EOF. The > signs at the start of the lines are the shell asking for more.

🔒 Extra: protect files from accidental overwrite (noclobber)
$ set -o noclobber # now > refuses to replace an existing file $ echo hi > f.txt bash: f.txt: cannot overwrite existing file $ echo hi >| f.txt # >| = "yes, I really mean it" $ set +o noclobber # switch the protection off again

Handling errors

The find command is a good test. A normal user is not allowed to look inside some folders, so find prints many errors:

$ find /etc -name passwd find: '/etc/audit': Permission denied /etc/passwd find: '/etc/sudoers.d': Permission denied /etc/pam.d/passwd

Reading the output: lines starting with find: are errors (stderr). Lines that are just a path are the results (stdout). Now we separate them:

$ find /etc -name passwd 2> /tmp/errors # errors → file. Results stay on screen $ find /etc -name passwd > /tmp/output 2> /tmp/errors # results → one file, errors → another file $ find /etc -name passwd > /tmp/output 2> /dev/null # results saved, errors thrown away $ find /etc -name passwd &> /tmp/all-messages # everything into one file $ find /etc -name passwd >> /tmp/all-messages 2>&1 # everything, appended to the file $ cat /tmp/output /etc/passwd /etc/pam.d/passwd # clean list: no error lines

Order matters with 2>&1

2>&1 means: "make channel 2 go where channel 1 goes right now". The shell reads left to right, so the order changes the result.

Always write the file first, then 2>&1 after it.
📝 &> versus > file 2>&1
&> and &>> work only in Bash. In scripts that must run in other shells (sh, dash), write the long form > file 2>&1.

Input redirection: feed a file into a command

Output redirection uses > (arrow pointing out to a file). Input redirection uses < (arrow pointing in to the command).

OperatorNameExample
< fileInput redirectwc -l < /etc/passwd
<< WORDHere-document (many lines)cat << EOF … EOF
<<< "text"Here-string (one piece of text)tr 'a-z' 'A-Z' <<< "hello"
$ wc -l /etc/passwd # wc -l counts lines. It opens the file itself 42 /etc/passwd $ wc -l < /etc/passwd # the shell gives the file to wc as input 42 $ sort < unsorted.txt > sorted.txt # input AND output redirection together $ tr 'a-z' 'A-Z' <<< "hello" HELLO

Notice: with wc -l file the output has the file name after the number. With wc -l < file the command only sees a stream of data, so it prints just the number.

Pipes: connect commands together

A pipe (the vertical bar |) sends the output of one command directly into the input of the next command. No file is needed in between.

Each command does one small job. The pipe passes the result along, like a factory line.
$ ls -l /usr/bin | less # read a long list page by page (q to quit) $ ls | wc -l # how many items are in this folder? $ ls -t | head -n 10 > /tmp/ten-newest # 10 newest files, saved into a file $ ps aux | grep sshd # show only the lines that contain "sshd" $ cat /etc/passwd | cut -d: -f1 | sort # usernames, in alphabetical order $ history | tail -n 5 # your last 5 commands $ find /etc -name "*.conf" 2>/dev/null | wc -l # count .conf files, ignore errors

📄 Redirection

Connects a command and a file.
ls > list.txt
sort < list.txt

🔗 Pipe

Connects a command and another command.
ls | sort

tee: save AND see at the same time

tee works like a T-shaped pipe fitting: the data goes on to the next step and a copy is saved in a file.

tee = T-junction: the data splits in two.
$ ls | tee output.txt # shows the list AND saves it $ ls -l | tee /tmp/saved-output | less # save it, then page through it $ ls -t | head -n 10 | tee /tmp/ten-last-changed # save and show $ ls | tee -a output.txt # -a = append instead of overwrite
⚠️ Classic mistake: redirect in the middle of a pipe
$ ls > /tmp/saved-output | less # less shows NOTHING!
The > sends all output to the file, so nothing is left to flow into less. Use tee when you want both.

Pipe the errors too

A pipe carries only stdout. To send errors through as well:

$ find / -name passwd 2>&1 | less # errors joined to the results, then piped $ find / -name passwd |& less # Bash shortcut for the same thing

&> and &>> cannot be used in the middle of a pipe. Remember the syntax of find: path first, then the options (find / -name passwd).

Cheat sheet: where does it go?

You writeMeaning
cmd > fresults → file f
cmd 2> ferrors → file f
cmd > f 2>&1results and errors → file f
cmd < ffile f → input of cmd
cmd1 | cmd2results of cmd1 → input of cmd2
cmd1 |& cmd2results and errors of cmd1 → cmd2
cmd | tee fscreen (or next command) and file f
🧩 Extra: open your own channel (intermediate)
$ exec 3> mylog.txt # open channel 3 and point it at a file $ echo "hello" >&3 # write to channel 3 $ exec 3>&- # close channel 3

8.1 Editing Text Files from the Command Line

Which editor should I choose?

Servers usually have no desktop, and you connect over SSH. So you need an editor that works inside the terminal.

💡 Recommendation
Learn the vim basics (the survival kit below). Almost every server has vi/vim, and exams use it. Use nano when you want something quick and simple.
$ sudo dnf install vim-enhanced nano # install both $ export EDITOR=nano # default editor for tools like crontab -e or git commit $ export VISUAL=nano # some programs read VISUAL first

  • To skip an alias for one command, put a backslash first: \vi file.
  • Safer way to edit a root-owned file: sudoedit /etc/file (or sudo -e).

Vi / Vim editor

Vim is different from other editors: it has modes. In each mode the same key does a different job. This is the most important idea. Once you know the modes, vim is easy.

Vim settings files

/etc/vimrc is for all users. ~/.vimrc is for you only. Example:

" ~/.vimrc (a double quote starts a comment) set number set expandtab set tabstop=2 set shiftwidth=2 autocmd FileType yaml setlocal ts=2 syntax on
📝 Why indentation settings matter
YAML files (used by Ansible and Kubernetes) are strict about spaces. A tab or a wrong number of spaces breaks the file. expandtab turns a Tab key press into spaces.

Extra: edit text without opening an editor (sed and awk)

Nano and vim are interactive: you open the file, change it, save it. sed and awk change or read text in one command, which is perfect for pipes and scripts. We use this small file:

$ cat people.txt john 30 usa alice 25 uk bob 40 canada

sed: find and replace (stream editor)

CommandWhat it does
sed 's/usa/US/g' people.txtReplace "usa" with "US" (s = substitute, g = every match on the line). Shows the result; the file is not changed
sed -i 's/usa/US/g' people.txt-i = change the file in place (for real)
sed -i.bak 's/usa/US/g' people.txtSame, but first keeps a backup people.txt.bak
sed '/bob/d' people.txtDelete lines that contain "bob"
sed -n '2p' people.txtPrint only line 2 (-n = be quiet, p = print)
$ sed 's/usa/US/g' people.txt john 30 US alice 25 uk bob 40 canada $ echo "hello root" | sed 's/root/admin/' # works in a pipe too hello admin

awk: work with columns

awk cuts every line into fields (columns), split by spaces or tabs. Then you pick the columns you want.

$1johnFirst column
$230Second column
$3 or $NFusaThird column. $NF = the last column
NR1The line number awk is reading now
NF3The number of fields on this line
$ awk '{print $1}' people.txt # first column only john alice bob $ awk '$2 > 28 {print $1, $2}' people.txt # only lines where column 2 is bigger than 28 john 30 bob 40 $ awk 'NR==2' people.txt # only line number 2 alice 25 uk $ awk -F: '{print $1, $7}' /etc/passwd | head -2 # -F: = columns are split at colons root /bin/bash bin /sbin/nologin $ awk -F: '$3 >= 1000 {print $1, $3}' /etc/passwd # regular users (UID 1000 and up) john 1000 alice 1001

The pattern is: awk 'condition { action }' file. If you give no condition, the action runs on every line. If you give no action, awk prints the matching lines.

RH134 1.1 Changing the Shell Environment

Variables: named boxes that hold text

📦 Labelled box analogy
A variable is a box with a label. The label is the name (COUNT) and inside is the value (40). The shell and many programs read these boxes to learn things like your username or your home folder.

Shell variable versus environment variable

export = "share this variable with the programs I start".

Create a variable

$ COUNT=40 # shell variable $ first_name=John $ MSG="hello world" # a value with a space needs quotes $ export EDITOR=vim # create AND share it (environment variable)
RuleGoodBad
Name: letters, digits, underscore; not starting with a digit_ID, file11file
No spaces around =COUNT=40COUNT = 40
Quotes for values with spacesMSG="hello world"MSG=hello world
Habit: ALL CAPS for system variables, lowercase for yoursmy_file

Use a variable: the $ sign

$ COUNT=40 $ echo COUNT COUNT # no $ = just the word $ echo $COUNT 40 # $ = "give me what is inside the box" $ echo ${COUNT}x 40x # braces mark where the name ends $ echo $COUNTx # shell looks for a variable named COUNTx: empty, no error

A useful trick for long file names:

$ file1=/tmp/tmp.z9pXW0HqcC $ ls -l $file1 $ rm $file1

Command substitution: use a command's output as a value

$ today=$(date +%F) $ echo "Backup_$today.tar.gz" Backup_2026-10-26.tar.gz $ cp notes.txt notes_$(date +%s).txt # %s = seconds since 1970, so the name is always unique

Write $( ), not the old backticks.

QuoteEffectExample
"double"Variables and $( ) are expandedecho "Hi $USER" → Hi john
'single'Everything is literalecho 'Hi $USER' → Hi $USER
\Protects the next characterecho \$USER → $USER

PATH: where does the shell look for commands?

When you type ls, the shell must find the program file. PATH is a list of folders, separated by colons. The shell checks them from left to right and runs the first match.

If the command is not in any listed folder: "command not found".
$ echo $PATH /home/john/.local/bin:/home/john/bin:/usr/local/bin:/usr/bin:/usr/local/sbin:/usr/sbin $ export PATH=${PATH}:/home/john/scripts # add a folder at the END (this session only) $ which ls ; type ls # where is a command? what kind is it? /usr/bin/ls ls is aliased to `ls --color=auto'

Reading the type ls answer: on RHEL ls is actually an alias that adds colours (aliases are explained below).

LANG and HISTTIMEFORMAT examples

$ date Mon Oct 26 10:05:00 UTC 2026 $ export LANG=fr_FR.UTF-8 # works only if that language is installed on the system $ date lun. 26 oct. 2026 10:05:10 UTC $ HISTTIMEFORMAT="%F %T " $ history | tail -2 101 2026-10-26 10:05:10 date 102 2026-10-26 10:05:25 history | tail -2

For a permanent system-wide language, use sudo localectl set-locale LANG=en_US.UTF-8.

PS1: design your prompt

$ PS1="[\u@\h \t \w]\$ " [john@server1 10:07:12 ~]$
\ujohnYour username
\hserver1Short hostname
\t10:07:12Time (24 hour)
\w~Current folder (full path; ~ = home). \W = only the last part
\$$$ for normal users, # for root
💡 Tip
Put the value in quotes, and end it with a space, so your typing does not touch the prompt.

Bash reads some text files when it starts. Which files depend on the type of shell:

The name starts with a dot (.bash_profile), so it is a hidden file. The default ~/.bash_profile on RHEL:

# .bash_profile # Get the aliases and functions if [ -f ~/.bashrc ]; then . ~/.bashrc fi # User specific environment and startup programs

Reading it: "if the file ~/.bashrc exists, run it". The dot at the start of . ~/.bashrc is the same as the command source.

💡 Rule of thumb: where do I put it?
• Aliases, prompt (PS1), functions → ~/.bashrc
• Settings once per login (EDITOR, extra PATH) → ~/.bash_profile
• For all users → create a file such as /etc/profile.d/custom.sh (as root). Do not edit /etc/profile itself.
# /etc/profile.d/custom.sh export COMPANY="Example Corp"

Aliases: your own shortcuts

An alias is a short name that is replaced by a longer command.

$ alias hello='echo "Hello, this is a long string."' $ hello Hello, this is a long string. $ alias ll='ls -lh --color=auto' # long list with readable sizes $ alias update='sudo dnf update -y' $ alias grep='grep --color=auto' $ alias c='clear' $ alias # list all aliases $ type ll # what is "ll"? ll is aliased to `ls -lh --color=auto' $ unalias hello # remove one alias $ unalias -a # remove ALL aliases (this session) $ \ls # backslash = ignore the alias for this one run
📝 Aliases are temporary
An alias lives only in the shell where you typed it. When you close the terminal it is gone, unless you save it in ~/.bashrc (see next part).
💡 Need arguments? Use a function
An alias is only text replacement. For logic or arguments, write a function:
$ mkcd() { mkdir -p "$1" && cd "$1"; } # make a folder and go into it $ mkcd projects/test

Make changes permanent

❗ Key idea
Typing export X=1 or alias a=b in a terminal lasts only for that terminal session. To keep it for ever, write it into a startup file.
  1. Open your file: vim ~/.bashrc (or nano ~/.bashrc)
  2. Add your lines at the bottom:
    PS1='[\u@\h \t \w]\$ ' alias ll='ls -lh' export EDITOR=vim export PATH=$PATH:$HOME/bin
  3. Save and quit, then apply it without logging out: source ~/.bashrc (or . ~/.bashrc)

Or add one line straight from the command line:

$ echo "alias ll='ls -lh'" >> ~/.bashrc $ echo 'export EDITOR=vim' >> ~/.bash_profile $ source ~/.bashrc
⚠️ Use >> (append), never >
A single > would erase your whole .bashrc and put only the new line in it.
I want…Put it in…Applies to
An alias or prompt for me~/.bashrcEvery interactive shell of mine
A variable once per login~/.bash_profileMy login shells
A setting for everyone/etc/profile.d/name.shAll users' login shells
Only for nowType it in the terminalThis shell only

Test it: open a new login shell (bash -l, or exit and log in again) and run echo $EDITOR and alias. Remove it: unset NAME, unalias name, and delete the line from the file, or it returns at the next login.

📝 Good to know (RHEL)
• /etc/environment is not read by Bash. Use /etc/profile.d/*.sh for system-wide variables.
• Find which file sets a value: grep -R "EDITOR" ~/.bash* /etc/profile /etc/profile.d/ 2>/dev/null
• Before editing an important config file, make a backup: cp file file.bak

Extra: command history

Bash remembers the commands you typed, so you do not have to type them again.

$ history | tail -3 98 ls /etc 99 cd /tmp 100 history | tail -3 $ !! # run the LAST command again $ sudo !! # last command again, with sudo (when you forgot it) $ !98 # run command number 98 (ls /etc) $ !ls # run the last command that started with "ls" $ history -c # clear the history of this shell

Ctrl+R is the fastest tool: press it, type a few letters of an old command, and Bash shows the match. Press Enter to run it, or Esc to edit it. The history is saved to ~/.bash_history when the shell exits.
