2.1 Matching Text with Regular Expressions

Goal: build patterns that find the exact lines you want in a file or in the output of any command.

regexpatternmetacharacteranchor ^ $wildcard .multiplier * + ? {}grepBRE / ERE

What is a regular expression?

A regular expression (regex) is a small pattern that describes text. Instead of searching for one fixed word, you describe a shape: "a line that starts with a number", "any word ending in dog", "an IP address". A tool reads each line and tells you if the line fits the pattern.

Tools that understand regex: grep, sed, awk, less, vim, and languages like Python, C and Rust. The syntax is almost the same everywhere, with small differences. This chapter uses the Bash/Linux version.

REAL WORLD

Finding one needle in 200,000 log lines. A website is slow. The log file has hundreds of thousands of lines. With regex you ask for "every line with status 500 or 503 from this hour" and get 40 lines in under a second. Without it you would scroll for days.

The simplest pattern: exact text

Plain letters match themselves, in the same order, with nothing between them. The pattern cat means: letter c, then a, then t.

Searching this file for cat:

cat

boondoggle
vindication
chilidog

Matches: cat, concatenate, category, educated (educated), vindication (vindication). Notice the pattern does not care about word borders.

Find empty lines and comment lines. ^$ matches a blank line (start immediately followed by end). ^# matches lines that begin with a hash, which are comments in most config files. Anchors are what make both patterns possible.

Wildcard: the dot

The dot . means "any one character" (but not the line break). So c.t means: c, one anything, t.

c.t   matches:  cat   cut   cot   c9t   c t   c$t   (and inside concatenate, vindication)
c.t   does NOT match:  ct   (nothing between)   cart   (two letters between)

Brackets: choose from a set

Square brackets [ ] mean "one character from this list". It is a safer wildcard because you decide the allowed letters.

BracketMeans
[abc]a or b or c
[a-z]any lowercase letter (a range)
[0-9]any digit
[A-Za-z0-9]any letter or digit
[^0-9]NOT a digit (the ^ inside brackets means "not")
[#;]# or ;
[Nn][Tt][Pp]ntp in any mix of upper and lower case
Two different jobs for ^ Outside brackets ^ means "start of line". Inside the very first spot of a bracket it means "not". ^[0-9] = line starts with a digit. [^0-9] = one character that is not a digit.

Multipliers: how many times?

A multiplier (also called quantifier) applies to the one item just before it (a letter, a dot, or a bracket).

ExtendedBasicMeaningExampleMatches
**zero or moreab*cac, abc, abbbc
+\+one or moreab+cabc, abbc (not ac)
?\?zero or one (optional)colou?rcolor, colour
{n}\{n\}exactly n times[0-9]{4}2026
{n,}\{n,\}n or more[a-z]{3,}abc, hello
{,m}\{,m\}at most m[0-9]{,2}"", 7, 42
{n,m}\{n,m\}between n and m[0-9]{2,4}12, 123, 1234
c[aou]*t    matches  ct  cat  coat  coot     # zero or more of a, o or u
c.*t        matches  ct  cat  coat  culvert  # c, anything (or nothing), t
c.{2}t      matches  coat  cart              # c, exactly two of anything, t

Test c.{2}t on this list: cat (only 1 between: no), coat (yes), convert (no), cart (yes), covert (no), cypher (no). Two matches.

.* is the "anything" combo .* = any number of any characters. start.*end finds lines where "start" comes first and "end" comes later.

Basic vs Extended: the backslash switch

There are two flavours of regex. They differ in how these characters act: | + ? ( ) { }

Beginner advice Use grep -E (extended) for most work. It reads more naturally and needs fewer backslashes. The older egrep command is outdated, so use grep -E instead.

Character classes: ready-made sets

Classes are named sets written inside brackets, like [[:digit:]] (note the double brackets). They are safer than ranges because they work in every language setting.

ClassMeaningSame as
[:digit:]digits0-9
[:alpha:]lettersA-Za-z
[:alnum:]letters and digits0-9A-Za-z
[:lower:]lowercase lettersa-z
[:upper:]uppercase lettersA-Z
[:blank:]space and tab
[:space:]space, tab, newline and similar
[:punct:]punctuation like ! " # $ % & ( ) *
[:xdigit:]hex digits0-9A-Fa-f
[:cntrl:]control characters
[:graph:]visible characters (letters, digits, punctuation)
[:print:]visible characters plus space
grep '[[:digit:]]'   file     # lines with at least one digit
grep '^[[:upper:]]'  file     # lines starting with a capital letter
grep '[^[:alnum:]]'  file     # lines containing a symbol or space

Word and space shortcuts

grep '\<cat\>' file     # the whole word cat only (not category, not concatenate)

Regex vs shell globbing: do not mix them up

Both use symbols like *, but they are different tools with different rules.

SymbolIn a shell globIn a regex
*any characters (including none)zero or more of the previous item

.just a dotany one character

REAL WORLD

The classic mix-up. A new admin types grep *.conf /etc to "find all conf files". The shell expands *.conf to local file names and grep gets confused. Correct tools: ls /etc/*.conf for file names, or grep -r 'Listen' /etc --include='*.conf' to search inside them.

Using grep: the main regex tool

grep PATTERN FILEpipe |-i-v-r-A -B-e-E

grep reads text line by line and prints every line that matches your pattern. The name means "global regular expression print".

grep '^computer' /usr/share/dict/words
computer
computerese
computerise
...

With several files, grep puts the file name and a colon in front of every result:

grep apache /etc/passwd /etc/group
/etc/passwd:apache:x:48:48:Apache:/usr/share/httpd:/sbin/nologin
/etc/group:apache:x:48:
Always use single quotes around the pattern Characters like $, *, {} and | mean something to the shell. Single quotes hand the pattern to grep exactly as typed. Without quotes the shell may change it first.

grep on command output with a pipe

The pipe | sends the output of one command into grep as its input.

ps aux | grep chrony
chrony   915  0.0 ...  /usr/sbin/chronyd -F 2
root    2297  0.0 ...  grep --color=auto chrony
grep finds itself! The second line above is the grep command itself, because its own command line contains the word chrony. Trick: write grep '[c]hrony'. The pattern [c]hrony matches "chrony" but the text [c]hrony does not match itself, so grep disappears from the result. Or use pgrep chronyd.

Example: ignore case with -i

grep -i serverroot /etc/httpd/conf/httpd.conf
# with "/", the value of ServerRoot is prepended ...
ServerRoot "/etc/httpd"

Example: reverse the match with -v

grep -v -i server /etc/hosts      # lines WITHOUT "server" in any case

Example: hide comments to read a config

grep -v '^[#;]' /etc/systemd/system/multi-user.target.wants/rsyslog.service
[Unit]
Description=System Logging Service
...
[Install]
WantedBy=multi-user.target

^[#;] means "line that starts with # or ;". With -v those lines disappear. In that file # is a general comment and ; is a commented-out value.

Example: look for several things at once with -e

grep -e 'pam_unix' -e 'user root' -e 'Accepted publickey' /var/log/secure | less

This finds lines that contain any of the three phrases. It is the same as grep -E 'pam_unix|user root|Accepted publickey'.

Example: show context with -A and -B

systemctl status httpd | grep Active -B 2 -A 3

The word is Active with a capital A. Regex is case-sensitive, so active would not match that line.

    Both UID and GID are 48. The path in front of each result tells you which file it came from.

2.3 Quiz Walkthrough: Matching Text with Regular Expressions

Work with this sample file called words.txt. Try each question before opening the answer.

bash      RedHat    systemd   init      kernel
tty6      passwd    shadow    mount     lsmod
12345     grep      cron      fstab     404
(each word is on its own line)
Q1. Which expression matches only lines that contain at least one digit? a) [[:alpha:]] b) [[:digit:]] c) [a-z0-9] d) [^[:digit:]]

Answer: b. [[:digit:]] is any digit. Lines found: tty6, 12345, 404. Option a finds letters. Option c matches any letter or digit, so it matches almost every line. Option d means "not a digit" so it matches lines with at least one non-digit.

Q2. Which expression matches only the RedHat line? a) ^[A-Z] b) [A-Z]$ c) ^[a-z] d) ^A-Z

Answer: a. ^[A-Z] = line starts with a capital letter. Only RedHat does. Option b needs a capital at the end (none). Option c matches every lowercase-start line. Option d is wrong because without brackets it looks for a literal "A-Z".

Q3. Which expression matches lines with at least three lowercase letters in a row? a) [a-z][a-z][a-z] b) [a-z]*3 c) [a-z][0-9][a-z] d) [a-z]\{3,\}

Answer: d. \{3,\} means "3 or more" of the previous item, in basic syntax. Option a also finds three letters in a row, but it is written for exactly that and gets long. The {3,} form says "at least three" clearly and scales to any number. Option b treats "3" as a literal character. Option c needs a digit in the middle.

Q4. Which lines match '^[[:digit:]]*$' ? a) 12345, 404 b) tty6 c) tty6, 12345, 404 d) none

Answer: a. Start, then only digits (zero or more), then end. That means "a line made only of digits". 12345 and 404 qualify. tty6 has letters. Warning: an empty line also matches because * allows zero digits.

Q5. Which command lists all lines that do not contain kernel, any case? a) grep -v 'kernel' b) grep -i 'kernel' c) grep -iv 'kernel' d) grep --exclude 'kernel'

Answer: c. -i ignores case and -v inverts. Together they show lines without "kernel", "Kernel", "KERNEL" and so on. Option a is case-sensitive. Option b shows the matching lines instead. --exclude is for file names.

Q6. Which command shows three lines before and three lines after each match for cron? a) grep -A3B3 b) grep -AB3 c) grep -C6 d) grep -A3 -B3

Answer: d. -A3 is 3 after, -B3 is 3 before. The shorter grep -C 3 cron words.txt does the same. -C6 would show six on each side. Options a and b are not valid syntax.

2.4 Summary

  • A regular expression is a pattern for text. Plain letters match themselves.
  • ^ and $ pin a match to the start or end of a line.
  • . is any one character. [abc] is one from a set. [^abc] is anything except the set.
  • Multipliers * + ? {n,m} say how many times the previous item repeats.
  • Basic (grep, sed, vim) needs a backslash for + ? ( ) { } |. Extended (grep -E) does not.
  • grep filters files or piped output. Key options: -i -v -r -A -B -e -E.
  • Always put patterns in single quotes.
  • In less and vim press / to search, n for next and N for previous.

2. Special characters and how to match them literally

These characters have a special job: . * [ ] ^ $ \ and in extended mode also + ? ( ) { } |. To search for the real character, put a backslash before it.

grep '192\.168\.1\.1' file        # literal dots
grep 'cost: \$5'       file        # literal dollar
grep -F '192.168.1.1'  file        # easiest: -F means "no regex at all"
The unescaped dot trap 192.168.1.1 as a regex also matches 192x168y1z1, because each dot is a wildcard. Escape the dots or use -F.

3. OR and groups (extended)

grep -E 'cat|dog' file                     # cat OR dog
grep -E '^(error|warn|fail)' log           # lines starting with any of the three
grep -E '(ab)+' file                       # ab, abab, ababab ...
grep -E '^(Mon|Tue|Wed)day' file

In basic mode (GNU grep) you can write \| for OR and \( \) for groups.

4. Greedy matching: .* takes as much as it can

echo '<b>hi</b> and <i>you</i>' | grep -oE '<.*>'
<b>hi</b> and <i>you</i>          # one huge match: greedy

echo '<b>hi</b> and <i>you</i>' | grep -oE '<[^>]*>'
<b>
</b>
<i>
</i>                                  # each tag on its own: better

Rule: when .* grabs too much, replace it with "anything except the end character", like [^>]*.

5. Back-references: match the same text again

grep -E '([a-z])\1' words      # a doubled letter, like oo and gg in boondoggle
grep -E '^(.+) \1$' file       # line made of the same text twice

\1 repeats whatever the first group matched.

6. grep -P (Perl style) for advanced work

grep -oP '(?<=user=)\w+' file    # print the word that follows "user="
grep -P '\d{3}-\d{4}' file         # \d is "digit" in Perl style

-P adds \d, lazy matching (.*?) and look-around. It is not part of the standard POSIX set, so avoid it in portable scripts.

7. sed: search and replace with regex

sed 's/old/new/'          file     # replace first "old" on each line
sed 's/old/new/g'         file     # replace every "old"
sed -E 's/[0-9]+/NUM/g'   file     # replace every number
sed -n '/error/p'         file     # print only matching lines (like grep)
sed '/^#/d'               file     # delete comment lines
sed -i 's/Listen 80/Listen 8080/' httpd.conf   # edit the file in place
Be careful with -i sed -i changes the file for real. Make a backup first: sed -i.bak 's/a/b/' file keeps the original as file.bak.

9. Locale and ranges

In some language settings [a-z] can include capital letters. Classes like [[:lower:]] are always correct. For exact byte behaviour you can run LC_ALL=C grep ....

10. Use the exit code in scripts

if grep -q '^PermitRootLogin yes' /etc/ssh/sshd_config; then
    echo "Root login is ON" >&2
fi

grep exits with 0 if there was a match, 1 if there was none, and 2 for an error such as a missing file.

11. Handy tools built on the same idea

  • pgrep name: find processes by name without the "grep finds itself" problem.
  • awk '/pattern/ {print $1}' file: match lines and print chosen columns.
  • find /etc -name '*.conf': glob style names, not regex.
  • zgrep: grep inside compressed .gz logs.
  • journalctl -g 'pattern': regex search in the systemd journal.

Real-World Scenarios

SCENARIO 1

Who is attacking my SSH server?

You suspect password guessing on a server.

sudo grep 'Failed password' /var/log/secure \
  | grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' \
  | sort | uniq -c | sort -rn | head

What happens: grep keeps the failure lines, -oE cuts out only the IP addresses, sort | uniq -c counts each, and the top 10 attackers are shown. Add the worst IP to a firewall block.

SCENARIO 2

Read a config file without the noise

A 900-line config has 850 comment and blank lines. See the 50 real settings:

grep -Ev '^[[:space:]]*(#|$)' /etc/httpd/conf/httpd.conf

Reads as: not (spaces, then a # or an end of line). That removes comments (even indented ones) and blank lines.

SCENARIO 3

Which config file sets this option?

Something listens on port 8080 and you do not know where it is set.

sudo grep -rn 'Listen' /etc/httpd --include='*.conf'

Result: file name, line number and the line. You edit the right file the first time.

SCENARIO 4

Find the first error and what happened around it

grep -n -B 5 -A 5 -m 1 'ERROR' app.log

Why: the first error often causes all later errors. -m 1 stops after the first match and the context lines show the events right before and after it.

SCENARIO 5

Count server errors per hour

grep -E '" 5[0-9]{2} ' access.log | cut -d: -f2 | sort | uniq -c

Result: a short table: hour and how many 5xx errors. Spikes show you when the problem started.

SCENARIO 6

Audit: find users who can log in

grep -vE '(nologin|false)$' /etc/passwd | cut -d: -f1

Reads as: lines that do NOT end with nologin or false. These accounts have a real shell. A quick security check.

SCENARIO 7

Clean a customer list

grep -E '^[[:alnum:]._-]+@[[:alnum:].-]+\.[[:alpha:]]{2,}$' emails.txt   # valid-looking
grep -vE '^[[:alnum:]._-]+@[[:alnum:].-]+\.[[:alpha:]]{2,}$' emails.txt  # suspicious ones

Use: with one pattern and one flag you split good-looking data from bad before importing into a database.
