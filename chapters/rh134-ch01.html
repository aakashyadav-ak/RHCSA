1.1 Changing the Shell Environment

Goal: understand variables, and control how the shell and your programs behave.

shellvariableexportenvironment variablePATHPS1alias~/.bashrc

What is a shell?

The shell is a program that reads the commands you type and asks Linux to run them. On RHEL the default shell is Bash (Bourne Again SHell). Every terminal window or SSH login starts its own shell.

What is a variable?

A variable is a named box that holds a value. You put something in once, then use it many times. This saves typing and avoids mistakes.

NAME=value        # correct: no spaces around =
COUNT=40
first_name=John
full_name='John Smith'   # quotes needed because of the space
file1=/tmp/abc
No spaces around the equal sign COUNT = 40 fails. Bash thinks COUNT is a command and = and 40 are its arguments.

Naming rules

  • Use letters, digits and underscore _ only.
  • Do not start with a digit.
  • Names are case-sensitive: Count and COUNT are different.
  • System variables are UPPERCASE (HOME, PATH). Use lowercase for your own to avoid clashes.

Using a variable: expansion with $

COUNT=40
echo COUNT              # prints the word COUNT
echo $COUNT             # prints 40
echo "Count is $COUNT"  # Count is 40
echo 'Count is $COUNT'  # Count is $COUNT  (single quotes = literal)
echo "Repeat $COUNTx"   # empty! Bash looks for a variable named COUNTx
echo "Repeat ${COUNT}x" # Repeat 40x  (braces fix it)
Good habit Always write "${var}": double quotes plus braces. It protects you when values contain spaces or when text sits right after the name.

How PATH works

When you type ls, Bash looks in each folder of PATH, from left to right, and runs the first match. That is why you can type ls instead of /usr/bin/ls.

echo $PATH
export PATH=${PATH}:/home/user/sbin     # add at the END (lowest priority)
export PATH=/home/user/sbin:${PATH}     # add at the START (highest priority)
which ls                                # shows /usr/bin/ls
REAL WORLD

"command not found" after installing a tool. You install a tool into /opt/mytool/bin and the shell says command not found. The folder is not in PATH. Fix: export PATH=$PATH:/opt/mytool/bin. Put it in ~/.bashrc to make it permanent.

Make settings permanent: startup files

Changes you type at the prompt vanish when the shell closes. To keep them, write them in a startup file. Which file Bash reads depends on how the shell was started.

Shell typeHow you get itFiles read
Login (interactive)Console login, ssh/etc/profile, then ~/.bash_profile (which loads ~/.bashrc)
Non-login (interactive)Open a terminal in the desktop, or type bash/etc/bashrc and ~/.bashrc
Non-interactiveA script runsOnly the file named in BASH_ENV (empty by default)
# ~/.bash_profile
if [ -f ~/.bashrc ]; then
    . ~/.bashrc
fi
export EDITOR=nano
Rules of thumb Personal settings go in ~/.bashrc. Settings for all users: create a .sh file in /etc/profile.d/ as root, instead of editing /etc/profile. After editing, load it now with source ~/.bashrc.

Aliases: your own short commands

alias ll='ls -lah'
alias hello='echo "Hello, this is a long string."'
hello
alias            # list all aliases
unalias hello    # remove one
REAL WORLD

Protect yourself from typos. Many admins add alias rm='rm -i' so rm asks before deleting. Another favourite: alias update='sudo dnf update -y'.

Remove variables

unset file1        # delete the variable completely
export -n PS1      # keep it, but stop sharing it with child programs
unalias hello      # delete an alias

1.3 Writing Simple Bash Scripts

scriptshebang #!chmod +x$1 $2STDOUTSTDERRredirect

What is a script?

A script is a text file full of commands. Instead of typing 20 commands every day, you save them once and run the file. Scripts are faster, repeatable and make fewer mistakes than humans.

REAL WORLD

Daily health report. Every morning an admin needs disk space, memory, and failed services. A 10-line script runs all three commands and saves a report. Combined with cron it runs by itself at 7 AM.

The shebang line

The first line of a script is #!/usr/bin/bash. It is called the shebang (sharp + bang). It tells Linux which program should read the file.

#!/usr/bin/bash
echo "Hello, world"

Running ./script.sh then works like /usr/bin/bash script.sh.

Create, allow, run

chmod +x firstscript.sh     # give execute permission
./firstscript.sh            # run from the current folder (./ means "here")

Run it by name from anywhere

Put the script in a folder that is in PATH, like ~/bin:

mkdir -p ~/bin
mv hello ~/bin/
hello               # works from any folder
which hello         # /home/user/bin/hello
Do not name a script like an existing command A script called test or ls can be skipped or can break things. The first match in PATH wins.

Positional parameters: give input to a script

Words you type after the script name become positional parameters.

NameHolds
$0The script name as you typed it
$1First word after the script
$2Second word
${10}Tenth word. Needs braces from 10 up.
$#How many words were given
"$@"All the words, each kept separate
#!/usr/bin/bash
echo "Script: $0"
echo "First: $1"
echo "Tenth (wrong): $10"      # prints $1 then the letter 0
echo "Tenth (right): ${10}"
./params.sh 1st 2nd 3rd 4th 5th 6th 7th 8th 9th 10th
Script: ./params.sh
First: 1st
Tenth (wrong): 1st0
Tenth (right): 10th

The set -- command can replace all parameters at once, for example set -- "$1" "$2" "$4" "$3" swaps the 3rd and 4th. Any parameter you do not list is dropped.

For real options like -v or -o yaml, use getopts with a case block.

REAL WORLD

A reusable user-creation helper. ./adduser.sh priya developers uses $1 as the user name and $2 as the group. One script, any number of users. If $# is not 2, the script prints a usage message and stops.

Quoting special characters

Some characters have special power in Bash: # $ * ? & ; and space. Quotes remove that power when you want the plain character.

echo # not a comment            # prints an empty line, # starts a comment
echo \# not a comment           # # not a comment
echo '# not a comment #'        # # not a comment #

var=$(hostname -s)
echo "host is ${var}"           # host is host
echo "Today: $(date +%F)"       # command runs inside double quotes
echo 'Today: $(date +%F)'       # literal text, nothing runs
echo "\"Hello, world\""         # "Hello, world"
Memory trick Single quote = "freeze everything". Double quote = "freeze file patterns like *, but still fill in $ values".

Script output: STDOUT and STDERR

Every program has three data channels:

SymbolMeaningExample
>Send STDOUT to a file, overwritels > list.txt
>>Send STDOUT to a file, appenddate >> log.txt
2>Send errors to a filecmd 2> err.log
>&2Send this echo to the error channelecho "bad" >&2
> f 2>&1Both channels into one filecmd > all.log 2>&1
> /dev/nullThrow output awaycmd > /dev/null 2>&1
#!/usr/bin/bash
echo "Hello, world"
echo "ERROR: Houston, we have a problem." >&2
hello 2> hello.log      # screen shows Hello, world. File holds the error.
REAL WORLD

Clean logs for support. A nightly backup writes good messages to backup.log and errors to backup.err. When something fails, you open only the small error file instead of scanning 10,000 lines. Also, echo "value is $x" is the simplest debugging tool: print values to see what the script is doing.

1.5 Running Loops and Conditional Commands

forwhileuntilif / elif / elseexit code$?test [[ ]]

The for loop: do it for each item

for VARIABLE in LIST; do
    command using $VARIABLE
done

Bash takes one item from LIST at a time, puts it in VARIABLE, and runs the body. It stops after the last item.

Ways to build the list

for HOST in host1 host2 host3; do echo $HOST; done      # typed words
for HOST in host{1,2,3};  do echo $HOST; done           # brace list
for HOST in host{1..3};   do echo $HOST; done           # brace range
for N in $(seq 2 2 10);   do echo $N;    done           # 2 4 6 8 10
for F in *.log;           do echo $F;    done           # every .log file
for U in $(cut -d: -f1 /etc/passwd | head -3); do echo $U; done  # command output
# print every kernel package with install date
for PACKAGE in $(rpm -qa | grep kernel); do
  echo "$PACKAGE installed on $(date -d @$(rpm -q --qf '%{INSTALLTIME}\n' $PACKAGE))"
done
REAL WORLD

Patch 50 servers. Instead of logging in 50 times, loop: for h in web{01..50}; do ssh admin@$h "sudo dnf update -y"; done. A task that took a day takes minutes.

Exit codes: how success is reported

Every command ends with a number from 0 to 255 called the exit code.

CodeMeaning
0Success
1-255Some kind of failure
ls /etc; echo $?          # 0
ls /nothing; echo $?      # 2 (or another non-zero)
/bin/true;  echo $?       # always 0
/bin/false; echo $?       # always 1
  • $? holds the exit code of the last command. The next command replaces it.
  • exit 0 ends the script with success. exit 3 ends it with error code 3.
  • exit with no number returns the last command's code.
  • A script that reaches its end returns 0 (or the last command's code).
  • errno -l lists standard error numbers.
REAL WORLD

Monitoring tools run on exit codes. A monitoring system runs your check script. If the script exits 0 the dashboard stays green. If it exits 2 the dashboard turns red and pages you. Good scripts always exit with the right number.

Testing conditions

Use [[ ... ]] (or the older test). It gives exit code 0 for true and 1 for false.

Spaces are required [[ $x -eq 1 ]] works. [[$x -eq 1]] fails. The bracket is like a command and needs spaces around everything.

Number tests

TestMeans
-eqequal
-nenot equal
-gtgreater than
-gegreater or equal
-ltless than
-leless or equal

Text and file tests

TestMeans
== or =text equal
!=text different
-z "$s"text is empty
-n "$s"text is not empty
-f pathis a regular file
-d pathis a directory
-r pathyou can read it
[[ 8 -gt 2 ]];   echo $?      # 0 true
[[ 2 -lt 2 ]];   echo $?      # 1 false
[[ abc == abc ]]; echo $?     # 0 true
STRING=''; [[ -z "$STRING" ]]; echo $?   # 0, it is empty
Use -eq for numbers, == for text Mixing them gives wrong answers. Also quote your variables: [[ -z "$name" ]].

if / elif / else: make decisions

if [[ condition ]]; then
    commands
elif [[ other condition ]]; then
    commands
else
    commands
fi
# start psacct only if it is not running
systemctl is-active psacct > /dev/null 2>&1
if [[ $? -ne 0 ]]; then
    sudo systemctl start psacct
fi

# shorter: use the command directly as the test
if ! systemctl is-active --quiet psacct; then
    sudo systemctl start psacct
fi

# three-way choice
systemctl is-active mariadb    > /dev/null 2>&1; MARIA=$?
systemctl is-active postgresql > /dev/null 2>&1; PG=$?
if   [[ $MARIA -eq 0 ]]; then mysql
elif [[ $PG    -eq 0 ]]; then psql
else                          sqlite3
fi
REAL WORLD

Disk space alarm. A script reads disk use as a number. if [[ $USE -ge 90 ]]; then echo "Disk almost full" >&2; exit 2; elif [[ $USE -ge 75 ]]; then echo "Warning"; else echo "OK"; fi. Three levels, one script.

while and until: repeat while a test is true or false

LoopKeeps running while the test is...Think
whileTRUE (exit code 0)"as long as"
untilFALSE (non-zero)"until it becomes true"

Both check the test before the first round, so the body may run zero times.

x=1
while [[ $x -le 5 ]]; do
    echo "x is $x"
    x=$((x + 1))         # without this the loop never ends!
done
echo "Finished"

x=5
until [[ $x -lt 1 ]]; do
    echo "x is $x"
    x=$((x - 1))
done
REAL WORLD

Wait for a server to come back after reboot. until ping -c1 -W1 server1 > /dev/null 2>&1; do sleep 5; done; echo "server1 is up". The script waits and then continues the moment the server answers.

Infinite loop warning If the test never changes, the loop never ends. Press Ctrl+C to stop it.

#!/usr/bin/bash

for SERVER in servera serverb; do

1.8 Summary

  • Shell variable lives in one shell. export turns it into an environment variable that child programs can read.
  • Put permanent settings in ~/.bashrc (user) or /etc/profile.d/*.sh (everyone). Use source to load without logging out.
  • A script starts with #!/usr/bin/bash, needs chmod +x, and gets input through $1 $2 ...
  • Quotes decide what Bash expands: '...' nothing, "..." variables and commands.
  • Send normal output to STDOUT and errors to STDERR (>&2).
  • for, while, until repeat work. if / elif / else make choices based on exit codes (0 = success).

Extra Must-Know Topics

These topics are used in almost every real script. Learn them now.

1. Check that the user gave the right input

#!/usr/bin/bash
if [[ $# -ne 2 ]]; then
    echo "Usage: $0 <user> <group>" >&2
    exit 1
fi
echo "Creating $1 in group $2"

2. AND, OR, and chaining

SymbolMeaningExample
;run next, alwayscd /tmp; ls
&&run next only if previous succeededmkdir d && cd d
||run next only if previous failedping -c1 h || echo down
&& in [[ ]]both tests true[[ -f f && -r f ]]
|| in [[ ]]either test true[[ $a -eq 1 || $b -eq 1 ]]

3. case: tidy multiple choices

case "$1" in
    start)   echo "Starting..."  ;;
    stop)    echo "Stopping..."  ;;
    restart) echo "Restarting..." ;;
    *)       echo "Usage: $0 {start|stop|restart}" >&2; exit 1 ;;
esac

Use case when you compare one variable against many fixed values. It is easier to read than a long elif chain.

4. Ask the user a question

read -p "Enter your name: " name
echo "Hello, $name"

5. Read a file line by line

while read -r line; do
    echo "Line: $line"
done < /etc/hosts
SSH inside a while-read loop Use ssh -n there. Plain ssh eats the rest of the file and the loop stops after the first line.

6. Loop controls

for ((i=1; i<=5; i++)); do
    [[ $i -eq 2 ]] && continue     # skip this round
    [[ $i -eq 4 ]] && break        # leave the loop
    echo $i                         # prints 1 and 3
done

7. Loop over an array safely

servers=(web01 web02 db01)
for s in "${servers[@]}"; do
    echo "Checking $s"
done

8. Functions: name a block of code

log() { echo "[$(date +%T)] $*"; }
log "Backup started"
log "Backup finished"

9. Safer scripts

#!/usr/bin/bash
set -euo pipefail
OptionEffect
-estop at the first failing command
-uerror if you use an unset variable (catches typos)
-o pipefaila pipeline fails if any part fails
REAL WORLD

The famous cleanup bug. rm -rf "$DIR/"* with DIR accidentally empty becomes rm -rf /*. With set -u the script stops because DIR is unset. One line saves your server.

10. Debug your script

bash -x script.sh      # show every command as it runs
bash -n script.sh      # check syntax only, do not run
shellcheck script.sh   # finds common mistakes (install from EPEL)

11. Useful variable tricks

echo "${name:-guest}"      # use "guest" if name is empty
echo "${#name}"            # length of the text
readonly PI=3.14           # cannot be changed later
today=$(date +%F)          # save command output in a variable

12. Where script output files should go

TMP=$(mktemp)              # safe unique temporary file
trap 'rm -f "$TMP"' EXIT   # delete it when the script ends

13. Run scripts automatically

Use cron (crontab -e) or a systemd timer to run a script on a schedule. A cron line like 0 2 * * * /home/student/bin/backup.sh runs it every day at 2 AM. Always use the full path in cron, because cron has a very small PATH.

Real-World Scenarios

SCENARIO 1

Create 20 new employee accounts

HR sends a text file newusers.txt with one user name per line.

#!/usr/bin/bash
while read -r user; do
    if id "$user" > /dev/null 2>&1; then
        echo "$user already exists, skipping"
    else
        sudo useradd -m "$user" && echo "Created $user"
    fi
done < newusers.txt

Uses: while read loop, if/else, exit code, redirect to /dev/null.

SCENARIO 2

Morning health report of many servers

#!/usr/bin/bash
REPORT=~/report-$(date +%F).txt
for h in web01 web02 db01; do
    {
      echo "===== $h ====="
      ssh -n "$h" "uptime; df -h /; free -m"
    } >> "$REPORT" 2>&1
done
echo "Report saved in $REPORT"

Uses: for loop, variables, command substitution, grouped redirect.

SCENARIO 3

Safe backup with a check

#!/usr/bin/bash
set -u
SRC=/etc
DEST=/backup
if [[ ! -d "$DEST" ]]; then
    echo "Backup folder missing" >&2
    exit 1
fi
tar -czf "$DEST/etc-$(date +%F).tar.gz" "$SRC" 2> /tmp/backup.err
if [[ $? -eq 0 ]]; then
    echo "Backup OK"
else
    echo "Backup FAILED, see /tmp/backup.err" >&2
    exit 2
fi

Uses: file test -d, STDERR, exit codes, date in file names.

SCENARIO 4

Restart a service only if it is down

#!/usr/bin/bash
SERVICE=${1:-httpd}
if systemctl is-active --quiet "$SERVICE"; then
    echo "$SERVICE is running"
else
    echo "$SERVICE is down, restarting" >&2
    sudo systemctl restart "$SERVICE"
fi

Uses: positional parameter with default value, if/else, exit code of a command.

SCENARIO 5

Rename 100 photos

n=1
for f in *.jpg; do
    mv -- "$f" "holiday-$(printf '%03d' $n).jpg"
    n=$((n + 1))
done

Uses: file glob in for loop, arithmetic, command substitution.
