Accessing Network-Attached Storage

NFS shares a folder from one Linux machine to others. autofs mounts that folder only when someone opens it. Learn the client side step by step, with commands, files to edit and output.

1What is NFS?

Why? Files stay in one place (the server) and many computers can use them. Nobody needs to copy files around.
WordFull formSimple meaning
NFSNetwork File Systema way to use a folder of another Linux machine as if it were on your own disk
NASNetwork-Attached Storagestorage that sits on the network and is shared with many computers
exportthe server shares a folder. It is listed in /etc/exports
mountthe client attaches the shared folder to a local empty folder (the mount point)
showmount -eshow mount, exportsasks a server: which folders do you share?
exportfsexport file systemstells the NFS server to read /etc/exports and start sharing
What to learnLearn the client side well: showmount, mount, /etc/fstab and autofs. The server side is needed only to build your own practice lab. It is in the next section.

2Practice server setup (lab only)

Why? The client needs something to connect to. These steps build a small NFS server so you can practise.
Goal: Make the server machine (IP 192.168.118.129) share the folder /nfs-shared. Do these steps on the server.

Install the service and open the firewall

# on the SERVER
$ sudo dnf install -y nfs-utils
$ sudo systemctl enable --now nfs-server
Created symlink '/etc/systemd/system/multi-user.target.wants/nfs-server.service' → '/usr/lib/systemd/system/nfs-server.service'.
$ sudo firewall-cmd --permanent --add-service=nfs
success
$ sudo firewall-cmd --permanent --add-service=mountd
success
$ sudo firewall-cmd --permanent --add-service=rpc-bind
success
$ sudo firewall-cmd --reload
success

The package nfs-utils holds all NFS tools. nfs-server is the service. The firewall must allow nfs, mountd and rpc-bind. The last two are used by showmount.

Make the folder

$ sudo mkdir -p /nfs-shared
$ sudo chmod 777 /nfs-shared

Edit /etc/exports

Open the file with sudo vim /etc/exports and add one line at the end:

/etc/exports
/nfs-shared   *(rw,sync,no_root_squash)
PartMeaning
*any client. For safety you can write one IP (192.168.118.130) or a network (192.168.118.0/24)
rwclients can read and write
syncserver writes to disk before it says "done". Safer
no_root_squashthe root user of the client keeps root power on the share. The default root_squash turns client root into a harmless user (nobody). Use no_root_squash only for practice
$ sudo systemctl restart nfs-server
$ sudo exportfs -av
exporting *:/nfs-shared
$ showmount -e localhost
Export list for localhost:
/nfs-shared *
Option of exportfsMeaning
-aall folders listed in /etc/exports
-rre-read /etc/exports (use this after you change the file)
-vverbose: print what it does
Practice onlychmod 777 (everyone can do everything) and no_root_squash are fine for a lab. On a real server use correct owners, a group, and root_squash.

3Client: mount an NFS share by hand

Why? Before you automate anything, you must prove that the share works. Hand mounting is the first test.
Goal: On the client, see what the server shares, mount /nfs-shared on the folder /nfs-access, and use it.
  1. Install the tools: dnf install -y nfs-utils
  2. Ask the server what it shares: showmount -e 192.168.118.129
  3. Make an empty folder for the mount: mkdir -p /nfs-access
  4. Mount it: mount 192.168.118.129:/nfs-shared /nfs-access
  5. Check with df -hT and write a test file
# on the CLIENT
$ sudo dnf install -y nfs-utils
$ showmount -e 192.168.118.129
Export list for 192.168.118.129:
/nfs-shared *
$ sudo mkdir -p /nfs-access
$ sudo mount 192.168.118.129:/nfs-shared /nfs-access
$ df -hT /nfs-access
Filesystem                  Type  Size  Used Avail Use% Mounted on
192.168.118.129:/nfs-shared nfs4   17G  1.8G   16G  10% /nfs-access
$ sudo touch /nfs-access/test.txt
$ ls -l /nfs-access
total 0
-rw-r--r--. 1 root root 0 Nov 23 10:12 test.txt
PartMeaning
192.168.118.129:/nfs-sharedserver:folder. The IP (or host name), a colon, then the shared folder on the server
/nfs-accessthe local empty folder (mount point)
nfs4 in dfthe type shown. The client picks NFS version 4 automatically

Now check on the server. The file is really there, because the folder is shared:

# on the SERVER
$ ls -l /nfs-shared
total 0
-rw-r--r--. 1 root root 0 Nov 23 10:12 test.txt
Temporary onlyA normal mount command lasts until the next reboot (or umount /nfs-access). To keep it, use /etc/fstab (next section) or autofs (after that).

4Client: permanent mount with /etc/fstab

Why? fstab tells Linux what to mount at every boot. One extra line keeps the NFS share always available.
Goal: Make the mount of /nfs-shared on /nfs-access come back after every reboot.

Unmount first, so that the test below is a real test. Then open sudo vim /etc/fstab and add one line at the end:

$ sudo umount /nfs-access
/etc/fstab (add the green line at the end)
192.168.118.129:/nfs-shared   /nfs-access   nfs   defaults   0 0
$ sudo systemctl daemon-reload
$ sudo mount -a
$ df -hT /nfs-access
Filesystem                  Type  Size  Used Avail Use% Mounted on
192.168.118.129:/nfs-shared nfs4   17G  1.8G   16G  10% /nfs-access
$ sudo reboot
# ...after the reboot...
$ df -hT /nfs-access
Filesystem                  Type  Size  Used Avail Use% Mounted on
192.168.118.129:/nfs-shared nfs4   17G  1.8G   16G  10% /nfs-access
Why daemon-reload and mount -a?systemctl daemon-reload makes systemd read the changed fstab. mount -a = mount all lines of fstab. If it prints nothing, the line is correct. A wrong line can stop the next boot, so always test first.
If the server is down at bootThe client waits for the server and boot becomes slow. Use the options defaults,_netdev,nofail in the line so that boot continues. (_netdev = "this is a network device, mount it after the network is up".)

5What is autofs?

Why? A fstab mount is always on, even when nobody uses it. autofs mounts a share only when it is needed, and cleans up afterwards.
WordMeaning
autofsAutomatic File System. The service (and package) of the automounter
automountera helper that mounts on demand when you open a folder, and unmounts when it is not used for a while (default 5 minutes)
master mapsays: "under this folder, use that map file". Files: /etc/auto.master and /etc/auto.master.d/*.autofs
map filesays: "this name means this NFS share". Example: /etc/auto.rhome
indirect mapmany shares appear inside one folder, such as /rhome/remoteuser1. Most common
direct mapa share is mounted at its own full path, such as /mnt/docs
/etc/fstabautofs
When mountedat boot, alwaysonly when someone opens the folder
When unmountednever (until umount)after the idle time
Needs root to useno, once mountedno. Normal users just open the folder
Best forone share that is always neededmany shares, home directories

Direct map (extra)

The master line uses the special folder /-. The map file holds the full path:

/etc/auto.master.d/docs.autofs
/-   /etc/auto.direct
/etc/auto.direct
/mnt/docs   -fstype=nfs4,rw   192.168.118.129:/nfs-shared

6Practice server: share the home folders

Why? autofs needs real shares on a server. Here the server shares four folders, one for each user.
Goal: On the server, share four home folders: /rhome/remoteuser1 to /rhome/remoteuser4. The client will mount them with autofs.
# on the SERVER
$ sudo mkdir -p /rhome/remoteuser{1..4}
$ sudo chmod -R 777 /rhome
$ ls -ld /rhome /rhome/remoteuser*
drwxrwxrwx. 6 root root 96 Nov 23 10:30 /rhome
drwxrwxrwx. 2 root root  6 Nov 23 10:30 /rhome/remoteuser1
drwxrwxrwx. 2 root root  6 Nov 23 10:30 /rhome/remoteuser2
drwxrwxrwx. 2 root root  6 Nov 23 10:30 /rhome/remoteuser3
drwxrwxrwx. 2 root root  6 Nov 23 10:30 /rhome/remoteuser4
What is {1..4}?The shell expands remoteuser{1..4} to remoteuser1 remoteuser2 remoteuser3 remoteuser4. One command makes four folders.

Open sudo vim /etc/exports and add four lines at the end. Keep the first line from before:

/etc/exports
/nfs-shared          *(rw,sync,no_root_squash)
/rhome/remoteuser1   *(rw,sync,no_root_squash)
/rhome/remoteuser2   *(rw,sync,no_root_squash)
/rhome/remoteuser3   *(rw,sync,no_root_squash)
/rhome/remoteuser4   *(rw,sync,no_root_squash)
$ sudo exportfs -rv
exporting *:/rhome/remoteuser4
exporting *:/rhome/remoteuser3
exporting *:/rhome/remoteuser2
exporting *:/rhome/remoteuser1
exporting *:/nfs-shared
$ showmount -e localhost
Export list for localhost:
/nfs-shared        *
/rhome/remoteuser1 *
/rhome/remoteuser2 *
/rhome/remoteuser3 *
/rhome/remoteuser4 *

7Client: autofs with an indirect map

Why? This is the main skill of the chapter: a share appears when you open its folder, with no fstab line and no manual mount.
Goal: On the client, make /rhome/remoteuser1 to /rhome/remoteuser4 appear automatically from the server.
  1. Install and start autofs: dnf install -y autofs nfs-utils, then systemctl enable --now autofs
  2. Test one share by hand (a good habit before autofs)
  3. Create the master map file /etc/auto.master.d/rhome.autofs
  4. Create the map file /etc/auto.rhome
  5. Restart autofs, then open the folders to test
# on the CLIENT
$ sudo dnf install -y autofs nfs-utils
$ sudo systemctl enable --now autofs
Created symlink '/etc/systemd/system/multi-user.target.wants/autofs.service' → '/usr/lib/systemd/system/autofs.service'.
$ sudo mkdir /testautofs
$ sudo mount 192.168.118.129:/rhome/remoteuser1 /testautofs
$ ls -ld /testautofs
drwxrwxrwx. 2 root root 6 Nov 23 10:30 /testautofs
$ sudo umount /testautofs

Master map file

Make the file with sudo vim /etc/auto.master.d/rhome.autofs. It must end with .autofs. Add one line:

/etc/auto.master.d/rhome.autofs
/rhome   /etc/auto.rhome

Map file

Make the file with sudo vim /etc/auto.rhome. Add four lines:

/etc/auto.rhome
remoteuser1   -fstype=nfs4,rw   192.168.118.129:/rhome/remoteuser1
remoteuser2   -fstype=nfs4,rw   192.168.118.129:/rhome/remoteuser2
remoteuser3   -fstype=nfs4,rw   192.168.118.129:/rhome/remoteuser3
remoteuser4   -fstype=nfs4,rw   192.168.118.129:/rhome/remoteuser4
Map line partMeaning
remoteuser1the key: the folder name that appears under /rhome
-fstype=nfs4,rwmount options: NFS version 4, read and write (the dash - at the start is needed)
192.168.118.129:/rhome/remoteuser1the share: server:folder

Do not make /rhome on the client yourself. autofs creates it. Restart autofs and test:

$ sudo systemctl restart autofs
$ ls /rhome
# (nothing is listed yet. This is normal)
$ cd /rhome/remoteuser1
$ pwd
/rhome/remoteuser1
$ df -hT /rhome/remoteuser1
Filesystem                         Type  Size  Used Avail Use% Mounted on
192.168.118.129:/rhome/remoteuser1 nfs4   17G  1.8G   16G  10% /rhome/remoteuser1
$ cd /rhome/remoteuser2
$ df -hT | grep rhome
192.168.118.129:/rhome/remoteuser1 nfs4   17G  1.8G   16G  10% /rhome/remoteuser1
192.168.118.129:/rhome/remoteuser2 nfs4   17G  1.8G   16G  10% /rhome/remoteuser2
Why was ls /rhome empty?autofs mounts a folder only when you open it. Before that, the name does not show up. After about 5 idle minutes the share is unmounted again and disappears from df. That is the automounter at work.
Other way to write the same thingYou can also put the master line into /etc/auto.master and the map lines into an existing file such as /etc/auto.misc. It works the same. Separate files (as above) are cleaner and safer to change.

8Wildcard map: one line for all users

Why? One wildcard line replaces many map lines, so adding a user needs fewer changes.

Four near-identical lines are boring. A wildcard map needs only one line, and new users need no change in the map file.

/etc/auto.rhome (replace the four lines with this one)
*   -fstype=nfs4,rw   192.168.118.129:/rhome/&
$ sudo systemctl restart autofs
$ cd /rhome/remoteuser4
$ df -hT /rhome/remoteuser4
Filesystem                         Type  Size  Used Avail Use% Mounted on
192.168.118.129:/rhome/remoteuser4 nfs4   17G  1.8G   16G  10% /rhome/remoteuser4

Add one more user later (remoteuser5)

  1. Server: make the folder first: mkdir /rhome/remoteuser5 and chmod 777 /rhome/remoteuser5
  2. Server: add the line /rhome/remoteuser5 *(rw,sync,no_root_squash) to /etc/exports, then exportfs -rv
  3. Client: with the wildcard map you change nothing. (With the four-line map, add one more line remoteuser5 ... to /etc/auto.rhome.)
  4. Client: create the user (next section) and test with su - remoteuser5

9Users with NFS home directories

Why? Central home directories let a user find the same files on every machine.
Goal: Make users whose home directory lives on the NFS server and is mounted by autofs when they log in.
# on the CLIENT
$ sudo useradd --no-create-home -d /rhome/remoteuser1 remoteuser1
$ sudo useradd --no-create-home -d /rhome/remoteuser2 remoteuser2
$ sudo su - remoteuser1
[remoteuser1@client ~]$ pwd
/rhome/remoteuser1
[remoteuser1@client ~]$ df -hT .
Filesystem                         Type  Size  Used Avail Use% Mounted on
192.168.118.129:/rhome/remoteuser1 nfs4   17G  1.8G   16G  10% /rhome/remoteuser1
[remoteuser1@client ~]$ touch myfile
[remoteuser1@client ~]$ exit
OptionMeaning
-d /rhome/remoteuser1set the home directory path
--no-create-homedo not make the folder on the client. The folder comes from the server through autofs

The file myfile is stored on the server in /rhome/remoteuser1. Log in as remoteuser1 on any client that has the same map and the same home comes along.

Same user ID everywhereNFS remembers files by the user number (UID), not by name. In real life make the user with the same UID on the server and on every client (check with id remoteuser1), or the owner looks wrong.
Login blocked by SELinux?If a user cannot use an NFS home directory, check getsebool use_nfs_home_dirs. To allow it: sudo setsebool -P use_nfs_home_dirs on. (SELinux = Security-Enhanced Linux.)

10Real lab: shared folders for three teams

Why? A real job example: each team gets its own shared folder on a central server, and autofs mounts them on demand.
Goal: Real lab: the machine serverb shares /shares/management, /shares/production and /shares/operation. On servera, mount them below /remote with autofs. The three team users are manager1, dbuser1 and contractor1.

1. Install autofs and test the share by hand

# on servera, as root
$ sudo dnf install -y autofs
Complete!
$ sudo mount -t nfs serverb:/shares /mnt
$ ls -l /mnt
total 0
drwxrws---. 2 manager1    managers   25 Jul 14 20:23 management
drwxrws---. 2 contractor1 operators  25 Jul 14 20:23 operation
drwxrws---. 2 dbuser1     production 25 Jul 14 20:23 production
$ sudo umount /mnt

2. Master map and map file

/etc/auto.master.d/shares.autofs
/remote   /etc/auto.shares
/etc/auto.shares
*   -rw,sync,fstype=nfs4   serverb:/shares/&
sync optionsync means writes go to the server at once (synchronous). Here the lab asks for it, so it is in the options.

3. Start autofs and check

$ sudo systemctl enable --now autofs
$ mount | grep nfs
rpc_pipefs on /var/lib/nfs/rpc_pipefs type rpc_pipefs (rw,relatime)
# (no share is mounted yet, because nobody opened a folder)

4. Test as each user

$ su - manager1
$ ls -l /remote/management
total 4
-rw-r--r--. 1 manager1 managers 58 Jul 14 20:23 Welcome.txt
$ cat /remote/management/Welcome.txt
### Welcome to Management Folder on SERVERB ###
$ echo TEST1 > /remote/management/test.txt
$ exit
# repeat for dbuser1 with /remote/production and contractor1 with /remote/operation
$ mount | grep remote
serverb:/shares/management on /remote/management type nfs4 (rw,relatime,sync,vers=4.2,...)
serverb:/shares/production on /remote/production type nfs4 (rw,relatime,sync,vers=4.2,...)
serverb:/shares/operation on /remote/operation type nfs4 (rw,relatime,sync,vers=4.2,...)
What you learned hereThe group permissions on the server decide who can use each folder. autofs only brings the folder to the client. Each team opens only its own folder.

11Interview questions

Why? Interviewers ask short theory questions about NFS and autofs. Click a question, answer in your own words, then check.
What is NFS?
NFS (Network File System) lets a client mount a folder of a server over the network and use it like a local folder. It is the standard file sharing method between Linux and Unix systems.
Which file lists the shared folders on the server?
/etc/exports. After editing it run exportfs -rv.
How does a client see what a server shares?
showmount -e SERVER_IP.
How do you mount an NFS share?
mount SERVER_IP:/folder /mountpoint. For a permanent mount add SERVER_IP:/folder /mountpoint nfs defaults 0 0 to /etc/fstab.
What is autofs and why use it?
autofs is the automounter. It mounts a share when someone opens the folder and unmounts it after it is idle (default 5 minutes). It saves resources and avoids boot problems when a server is down.
Direct map or indirect map?
Indirect: shares appear inside one folder (/rhome/user1). Direct: a share has its own full path (/mnt/docs), master line /- /etc/auto.direct.
What do * and & mean in an autofs map?
* matches any name that a user opens. & repeats that same name. One line * -fstype=nfs4,rw server:/rhome/& serves all users.
What is root_squash?
It turns the client root user into a harmless user (nobody) on the server. It is the safe default. no_root_squash switches it off, so client root keeps root power.
Which firewall services does an NFS server need?
nfs (TCP port 2049 for NFSv4), plus mountd and rpc-bind for tools like showmount.
umount says "target is busy". What now?
Something uses the mount. Leave the folder with cd (your own shell may be in it), close programs, then run umount again. fuser -m /mountpoint shows who uses it.
NFS or Samba?
NFS is for Linux and Unix clients. Samba (SMB protocol) is mainly for Windows clients.

12Exam steps and common errors

Why? The same order every time means you do not forget a step.

Same order every time (client side)

  1. dnf install -y nfs-utils autofs
  2. showmount -e SERVER to see the exports. Mount once by hand to test.
  3. fstab way: make the folder, add the line, systemctl daemon-reload, mount -a, df -hT.
  4. autofs way: master map file in /etc/auto.master.d/NAME.autofs, map file, systemctl enable --now autofs.
  5. Open the folder, then check with df -hT or mount | grep nfs.
  6. Reboot and check once more.
