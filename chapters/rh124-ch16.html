🛎️ Controlling Services and Daemons

Web servers, SSH, firewalls and schedulers all run in the background. In this chapter you learn how to see, start, stop, auto-start and block them with systemctl. This is a core RHCSA topic.

1. Daemon vs Service

🧩 Daemon
The background process itself, running without a user at the keyboard. Example: sshd. Names often end in d.
🎛️ Service
How systemd manages that daemon: start, stop, restart, auto-start. Example: sshd.service.

On RHEL the SSH service is sshd. The name ssh is used on Ubuntu and Debian. Always use sshd in RHCSA.
⚡ Oneshot service: a service that runs once, changes something (for example applies a setting at boot) and exits. It shows active (exited) and there is no process to find with ps. That is normal, not a fault.

2. systemd: The Boss of Services

systemd is PID 1, the first process. It boots the system, starts services in the right order, restarts crashed ones and collects logs. Each thing it manages is called a unit, described by a small text file.

Why systemd is better than the old init

⚡ Parallel start
Starts many services at the same time, so boot is faster.
🎯 On-demand start
Starts a daemon only when someone needs it.
🔗 Dependencies
A service that needs the network waits until the network is up.
📦 cgroups tracking
Keeps all processes of a service together, so stop removes every child too.
Unit typeWhat it managesExample
.serviceA daemon or task. The default type, so sshd means sshd.servicesshd.service
.socketStarts a service only when a connection arrives. Must be definedcockpit.socket
.pathStarts a service when a file or folder changes. Must be definedcups.path
.timerStarts a service on a schedule (like cron)dnf-makecache.timer

$ systemctl -t help                 # list every unit type
$ systemctl list-units --type=service              # services loaded now
$ systemctl list-units --type=service --state=running
$ systemctl list-unit-files --type=service         # all installed, with enabled/disabled
$ systemctl list-dependencies sshd                 # what sshd needs to start
$ systemctl list-sockets ; systemctl list-timers   # sockets and timers

3. Reading systemctl status

$ systemctl status sshd
● sshd.service - OpenSSH server daemon                          # name and description
     Loaded: loaded (/usr/lib/systemd/system/sshd.service; enabled; preset: enabled)
     Active: active (running) since Sun 2026-11-01 09:10:11 IST; 2h ago
   Main PID: 850 (sshd)                                          # the daemon's PID
      Tasks: 1 (limit: 11200)
     Memory: 5.2M
     CGroup: /system.slice/sshd.service
             └─850 "sshd: /usr/sbin/sshd -D [listener]"
Nov 01 09:10:11 server sshd[850]: Server listening on 0.0.0.0 port 22.   # latest log lines

The "Loaded" line: your note, made precise

enabled (first word)
This service will start at boot on this machine. Someone ran systemctl enable, or the install did.
preset: enabled (older RHEL: vendor preset)
The default policy from the distribution (RHEL) for this service. It is only advice. Your own setting is the first word.

So enabled; preset: disabled means: RHEL's default is off, but an admin turned it on. Other values: disabled, static (cannot be enabled, started only by another unit), masked.

The "Active" line

active (running)Daemon is running now
active (exited)A one-time task ran and finished OK
active (waiting)Started, waiting for an event
inactive (dead)Not running
failedCrashed or could not start

Quick checks (good for scripts)

$ systemctl is-active sshd     # active
$ systemctl is-enabled sshd    # enabled
$ systemctl is-failed sshd     # active  (says "failed" only when failed)
$ systemctl --failed           # list all failed units

$ systemctl show sshd -p MainPID,ActiveState,UnitFileState

Who may do what? Any user can view (status, list-units, is-active). Changing a service (start, stop, enable, mask) needs root or sudo. In status, press q to leave the pager.

4. Controlling Services with systemctl

Now vs at boot: the most important idea

Running now?Starts at boot?
startYesNo change
stopNoNo change
enableNo changeYes
disableNo changeNo
enable --nowYesYes
disable --nowNoNo
CommandWhat it does
systemctl start sshdStart now
systemctl stop sshdStop now
systemctl restart sshdStop, then start. Brief downtime, connections drop
systemctl reload sshdRe-read the config file without stopping. Use after editing the config
systemctl reload-or-restart sshdReload if the service supports it, else restart
systemctl try-restart sshdRestart only if it is already running

🏢 Scenario: install and run a web server

$ sudo dnf install -y httpd
$ sudo systemctl enable --now httpd
Created symlink /etc/systemd/system/multi-user.target.wants/httpd.service → /usr/lib/systemd/system/httpd.service.
$ systemctl is-active httpd ; systemctl is-enabled httpd
active
enabled
$ sudo vim /etc/httpd/conf/httpd.conf    # change a setting
$ sudo apachectl configtest              # check for typos first
Syntax OK
$ sudo systemctl reload httpd            # apply it with no downtime
Enable just creates a symlink inside /etc/systemd/system/multi-user.target.wants/. That link is how systemd knows to start the service at boot.

Proof: restart changes the PID, reload does not

$ systemctl status sshd | grep "Main PID"
   Main PID: 784 (sshd)
$ sudo systemctl restart sshd
$ systemctl status sshd | grep "Main PID"
   Main PID: 1193 (sshd)            # NEW process
$ sudo systemctl reload sshd
$ systemctl status sshd | grep "Main PID"
   Main PID: 1193 (sshd)            # same PID. Reload sends SIGHUP (ExecReload=/bin/kill -HUP $MAINPID)
$ sudo sshd -t && sudo systemctl reload sshd     # safe habit: test the config first, then reload
$ sudo systemctl try-restart chronyd              # restart only if it is already running
$ sudo systemctl reload-or-restart chronyd        # reload if supported, else restart
Two different "configs": a service config (/etc/ssh/sshd_config) needs reload or restart. A unit file (/etc/systemd/system/x.service) needs daemon-reload first.

Dependencies and on-demand start


🏢 Scenario: you stopped CUPS (printing) but it came back
$ sudo systemctl stop cups.service
Warning: Stopping cups.service, but it can still be activated by:
  cups.path
  cups.socket
A print job lands in the spool folder (.path) or a client connects (.socket), and systemd starts the service again. To stop printing completely, stop and disable all three:
$ sudo systemctl disable --now cups.service cups.socket cups.path

5. Mask and Unmask: the Hard Block


disable only stops auto-start. Someone can still run start by hand. mask links the unit to /dev/null, so it cannot be started at all, not even by another service. Use it for something that must never run (for example, to stop firewalld clashing with another firewall tool).


$ sudo systemctl mask sshd
Created symlink /etc/systemd/system/sshd.service → /dev/null.
$ sudo systemctl restart sshd
Failed to restart sshd.service: Unit sshd.service is masked.
$ systemctl is-enabled sshd
masked
$ sudo systemctl unmask sshd
Removed "/etc/systemd/system/sshd.service".
$ sudo systemctl start sshd                  # works again


Never mask sshd on a remote server you are connected to, or you may lock yourself out after the next reboot. Practise only on a lab VM.

🏢 Scenario: two mail servers conflict
Postfix and sendmail must not both run. Run sudo systemctl mask sendmail. Now nobody can start sendmail by mistake. Check: systemctl list-unit-files | grep sendmail shows masked.



6. Create Your Own Service


🏢 Scenario: run your monitoring script as a service
You have a script /usr/local/bin/monitor.sh and want it to start at boot and restart if it crashes.


📍 Where to Add What
Create the file /etc/systemd/system/monitor.service (as root) with exactly these lines:

[Unit]
Description=My monitoring script
After=network.target

[Service]
ExecStart=/usr/local/bin/monitor.sh
Restart=on-failure
User=nobody

[Install]
WantedBy=multi-user.target


SectionMeaning
[Unit]Description and ordering. After= means start later than that unit
[Service]ExecStart = command to run. Restart = auto-restart rule. User = run as this user, not root
[Install]WantedBy=multi-user.target = what enable hooks into


$ sudo chmod +x /usr/local/bin/monitor.sh
$ sudo systemctl daemon-reload           # REQUIRED: tell systemd about the new/changed file
$ sudo systemctl enable --now monitor
$ systemctl status monitor | grep Active
     Active: active (running) since Sun 2026-11-01 11:20:01 IST; 3s ago


📍 Where to Add What: change an existing service safely
Do not edit files in /usr/lib/systemd/system/. Package updates overwrite them. Run sudo systemctl edit sshd. It opens a new file, /etc/systemd/system/sshd.service.d/override.conf. Add:

[Service]
Restart=on-failure
Save, and systemd reloads automatically. Check with systemctl cat sshd.



7. Targets: System Modes


A target is a group of units that make up a system state. It replaces the old "runlevels".


TargetMeaning
multi-user.targetText mode, network, no GUI. Normal for servers
graphical.targetMulti-user plus a GUI desktop
rescue.targetSingle-user repair mode
poweroff.target / reboot.targetShut down / reboot


$ systemctl get-default
graphical.target
$ sudo systemctl set-default multi-user.target   # next boot = text mode (no file to edit)
Removed "/etc/systemd/system/default.target".
Created symlink /etc/systemd/system/default.target → /usr/lib/systemd/system/multi-user.target.
$ sudo systemctl isolate multi-user.target       # switch NOW, no reboot



Practice Labs (do these on a lab VM)


Lab 1: see "now" vs "at boot" for real


$ sudo -i
# systemctl status chronyd | grep Active      # active (running)
# systemctl stop chronyd ; systemctl is-enabled chronyd
enabled                       # stopped now, but still enabled
# systemctl reboot            # log in again after it is up
# systemctl is-active chronyd
active                        # came back because it is ENABLED
# systemctl disable chronyd ; systemctl is-active chronyd
active                        # disable does NOT stop it. It only affects the next boot
# systemctl reboot
# systemctl is-active chronyd
inactive                      # gone after boot because it is disabled


Learn: stop + enable = comes back after reboot. disable alone does not stop a running service. Use disable --now for both.

🏢 Scenario: nginx will not start
$ sudo systemctl start nginx
Job for nginx.service failed because the control process exited with error code.
$ journalctl -u nginx -n 5 --no-pager
nginx[3201]: bind() to 0.0.0.0:80 failed (98: Address already in use)   # port 80 is taken
$ sudo ss -tlnp | grep ':80'
LISTEN 0 511 *:80  *:*  users:(("httpd",pid=2210,fd=4))               # httpd owns it
$ sudo systemctl stop httpd ; sudo systemctl start nginx             # fixed
$ sudo systemctl reset-failed nginx                                   # clear the failed mark if needed
