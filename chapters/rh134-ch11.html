Managing Storage with LVM

LVM lets you join disks into one pool and cut flexible volumes from it. You can make a volume bigger while it is in use. Learn it step by step, with commands and output.

1What is LVM?

Why? A normal partition has a fixed size. When it becomes full, fixing it is hard and risky. LVM (Logical Volume Manager) lets you make a volume bigger later, while it is in use.
Short nameFull formSimple meaning
PVPhysical Volumea disk or partition that LVM can use
VGVolume Groupa big pool of space made from one or more PVs
LVLogical Volumea piece cut from the pool. You format it and mount it, like a partition
Real lifeVG is a water tank filled from many bottles (PVs). An LV is a pipe that takes some water from the tank. You can add more bottles to the tank, and you can make the pipe bigger at any time.
What about PE?You will see PE (Physical Extent) in the output. It is the small block LVM cuts the pool into. The next section explains it with pictures and simple maths.
NamesAn LV named mylv in a VG named myvg is found at /dev/myvg/mylv.

2PE and extents: how LVM counts space

Why? LVM hands out space in whole blocks. Knowing this explains why sizes round up, why exam questions give a PE size, and what the numbers in vgdisplay mean.

The idea: tiles on a floor

LVM cannot hand out space one byte at a time. First it cuts the whole pool into equal small blocks. Then it gives out whole blocks only, like tiles for a floor. You can buy 3 tiles or 4 tiles, but never 3 and a half.

Two words: PE and LE

WordFull formSimple meaning
PEPhysical Extentone block, counted from the disk side (inside a PV)
LELogical Extentthe same block, counted from the volume side (inside an LV)
extentjust another word for "block". PE and LE are always the same size

The two formulas

Learn these two linessize = number of blocks × PE size
number of blocks = size ÷ PE size (if something is left over, LVM rounds up for an LV)

With the default PE size of 4 MiB:

Size you wantCalculationBlocks (extents)
300 MiB300 ÷ 475
500 MiB500 ÷ 4125
1 GiB = 1024 MiB1024 ÷ 4256
2 GiB = 2048 MiB2048 ÷ 4512

You can see these numbers in your own pool. In lvextend output you saw 500.00 MiB (125 extents). That is the same calculation: 500 ÷ 4 = 125.

Why sizes round up

Suppose you ask for 100 MiB. What you get depends on the PE size of the pool. LVM must give whole blocks, so it always rounds up to the next full block.

PE size100 ÷ PE sizeBlocks givenYou get
4 MiB100 ÷ 4 = 25 (exact)25100 MiB
16 MiB100 ÷ 16 = 6.257 (rounded up)7 × 16 = 112 MiB
64 MiB100 ÷ 64 = 1.562 (rounded up)2 × 64 = 128 MiB
# example: a pool whose PE size is 16 MiB
$ sudo lvcreate -L 100M -n test vgtest
  Rounding up size to full physical extent 112.00 MiB
  Logical volume "test" created.
Try it yourself

Same disk, different PE size

The same idea applies to the disk itself. A 2 GiB partition gives about 2047 MiB of usable space (LVM keeps 1 MiB for its own information). The pool can only use whole blocks, so the last small piece is wasted.

PE sizeBlocks in 2047 MiBSpace usedLeft over
4 MiB2047 ÷ 4 = 511.75, so 511511 × 4 = 2044 MiB3 MiB
16 MiB2047 ÷ 16 = 127.9, so 127127 × 16 = 2032 MiB15 MiB
64 MiB2047 ÷ 64 = 31.98, so 3131 × 64 = 1984 MiB63 MiB

Notice: on a disk the number of blocks is rounded down (a half block cannot be used). For an LV it is rounded up (you always get at least what you asked for).

What changes when you pick a different PE size?

Smaller PE (1 to 4 MiB)Bigger PE (16 to 64 MiB)
Size stepssmall steps, sizes are more exactbig steps, more rounding up
Wasted spacevery littlea bit more
Number of blocksmore blocks to keep track offewer blocks
Speed of read and writeno real differenceno real difference
  • The PE size must be a power of 2: 1M, 2M, 4M, 8M, 16M, 32M, 64M. A value like 10M is not allowed.
  • One pool has one PE size. All its PVs share it.
  • You choose it when you create the pool: vgcreate -s 16M. Changing it later is hard (vgchange -s only works when no blocks need to move), so decide at the start.
  • The default 4 MiB is right for almost every case. Very old LVM1 allowed only 65,534 blocks per LV, so huge volumes needed a bigger PE. Modern LVM2 has no such limit.

How an LV sits on the disks

Imagine the pool from Practice 2: two disks, one small volume mylv (75 blocks) and one big volume mylv2 (1024 blocks). LVM keeps a map from every LV block (LE) to a disk block (PE). That is how mylv2 can use two disks.

You can see this map yourself with pvdisplay -m. Each line says which disk blocks (physical extent) belong to which LV blocks (logical extents):

$ sudo pvdisplay -m /dev/sdb1
  --- Physical volume ---
  PV Name               /dev/sdb1
  VG Name               myvg
  PE Size               4.00 MiB
  Total PE              511
  Free PE               0
  Allocated PE          511

  --- Physical Segments ---
  Physical extent 0 to 74:
    Logical volume      /dev/myvg/mylv
    Logical extents     0 to 74
  Physical extent 75 to 510:
    Logical volume      /dev/myvg/mylv2
    Logical extents     0 to 435
$ sudo pvdisplay -m /dev/sdc1 | tail -6
  Physical extent 0 to 587:
    Logical volume      /dev/myvg/mylv2
    Logical extents     436 to 1023
  Physical extent 588 to 1278:
    FREE

Check the numbers with vgdisplay. Total blocks = used blocks + free blocks, and blocks × PE size = size:

$ sudo vgdisplay myvg
  VG Name               myvg
  VG Size               <7.00 GiB
  PE Size               4.00 MiB
  Total PE              1790
  Alloc PE / Size       1099 / 4.29 GiB
  Free  PE / Size       691 / 2.70 GiB

Check: 511 + 1279 = 1790 total. 75 + 1024 = 1099 used. 1790 − 1099 = 691 free. And 1099 × 4 MiB = 4396 MiB = 4.29 GiB.

Exam ruleThe question gives a PE size: use vgcreate -s. The question gives a number of extents: use small -l. The question gives MiB or GiB: use capital -L. Copy the numbers. Do the multiplication only if the question asks for the final size.

4Practice 1: make your first LV

Why? This is the basic flow you must know: partition, PV, VG, LV, format, mount, fstab.
Goal: Make a 300 MiB volume mylv in a pool called myvg, format it, and mount it on the folder /mydata so it stays after reboot.
  1. Make the partition /dev/sdb1 (2 GiB, type Linux LVM) and run udevadm settle. (See the section Before you start.)
  2. PV: pvcreate /dev/sdb1
  3. VG: vgcreate myvg /dev/sdb1
  4. LV: lvcreate -L 300M -n mylv myvg
  5. Format: mkfs.xfs /dev/myvg/mylv. Make the folder: mkdir /mydata
  6. Add one line to /etc/fstab, then systemctl daemon-reload and mount -a
  7. Check with df -hT

Make PV, VG and LV

$ sudo pvcreate /dev/sdb1
  Physical volume "/dev/sdb1" successfully created.
$ sudo vgcreate myvg /dev/sdb1
  Volume group "myvg" successfully created
$ sudo lvcreate -L 300M -n mylv myvg
  Logical volume "mylv" created.
CommandWhat it does
pvcreate /dev/sdb1prepares the partition for LVM (it becomes a PV)
vgcreate myvg /dev/sdb1makes a pool named myvg from that PV
lvcreate -L 300M -n mylv myvg-L = size, -n = name, last word = which pool to take space from

Check your work: pvs, vgs, lvs

Three short commands. Each shows one layer. In vgs the column VFree is the free space left in the pool.

$ sudo pvs
  PV         VG    Fmt  Attr PSize  PFree
  /dev/sdb1  myvg  lvm2 a--  <2.00g 1.70g
$ sudo vgs
  VG   #PV #LV #SN Attr   VSize  VFree
  myvg   1   1   0 wz--n- <2.00g 1.70g
$ sudo lvs
  LV    VG   Attr       LSize   Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert
  mylv  myvg -wi-a----- 300.00m
Reading lvsLook at only three columns: LV (name), VG (pool) and LSize (size). The rest you can ignore for now. There are also long versions, pvdisplay, vgdisplay and lvdisplay, which show the same facts with more detail.

Format and make the folder

$ sudo mkfs.xfs /dev/myvg/mylv
meta-data=/dev/myvg/mylv         isize=512    agcount=4, agsize=19200 blks
data     =                       bsize=4096   blocks=76800, imaxpct=25
log      =internal log           bsize=4096   blocks=16384, version=2
$ sudo mkdir /mydata
XFS minimumXFS needs a volume of at least about 300 MiB. That is why 300M is used here.

Make it permanent: edit /etc/fstab

Without this line the volume is gone after a reboot. Open the file and add one new line at the very end:

$ sudo vim /etc/fstab
/etc/fstab (add the green line at the end)
/dev/myvg/mylv   /mydata   xfs   defaults   0 0
PartExampleMeaning
1/dev/myvg/mylvwhat to mount (the LV)
2/mydatawhere to mount it (the folder must exist)
3xfsfile system type. It must match what you made
4defaultsnormal mount options. Write exactly defaults
5 and 60 0old backup and check settings. Use 0 0
$ sudo systemctl daemon-reload
$ sudo mount -a
$ df -hT /mydata
Filesystem            Type  Size  Used Avail Use% Mounted on
/dev/mapper/myvg-mylv xfs   280M   17M  263M   6% /mydata
What do daemon-reload and mount -a do?systemctl daemon-reload tells the system to read the changed fstab. mount -a means mount all lines of fstab. If it prints nothing, your line is correct. Always do this test before you reboot. A wrong line in fstab can stop the system from booting.

Finally reboot and check that the volume is still mounted:

$ sudo reboot
# ...after the reboot...
$ df -hT /mydata
Filesystem            Type  Size  Used Avail Use% Mounted on
/dev/mapper/myvg-mylv xfs   280M   17M  263M   6% /mydata

5Practice 2: add a disk to the pool

Why? When the pool is too small, you do not repartition. You simply add another disk with vgextend. Very common in real jobs.
Goal: Make a second volume mylv2 of 4 GiB in the same pool. The pool has only about 1.7 GiB free, so first add a new disk /dev/sdc to the pool.

Prepare the new disk and add it to the pool

8Practice 5: make volumes bigger

Why? The most common real task: a volume is full. You grow the LV and then its file system, while it stays mounted.
Goal: Make lvweb bigger by 3 GiB and lvbackup bigger by 2 GiB. The pool has only 544 MiB free, so first add a new 6 GiB disk /dev/sde.

Add the new disk to the pool

On /dev/sde press: g, n, Enter, Enter, Enter (whole disk), t, 44, p, w. Then:

$ sudo udevadm settle

$ sudo vgs vgapps
  VG     #PV #LV #SN Attr   VSize  VFree
  vgapps   2   2   0 wz--n- <8.00g  6.53g

9Shrink, move and removeextra

Why? Rare tasks, but good to know for interviews.

Shrink: only ext4, never XFS

$ sudo umount /backup
$ sudo e2fsck -f /dev/vgapps/lvbackup
$ sudo lvreduce -r -L 1G /dev/vgapps/lvbackup
  Logical volume vgapps/lvbackup successfully resized.

Remove a disk from a pool

$ sudo pvmove /dev/sdd1
  /dev/sdd1: Moved: 100.00%
$ sudo vgreduce vgapps /dev/sdd1
  Removed "/dev/sdd1" from volume group "vgapps"
$ sudo pvremove /dev/sdd1

Remove an LV and its pool

$ sudo umount /web          # also delete its line from /etc/fstab first
$ sudo lvremove /dev/vgapps/lvweb

Delete the fstab line firstIf fstab still lists a volume that no longer exists, the next boot can fail. Back up data before shrinking or removing anything.

10Interview questions

Why? Interviewers ask short theory questions about LVM. Click a question, answer in your own words, then check.
What is a PE (extent), and what happens if you change its size?
PE (Physical Extent) is the small block the pool is cut into. The default is 4 MiB. An LV gets whole blocks only, so its size is always a multiple of the PE size and LVM rounds up. A smaller PE gives finer sizes and less wasted space. A bigger PE gives bigger steps. Speed is almost the same. You set it with vgcreate -s and it is hard to change later.
What is LVM and why use it?
LVM (Logical Volume Manager) sits between disks and file systems. It joins disks into a pool and lets you cut volumes from it. You can grow a volume while it is in use, add disks later, and move data between disks. A normal partition has a fixed size.
What are PV, VG and LV?
PV = Physical Volume (a disk or partition for LVM). VG = Volume Group (the pool made from PVs). LV = Logical Volume (a piece of the pool that you format and mount).
Steps to make an LV from a new disk?
Partition (type Linux LVM), pvcreate, vgcreate, lvcreate, mkfs, mkdir, add a line in /etc/fstab, mount -a, check with df -hT.
A volume is 95% full. What do you do?
Find the LV with df -hT. Check vgs for free space. If there is space: lvextend -r -L +5G /dev/VG/LV. If not: add a disk with pvcreate and vgextend, then extend. No unmount needed.
What is the difference between lvextend and xfs_growfs?
lvextend makes the LV bigger. xfs_growfs (or resize2fs for ext4) makes the file system inside bigger. The option -r does both.
Can you shrink a volume?
XFS cannot be shrunk. ext4 can, but it must be unmounted first. Always back up before shrinking.
What is the difference between -L and -l?
Capital -L = a size (like 500M or 2G). Small -l = a number of extents (blocks), like -l 100.
What happens if a disk in the pool fails?
LVM alone has no protection. Data on the failed disk is lost. Use RAID under LVM and keep backups.
Is LVM the same as RAID?
No. RAID = safety and speed. LVM = flexible sizes. They are often used together.
What is a snapshot? (extra)
A frozen copy of an LV at one moment, useful for a backup before an upgrade. Example: lvcreate -s -n snap1 -L 500M /dev/vgapps/lvweb.

11Exam steps and common errors

Why? Follow the same order every time and you will not forget a step.

Same order every time

  1. lsblk to find the new disk.
  2. fdisk: g, n, size, t, 44, p, w. Then udevadm settle.
  3. pvcreate, then vgcreate (or vgextend to add to an existing pool).
  4. lvcreate with -L (size) or -l (extents), using the exact name from the question.
  5. mkfs.TYPE with the file system type from the question.
  6. mkdir the folder, add the line in /etc/fstab, systemctl daemon-reload, mount -a.
  7. df -hT, vgs, lvs to check. Then reboot and check again.
SizesExams accept sizes that are about right. Names, folders and file system types must be exact.
