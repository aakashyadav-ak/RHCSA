Managing Containers with Podman

Containers package an application so it runs the same everywhere. Podman finds, runs and builds them. Learn it step by step, with commands, files to edit, output and a full lab.

1What are containers and Podman?

Why? Containers let you package an application once and run it anywhere, quickly and with little resource use.

A container is a small, isolated box that holds one application and everything it needs (libraries, settings). It starts in seconds and runs the same on every machine. It shares the kernel of the host, so it does not need a full operating system of its own.

Virtual machineContainer
Containsa whole operating system with its own kernelonly the app and its libraries. Shares the host kernel
Sizegigabytesmegabytes
Start timeminutesseconds
Isolationvery stronggood, but lighter
Good forrunning a whole separate systempackaging and running one application

The words you need

WordFull formSimple meaning
imagea read-only template (like an installer). You start containers from it
containera running (or stopped) copy made from an image
registrya server that stores images, like an app store
PodmanPod Managerthe tool that finds, runs and builds containers
OCIOpen Container Initiativethe standard for image format, so tools like Podman and Docker understand each other
UBIUniversal Base Imagefree Red Hat base image you can build on
Containerfilea text file with the steps to build an image

Podman is daemonless and rootless

PodmanDocker
Background service (daemon)none. Each podman command runs by itselfalways-running dockerd service
Runs asa normal user (rootless) by defaultusually root
Commandsalmost the same as Docker. alias docker=podman works

Daemonless means there is no big always-on program that runs as root. That is safer, and a normal user can run containers without admin power.

note Where the login is storedPodman saves the login in ${XDG_RUNTIME_DIR}/containers/auth.json. (XDG_RUNTIME_DIR is a folder for your session files, normally /run/user/1000.)

Layers (union file system)

A union file system (Podman uses OverlayFS) shows many layers as one file system. Layers are shared: ten containers from one image use the same read-only layers, so they save space.

Why did it say Exited (0)?

A container lives only while its main process runs. When that program ends, the container stops. Exited (0) means it ended normally. A number other than 0 means an error.

When do I need -it?An OS image such as ubi runs bash as its main process. Bash needs a terminal, and without -it it ends at once. A service image such as httpd-24 runs its web server and stays up without -it.

7Expose container ports

Why? Without a published port, nobody outside the container can use the service inside it.

Exposing a port means making a port of the container reachable from outside the container. A container has its own private network. By default nothing from the host can reach the web server inside it. The option -p (publish) builds a bridge.

$ podman run -p 8080:8080 registry.redhat.io/rhel10/httpd-24:latest
# (the server runs in the foreground. Press Ctrl+c to stop it)
$ podman run -d --name web02 -p 8080:8080 registry.redhat.io/rhel10/httpd-24:latest
$ podman ps
CONTAINER ID  IMAGE                                      COMMAND             STATUS        PORTS                   NAMES
7e0b4c2a9d13  registry.redhat.io/rhel10/httpd-24:latest  /usr/bin/run-httpd  Up 4 seconds  0.0.0.0:8080->8080/tcp  web02
$ curl localhost:8080
$ curl 127.0.0.1:8080
$ curl 0.0.0.0:8080
# (all three reach the container web server)

What does 8080:8080 mean?

-p HOST_PORT:CONTAINER_PORT. Yes, it is port forwarding: traffic that arrives at the host port is passed into the container port. Podman sets up this forwarding for you. A normal user (rootless) gets a small helper program for this, and a root user gets firewall rules.

ExampleMeaning
-p 8080:8080host 8080 goes to container 8080. Test with curl localhost:8080
-p 8081:8080host 8081 goes to container 8080. Useful when 8080 is already used. Test with curl localhost:8081
Which container port?Use the port the program listens on inside the container. Find it with podman image inspect (ExposedPorts). The web server image uses 8080.
Good to knowA normal user cannot publish host ports below 1024 (like 80). Use ports above 1024. To reach the container from another machine, use the host IP, and open the port in the firewall: sudo firewall-cmd --add-port=8080/tcp --permanent then --reload.

8Keep data: volumesextra

Why? Container data is lost when the container is removed. A volume keeps it on the host.
note Extra topic: save data with a volumeA volume (bind mount) links a folder of the host to a folder in the container. The data lives on the host, so it stays when the container is removed.
$ mkdir ~/mycon-data
$ podman run -dit --name data01 -v ~/mycon-data:/tmp:Z registry.redhat.io/ubi10/ubi bash
$ touch ~/mycon-data/test.txt
$ podman exec data01 ls /tmp/
test.txt
$ podman rm -f data01
$ ls ~/mycon-data
test.txt
$ podman run -dit registry.redhat.io/ubi10/ubi sleep infinity
PartMeaning
-v ~/mycon-data:/tmp:Zvolume: HOST_FOLDER:CONTAINER_FOLDER:OPTIONS. The host folder must exist first
:Ztells SELinux to label the folder for this container only. Without it the container may get Permission denied
sleep infinitya command that never ends, so the container stays up (a trick for tests)

9Build an image from a Containerfile

Why? Your own image lets you start the same ready-made application on any machine, again and again.
Goal: Build your own image myhttpd that serves a page index.html, then run it.
  1. Make a folder and a test page: mkdir images-container, cd images-container, echo test > index.html
  2. Create the file Containerfile (capital C, no extension). Add the lines below
  3. Build: podman build -t myhttpd .
  4. Run: podman run -d --name myweb1 -p 8080:8080 localhost/myhttpd:latest
  5. Test: curl localhost:8080

Open vim Containerfile and write these lines:

images-container/Containerfile
# Use the ubi10 base image
FROM registry.redhat.io/ubi10/ubi
# Install httpd
RUN dnf install -y httpd
# Let httpd listen on 8080 instead of 80
RUN sed -i 's/^Listen 80$/Listen 8080/' /etc/httpd/conf/httpd.conf
# Copy the test page into the web server root
COPY index.html /var/www/html/index.html
# Document that the container uses port 8080
EXPOSE 8080
# Run httpd in the foreground
ENTRYPOINT ["/usr/sbin/httpd", "-DFOREGROUND"]
InstructionMeaning
FROMthe base image to start from
RUNrun a command while building (install software)
COPYcopy a file from your folder into the image
EXPOSEnote which port the program uses. It is documentation only. It does not publish the port. -p does that
ENTRYPOINTthe program that starts when the container starts. It must run in the foreground, or the container stops at once

10Tag images

Why? A tag names the version of an image, and gives it the registry name it needs before it can be pushed.

A tag is a label after the colon in an image name, such as :1.0 or :latest. It tells versions apart. Tagging also lets you give an image the full name a registry needs before you push it.

Add a tag

$ podman images
REPOSITORY         TAG     IMAGE ID      CREATED         SIZE
localhost/myhttpd  latest  4c1e9a7b2d03  10 minutes ago  372 MB
$ podman tag localhost/myhttpd:latest localhost/myhttpd:1.0
$ podman tag localhost/myhttpd:1.0 registry.lab.example.com:5000/myhttpd:1.0
$ podman images
REPOSITORY                             TAG     IMAGE ID      CREATED         SIZE
localhost/myhttpd                      1.0     4c1e9a7b2d03  10 minutes ago  372 MB
localhost/myhttpd                      latest  4c1e9a7b2d03  10 minutes ago  372 MB
registry.lab.example.com:5000/myhttpd  1.0     4c1e9a7b2d03  10 minutes ago  372 MB

Look at the IMAGE ID column: it is the same for all three rows. A tag does not copy the image. It only adds another name for it.

CommandMeaning
podman tag SOURCE TARGETgive the image SOURCE a new name TARGET (long form: podman image tag)
podman build -t myhttpd:2.0 .tag the image while you build it
podman imagesshows each tag as its own row. Same IMAGE ID = same image
podman rmi localhost/myhttpd:1.0removes only that tag if the image has other tags
$ podman rmi localhost/myhttpd:1.0
Untagged: localhost/myhttpd:1.0
$ podman images
REPOSITORY                             TAG     IMAGE ID      CREATED         SIZE
localhost/myhttpd                      latest  4c1e9a7b2d03  12 minutes ago  372 MB
registry.lab.example.com:5000/myhttpd  1.0     4c1e9a7b2d03  12 minutes ago  372 MB

The image data is deleted only when the last tag is removed.

Tag, then push

$ podman push registry.lab.example.com:5000/myhttpd:1.0
...output omitted...
Writing manifest to image destination
Two ways to pushEither tag first and push the tagged name (above), or give source and destination in one command: podman image push localhost/custom_app:1.0 registry.lab.example.com:5000/custom_app:1.0. Both end with the same result in the registry.

Rules and good habits

PointMeaning
No tag givenPodman uses latest. This is only a label. It does not automatically mean the newest version
Allowed charactersletters, digits, _ (underscore), . (dot) and - (dash). It cannot start with a dot or a dash
Version tagsuse clear versions like 1.0, 1.1, 2.0. You can roll back by running an older tag
Registry nameto push, the image name must start with the registry: registry.example.com:5000/name:tag
Real job exampleYou release myhttpd:1.1 and users report a bug. You run podman run -d -p 8080:8080 registry.lab.example.com:5000/myhttpd:1.0 to go back to the working version in seconds. This is why every release gets its own tag.
note Tag or digest?A tag can be moved to another image later. A digest (name@sha256:...) always points to the exact same content. Find it with podman image inspect --format '{{.Digest}}' IMAGE.

14Interview questions

Why? Interviewers often start with containers. Click a question, answer in your own words, then check.
What is a container?
An isolated process that holds one application and its libraries. It shares the host kernel, starts in seconds and uses few resources.
Container or virtual machine?
A VM has a full guest OS with its own kernel (heavy, slow to start). A container shares the host kernel and has only the app and libraries (light, fast).
What is the difference between an image and a container?
An image is a read-only template. A container is a running or stopped instance made from it. One image can start many containers.
What is Podman and why daemonless?
Podman is the Red Hat tool to run and build containers. It has no background daemon and runs rootless (as a normal user), so it is safer. The commands match Docker.
What is a registry?
A server that stores images, for example registry.redhat.io, quay.io, Docker Hub, Amazon ECR.
What do -i, -t and -d mean?
-i keeps input open, -t gives a terminal, -d runs in the background (detached).
What does -p 8080:8080 mean?
Publish a port: host port : container port. Traffic to port 8080 of the host is forwarded to port 8080 inside the container.
Why did my container exit immediately?
Its main process ended. For an OS image like ubi, bash ends without a terminal, so use -it or -dit. Exited (0) means a normal end.
What happens to data in a container when it is removed?
It is lost, because it lives in the thin writable layer. Use a volume (-v) to keep data on the host.
What is a Containerfile?
A text file with the steps to build an image: FROM, RUN, COPY, EXPOSE, ENTRYPOINT. Built with podman build -t NAME ..
What is an image tag?
A label after the colon in an image name (myhttpd:1.0). It marks the version. podman tag SOURCE TARGET adds another name for the same image, and no extra space is used. If you give no tag, Podman uses latest.
How do you share an image?
Log in to a registry, then podman image push LOCAL registry/name:tag. Others pull it with podman pull.
What is rootless?
A normal user runs the containers. Root inside the container is only that user outside, so a break-out has little power.
What are image layers?
Each step of a Containerfile adds a read-only layer. A container adds one writable layer on top. Layers are shared between images to save space.

15Exam steps and common errors

Why? The same order every time means you do not forget a step.

Same order every time

  1. podman login REGISTRY (if the registry needs it)
  2. podman search and podman pull the image. Check with podman images.
  3. Run it: podman run -d --name NAME -p HOST:CONTAINER IMAGE
  4. Check with podman ps and curl localhost:PORT
  5. To build: write the Containerfile, then podman build -t NAME:TAG .
  6. To share: podman image push, then podman rmi if asked to delete it locally.
